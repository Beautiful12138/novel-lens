状态：两份 Skill 已实现，格式、独立资源与单份资料同步验证通过；实际客户端已有首批分析样本抽核，修订后的行为效果与稳定性仍待对照验证。不新增服务接口、检索索引或数据库迁移。

依据：需求基线第 24、32.5、35 章，两份方法文档，Spec 02–07 的工具契约、Spec 09 的关键词检索增量，以及已确认的精简与独立使用要求。

## 1. 范围与交付

在 `.agents/skills/` 维护 novel-analysis 与 chinese-novel-writing 两份 Skill。每个完整文件夹可独立交付，不依赖开发仓库、其他 Skill 或历史会话；按任务需要使用已连接的 NovelLens MCP。

当前服务的原文读取、关键词／语义搜索、标注列表与详情默认 compact。两份 Skill 须说明如何将精简引用与响应顶层归属合成完整 SourceRange，不将摘录当全文；分析 Skill 在修订标注前显式请求 full。写入和历史回执保持完整，其他资产接口维持原契约。格式精简不改变文学目标或默认只读边界。

Skill 主要补充任务标准和工具约束，依靠 LLM 自身的阅读、分析和创作能力，不把完整分析指南、44 项维度、专项教程和大量示例作为运行资料。完整分析指南保留在 docs/ 供维护参考；分析 Skill 自身须写清必要的证据、标注质量与工作边界。

中文写作原则只随 chinese-novel-writing 携带一份，保留六项核心原则、创作取向和定向修订方法。维护源仍为 docs/中文小说正文写作原则.md；同步脚本只负责该单份副本，运行 Skill 无需脚本或 Python。两个入口及各自 MCP 流程人工维护，不自动复制其他文档。

本期不安装全局 Skill、不配置实际 AI 宿主、不修改服务代码或运行依赖、不操作共享数据库、不执行 Git 提交推送。

## 2. novel-analysis

- 面向指定作品范围的深读、标注和资产修订，也支持接续已有分析任务。仅查看和讨论时只读；明确要求保存时在目标范围内连续处理。
- 在入口开头突出分析服务于后续创作的核心目标：帮助 AI 找到适用原文、理解具体写法并结合新作条件借鉴；提交时据此判断标注是否提供有用的原文入口与具体观察。标签、说明与导航提供检索入口和理解线索，不能代替原文参考；关注普通行文及表达与组织过程，不只挑精彩句子，也不把个案总结成普遍公式。
- 说明具体文本选择、组织关系、必要条件和适用边界，用真实原文支持结论；区分事实、解释和未知，不以剧情概括或空泛评价代替分析。
- 提交前核对核心论断与原文，引用包含支持顺序、对照或呼应等判断的必要证据；遗漏时补引，证据不足时收窄结论或保留问题。后续证据改变或削弱已有结论时，同步修订受影响的分析资产与 recovery，不让接续疑问与资产中的确定结论并存。
- 边界说明针对影响判断或借鉴的具体条件，不要求逐条附范围免责声明或独立创作建议。标签定义描述可识别的特征与作用，个案特有的效果与成立条件放在标注中，不上升为标签的必然规律。
- 不固定审美偏好，不替参考作者改稿，不机械填维度，不跳过普通片段，不把局部证据扩大为全书规律。
- 区分 Annotation、Tag、Entity、Relation、StyleGuide 和任务进度；给出必要的选择规则，按需读取包内 MCP 参数与恢复流程。
- 沿用稳定定位、作品隔离、真实分页、版本校验、固定请求键和原子 checkpoint；新标签或实体需先取得可引用 ID。只对已按任务处理并成功提交的范围推进进度。
- 新会话从当前任务、Coverage 和 recovery 恢复；缺失的未提交请求不能假称可恢复。结果不明、完成和重开行为遵循既有契约。
- 纠错按当前版本选择修改、撤回或恢复标注；同一共享概念可修订标签，新概念另建，避免以全局标签变化迁就个案。受影响的关系、导航和接续结论由 AI 判断并更新，服务不自动连带处理；未完成核验的范围沿用 needs_revisit。参数和历史回执兼容遵循 Spec 04 的 0009 增量。

## 3. chinese-novel-writing

- 统一处理中文小说构思、正文创作、续写与修订。采用用户任务和前文，根据创作需要判断是否使用参考材料，使用 NovelLens 时再加载 MCP 调用说明。
- 读取包内写作原则，保留事实与人物依据、因果可信度、信息与声音归属、参考迁移和表达自由，以及想象力、情绪、期待和愿望兑现的创作取向。
- 已连接 NovelLens 时，由 AI 主动选择适用的作品、材料、查询方式与读取范围，无需用户点名工具或指定参数；遵守用户指定的参考范围。用户明确不用参考库、现有材料已足够或库中无适用材料时不强制检索。参考库查询不再拥有独立 Skill 入口。
- 使用风格导航、标签/实体字面查询、标注过滤、关系查询和原文读取；Spec 09 增加原文及写法说明关键词检索，按实际工具发现与启用状态使用，不虚构向量或统一 Search 工具。
- 在入口开头突出以适用原文的具体写法为主要创作参考的核心目标，主动学习对白接续、动作与叙述穿插、细节选择和语言节奏，并结合新作条件运用；成稿回看时核对是否落实到具体语言与组织、是否适合新作。标签、说明与导航用于定位和辅助理解，不停留于抽象技巧概括。用户的新作事实优先，不照搬原句、情节、人物经历与关系基础。
- 标注引用范围是阅读入口，不限制必要上下文。局部表达可读局部，人物互动、情绪推进和叙述节奏需补读到能够理解必要的起因、展开与变化；根据实际返回调整范围，不固定小窗口，也不把找到标签或概括技巧当作参考充分。
- 原文工具 schema 支持时优先使用 Spec 02–03 的 compact 格式；从顶层归属和范围端点重建 SourceRange，保留续页与边界判断。旧服务省略 format，字节定位使用 full；增大 limit 不会扩大引用范围。
- 参考库默认只读，不因写作修改资产或推进分析进度。必要证据不可用时说明缺口；用户允许不依赖参考时可继续，必须使用指定参考时则保留阻塞。
- 当前 get 返回 withdrawn 的标注不作为有效分析依据；原文仍可独立阅读，历史无状态回执不代表当前有效。恢复后的索引覆盖以实时结果为准，不在写作流程自动执行纠错写入。

Spec 10 的全文增量为两份 Skill 增加 `semantic_index_get` 与 `source_semantic_search` 的调用规则：先核对作品和覆盖，再按实际 SourceRange 回读证据；候选分数与索引覆盖不代表文学判断或分析进度。分析包另外说明用户要求构建时的 create / build 请求键与接续流程，写作包保持默认只读。全文和标注引用原文分别使用 fulltext / annotation；标注命中需按 annotation_id 回读说明和证据，并区分历史代状态与实时覆盖。该适配不改变分析标准、写作原则或两包独立性；真实协议验证见 Spec 10 的两层增量验收，实际 AI 宿主与文学效果仍待验证。
