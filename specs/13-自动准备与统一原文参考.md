# 13 自动准备与统一原文参考

状态：本轮实现、工程回归及限定真实小说的 AI 流程验收完成，证据和限制见第 8 节；独立文学质量对照与长篇规模验证仍待后续开展。依据用户最新决定及[职责方案](../docs/原文参考自动化流程与职责方案.md)。开发库数据可重建，不要求旧数据或接口兼容。

## 1. 边界

用户提供待分析 TXT 后，正在执行的 AI 自动准备格式、导入、逐批阅读和保存必要标记；创作请求自动查阅原文。AI 停止后不自动唤醒或恢复，不增加后台 AI 执行器。服务运行期间自行维护派生索引，保存可靠进度，文学判断仍由外部 AI 完成。

## 2. 自动准备

- 原子写入边界分别为一次导入、一批标记及其进度、一批索引及其进度、一次清理。失败仅回滚本次操作，已成功的批次保留，AI 可以修正后继续；不引入整部暂存与统一发布机制。
- 整部作品用于判断准备是否完成，也可以作为明确放弃时的清理范围。清理不自动触发，不删除外部 TXT 或其他作品；清理与仍在执行的批次、索引发布互斥，失败全部回滚。
- 请求超时不等于写入失败，查询回执或原键原输入重试，不盲目换请求键。输入拒绝不推进进度，失败不得被算作完成。
- 原文导入与该分部准备任务、索引待办在同一事务中登记。相同请求和相同来源重试复用已有结果；追加分部保留旧任务进度。
- 任务覆盖指定分部的完整正文，可分批处理，允许没有新标记的批次。完成不强制风格导航或长分析报告。
- 批次成果、进度和接续信息原子保存。请求幂等、作品归属、版本并发控制继续有效。
- 已完成任务可通过同一批次入口修订：AI 提供 `reopen_reason` 和至少一条标记，重开、清除旧完成说明、保存标记及推进版本共用一个事务，保留已有阅读覆盖；失败仍保持原完成状态。运行中任务不接受重开原因。修订后重新核对索引并完成任务，不增加用户确认步骤。
- 原文、标记及标签变动自动登记派生索引更新；执行器重启后继续处理。网络推理期间不持有写事务，发布前核对版本；中途变动不得发布过期结果。
- 完成阅读处理与索引就绪分别表达。整部作品准备完成须全部目标已处理且有关索引同步；原文索引已就绪即可供创作参考，不等待全书全部标记。

## 3. 统一检索

阅读返回、多作品范围和候选续查的当前契约由 [Spec 14](14-阅读返回与多作品召回续查.md) 定义；本文件保留准备与索引维护要求。

- 一个入口执行原文语义、原文字面、标记短说明与标签的语义和字面检索，融合排名、去重后返回原文入口。未标记原文必须参与。
- 原文与检索线索分别表示，修改说明或标签不重算有效原文向量。追加内容复用已有效切片；派生数据不得改写原文。
- 默认返回来源、真实范围、原文预览及截断标识和必要缺口提示；full 返回当时命中通道和覆盖诊断。作品限制在候选生成阶段生效，不跨作品拼接范围。
- 必要原文索引未就绪时返回可观察的准备状态；模型失败或不可处理输入分别报错，不假报无命中或静默退化为关键词搜索。
- 原文读取保留连续范围与分页续读；不固定文学阅读配额，不把技术切片判为文学场景。

## 4. 默认 MCP 与 Skill

默认提供作品导航、导入并登记任务、准备状态、批次标记保存、完成准备、失败清理、统一参考查询、连续原文阅读八项业务职责。索引手工构建及维护 CRUD 不默认暴露。HTTP 和 MCP 共用业务能力；维护能力保留独立入口。

批次标记输入包含明确的创建或修订数据、真实原文引用与标签；服务处理标签精确复用，不要求 AI 先操作若干 CRUD 工具。写入不接受任意 SQL、工具名或脚本。

资料准备 Skill 自动串联导入和逐批处理，不为普通步骤询问用户；创作 Skill 默认先取得适用原文并理解，再确定依赖参考的方案。用户明确不用参考、仅文字校对或当前上下文已有足够原文时按实际需要执行。短说明与标签不能代替正文。

### 统一查询与默认入口契约

- `reference_query` 新查询接收 query、scope、可选 terms/exclude_ranges/limit/format，续查只接收 search_id、可选 cursor/format；多作品、固定候选池与分页按 Spec 14 执行。一次新查询只生成一个查询向量，在同一数据库快照执行四路召回，默认不提供通道开关。
- 独立线索表示包含标记短说明和所关联标签的名称、定义、别名；直接使用保存内容，不由服务扩写解释。迁移 0013 为既有作品重新登记同步，只有指纹变化的线索重新计算，纯原文向量复用。
- 字面通道覆盖查询及显式线索，按匹配线索数量排序，稳定原文顺序用于同分排序；向量通道按余弦距离排序。每路保留有界候选窗口，采用 RRF 融合名次，得分不表示文学质量或相关概率。结果报告窗口是否截断，不声称穷尽所有相关原文。
- 同章范围重叠达到较短范围的 80% 时合并，保留命中通道和标记 ID，合并范围由真实端点构成；不跨章或拼接不连续证据。返回原文预览、是否截断、完整范围和分部/章节定位。阅读工具再取得完整正文。
- 按请求作品或分部核验原文覆盖。所选索引在请求范围内完整、且契约匹配即可使用；追加其他分部不使已完整覆盖的旧分部不可读。线索向量只接受当前有效标记的指纹；说明或标签修订后旧向量立即排除，尚未同步的线索通过当前字面表示参与，返回同步状态。
- 默认 MCP 为 `library_browse`、`prepare_import`、`prepare_status`、`prepare_batch`、`prepare_finish`、`prepare_cleanup`、`reference_query`、`source_read`。准备状态支持按任务读取当前状态或按请求 ID 查提交回执，二者互斥。导航支持作品、分部、章节、标记与任务列表；原文阅读支持整章分页、范围分页及按真实段落扩展上下文。
- 既有维护 MCP 通过显式维护配置启动，默认业务连接不注册维护工具；HTTP 维护接口仍可使用。维护配置只改变工具暴露，不改变读写、隔离与可靠性规则。

## 5. 验收

1. 真实 PostgreSQL、PGroonga 与 pgvector 上验证原子导入、任务复用、批次回滚、并发版本和自动索引更新。
   中途批次失败不丢失此前成功成果，失败批次无残留；整作品清理不影响其他作品与外部 TXT。
2. 追加原文、修改说明或标签、撤回标记后正确更新，过期结果不可被当作当前内容使用；故障可观察且重启可继续。
3. 未标记原文与标签线索均可召回，结果可回读，去重与作品隔离有效；不同通道的得分不是同尺度概率。
4. 默认 MCP 实际只列出约定业务工具，协议与 HTTP 行为一致，Skill 指向真实工具参数。
5. 在运行中的 AI 任务验证自然语言触发、连续处理和先读后写；AI 停止后的自动恢复不属于验收。
6. 真实小说召回及创作读感独立验证，不能用模拟向量、工具成功或测试数量代替文学效果证据。

## 6. 第一阶段实现记录

第一阶段实现第 2 节的可靠准备能力：`prepare_import`、`prepare_batch`、`prepare_status`、`prepare_finish`、`prepare_cleanup` 和回执查询。首次导入仍使用已确认的规范 TXT；AI 的文件整理方法沿用 Spec 12，服务不擅自改写正文。

- 导入新建作品提供 `name`，追加提供 `work_id`。相同请求同内容重放；同作品同 SHA-256 来源复用分部及其准备任务。外部文件删除后仍可按请求键查询提交快照。
- 批次提供当前任务版本、一段连续处理范围、零到多条完整标记及接续信息；标签按 namespace/name 精确复用，已有定义不覆盖。每条修订须附当前标记版本，引用必须属于本作品。标记可引用同作品其他位置，处理进度只推进本批明确范围。
- 状态返回剩余未 processed 范围、任务版本和索引状态。`work_ready` 仅在所有分部已有完成的全分部任务，且作品索引同步时为 true；分部任务完成不等于后续追加分部已完成。索引状态与历史完成回执分开读取。
- 完成入口检查本任务全部目标已处理和作品索引同步，不以标签数量判断完成。不要求风格导航；旧独立任务完成入口仅表示阅读处理完成。
- 清理须指定作品 UUID 和当前作品名；未找到视为目标已达成。只删除该作品数据和本准备流程创建、已无其他引用的标签；其他作品、既有共享标签、外部 TXT 保留。
- 自动索引在已配置 embedding 的服务生命周期内运行，多个进程以作品锁互斥。提交阶段的延迟触发器与业务数据原子登记待办，避免标记过程提前竞争队列行。每次向量计算有界，推理时不持写事务，发布前重新核验待办版本。临时失败保留待办并延后重试；输入过长标记阻塞，原文或标记变更后重新排队。
- 迁移 `0012` 新增待办、独立线索向量和准备流程新建标签归属三张表。完整原文向量继续使用既有语义索引；追加分部复用同契约的完整旧代切片。

第一阶段当时仅增加准备入口，未收拢 MCP 或改造 Skill；以下第 7 节保留当时验证记录。统一召回和默认工具的当前结果见第 8 节。
