## 1. 目标与范围

支持创作 AI 在选定作品中查找原文、阅读全文、继续查看候选，并在改变查询时减少重复返回已读内容。用户不需要管理检索参数或已读清单。

本期只实现以下三项：

1. 默认 `compact` 面向阅读，`full` 提供诊断；格式不参与候选生成、排序或分页。
2. 同一个 `reference_query` 支持多作品范围，并可按作品限定分部或章节。
3. 支持固定候选列表的分页续查，以及新查询显式排除已读范围。

默认 MCP 仍为 Spec 13 的八个工具。调整三个业务读入口 `library_browse`、`reference_query`、`source_read`，五个准备入口保留原契约。HTTP 与 MCP 使用相同业务规则。不全面重构维护工具，不增加独立搜索、已读登记或诊断 MCP。

本期不增加重排模型、关系图检索、实体或风格导航召回、服务端文学任务拆解、生成式分析、自动唤醒 AI 或全局阅读历史。工程验收不等同于文学质量提升的证明。

## 2. 实施前状态与改动点

实施前 `reference_query` 接受单个 `work_id` 和可选 `part_id`，四路召回后返回前 `limit` 条；每路候选窗口为 `limit * 10`。返回混合原文入口、得分、命中通道、索引和覆盖统计，没有候选翻页或已读排除。

实施前 `library_browse` 返回较完整对象，包含未使用视图的空字段；业务 `source_read` 已采用精简正文返回，但没有格式切换。维护原文接口已有 `compact/full` 投影，可复用其真实位置与段落字段。

实现时须把候选池大小与每页数量分开，并在整个候选池融合完成后分页。不得在现有前 `limit` 条结果外简单添加页码。

## 3. 阅读与诊断返回

三个业务读入口增加 `format: "compact" | "full"`，默认 `compact`。由同一业务结果生成两种投影，不能为两种格式分别执行检索或不同范围的读取。

### 3.1 reference_query

两种格式共用以下顶层字段：

- `search_id`：本轮搜索身份，可用于重读第一页或继续分页。
- `snapshot_at`、`expires_at`：搜索快照创建时间和到期时间，UTC 时间戳；不是当前索引状态。
- `items`：本页候选。
- `next_cursor`：下一页凭据，列表结束时为 `null`。
- `candidate_window_limited`：任一路存在未纳入候选池的候选时为 `true`，不是是否还有下一页。
- `warnings`：仅存在影响判断的限制时返回，正常时省略。线索尚未同步用 `CLUES_PENDING` 或 `CLUES_BLOCKED`、受影响 `work_id` 及简短说明表达；不返回例行统计，也不隐藏实际能力缺口。

线索警告按选定范围内有效标记引用对应的线索判断，不因未选择分部的线索待同步而提示本次范围存在缺口。full 中既有作品级索引统计明确标为作品级，与请求范围的覆盖和警告分开表达。

`compact.items` 每项保留 `work_name`、`source_range`、`part_id`、`part_name`、`section_title`、`excerpt`、`excerpt_truncated`、`annotation_ids`。`source_range` 包含 `work_id`、`section_id`、`start_paragraph_id`、`end_paragraph_id`。这些字段提供来源辨认、原文回读和必要的标记详情入口。

`full` 保留以上字段，在每项增加 `score`、`channels`，并增加 `diagnostics`：规范化请求范围、每作品采用的索引身份、当时索引状态与请求范围覆盖信息。全部为 `snapshot_at` 时刻的信息；当前准备状态仍通过已有状态入口读取。不再沿用含义不明的顶层单个 `work_id/index_id` 表示多作品查询。

`full` 不表示返回整部小说。两种格式的预览文本、截断标识、候选身份、顺序和下一页必须完全一致，不因精简格式进一步缩短预览，也不截断 `annotation_ids`。预览在候选范围内优先选取包含检索词的第一段，从首次命中前最多 40 字开始返回最多 200 字连续原文；没有可定位命中时回退首段。预览不拼接、不改写正文，不代表整个范围已经读完。阅读全文仍由 `source_read` 完成。批量获取候选预览，避免按候选数量增加数据库往返次数。

### 3.2 library_browse

资产查找增量见 [Spec 16](16-资产查找与分批分析维护.md)：增加 tags 视图及标注筛选，保留既有范围和分页输入。`compact` 只返回当前视图及其必要归属，不序列化其他视图的空槽；`full` 保留现有详细信息。

| 视图 | compact 必须保留的信息 |
| --- | --- |
| works | 作品 ID、名称及列表续页凭据 |
| parts | 所属作品 ID/名称、分部 ID/名称、顺序及续页凭据 |
| sections | 所属作品、分部 ID/名称、章节 ID/标题/顺序及续页凭据 |
| tags | 共享标签 id、namespace、name、full_name、description、aliases 及 tag_page 续页凭据 |
| annotations 列表 | 标记 ID、状态、版本、短说明、真实引用预览及其截断/未展示引用提示、简短 tags:[{id,full_name}]、续页凭据 |
| annotation 详情 | 标记 ID、作品归属、状态、版本、全部真实引用、短说明、标签 ID/namespace/名称/定义/别名；不因精简而失去安全修订所需信息 |
| jobs | 任务 ID、目标范围、状态、版本、判断与接续所需的摘要及续页凭据 |

上述为字段语义清单，优先沿用既有英文键和可复用投影。普通导航不附带文件摘要、字节数、时间和全作品索引统计。操作所必需的状态、版本和截断说明不属于可删除的噪声。

### 3.3 source_read

保留完整自然段及其 ID、顺序、作品与章节身份、`actual_range`、已有请求范围信息和 `next_cursor`。`actual_range` 仅表示本页真实返回的段落，不表示请求或扩展范围全部读完；整章读取也遵循此规则。`full` 增加既有原文读取投影中的详细定位信息。

原文按既有范围与分页规则读取，不新增阅读会话存储。格式不进入游标绑定条件；同一数据状态、同一范围和同一页切换格式，段落身份、正文与顺序一致。只有召回候选使用第 6 节的持久搜索快照，不承诺目录和原文读取跨业务变更仍保持旧快照。

## 4. 多作品查询输入

`reference_query` 支持两类互斥请求，不增加工具名称或任意 `action`。

| 类型 | 输入 |
| --- | --- |
| 新查询 | 必填 `query`、`scope`；可选 `terms`、`exclude_ranges`、`limit`、`format`；不接受 `search_id/cursor` |
| 续查或重读 | 必填 `search_id`；可选 `cursor`、`format`；不接受 `query/scope/terms/exclude_ranges/limit` |

新查询 `query` 和 `terms` 沿用现有长度、非空及查询 token 校验；`limit` 默认 8，范围 1–30，仅决定每页条数，在本轮搜索内固定。旧 `work_id/part_id` 查询形式不继续兼容，实际调用方随实施一起更新。

`scope` 是 1–20 项的数组，每作品只能出现一次。每项必填 `work_id`，可选 `part_ids` 或 `section_ids`，二者互斥：

- 仅 `work_id` 表示该作品全部原文。
- `part_ids` 表示这些分部的并集；`section_ids` 表示这些章节的并集。
- 显式选择列表不得为空或含重复 ID；重复作品拒绝，不隐式覆盖或合并。
- 所有选择 ID 合计最多 200 个；校验分部、章节确实属于对应作品。
- 空 `scope`、非法归属或不可读作品返回错误，不回退到全库，也不静默跳过。

范围在全部通道的候选生成和原文覆盖检查中生效。任何指定范围的必要原文索引未完整就绪，整次请求返回 `REFERENCE_NOT_READY`，指明未就绪的作品及所选范围；不返回部分成功列表。检查针对选定范围，不要求作品中未选择的分部也就绪。已读排除不用于绕过所选范围的就绪检查。

当前线索尚未全部同步时，允许使用完整原文索引、当前有效的线索向量和当前线索字面内容，按第 3 节提示缺口；过期线索向量不得参与。所有作品使用同一模型契约，一次新查询只生成一个查询向量。

## 5. 排除已读与候选生成

### 5.1 exclude_ranges

新查询可提供最多 200 条 `SourceRange`，默认空数组。每条使用作品、章节和起止段落 ID；端点必须存在、属于指定章节且先后合法。条数限制在归一化之前检查。

为方便 AI 复用当前探索的已读清单，允许携带当前 `scope` 外的有效已读范围；仍校验其作品可读及端点归属，只对与 `scope` 相交的部分生效。不得因此扩大查询范围。返回归属或可读性错误时，AI 可移除不再适用的条目后重新查询。

同一章节内重复、相交和相邻的已读范围合并。候选整个范围被已读区间并集覆盖时排除；只要还含未读段落就保留。排除在各通道排序截取窗口前生效，不能先拿满已读候选再删除而造成假性空页。

不裁碎部分重叠候选，不拼接不连续原文，不因读过几段就排除整章。本规则减少重复，不保证不同结果完全没有重叠。已读清单不修改分析任务的 processed 进度，也不在服务中形成跨创作任务的阅读历史。

AI 根据实际取得并阅读的正文决定排除范围，可将 `source_read` 的本页 `actual_range` 与作品、章节 ID 组成 `SourceRange`；不能用整个请求范围或截断预览冒充已读。排除只约束候选搜索，不阻止 `source_read` 回读这些原文。

### 5.2 四路召回、融合与排序

1. 原文语义、原文字面、标记线索语义、标记线索字面四路继续参与，未标记原文必须可召回。
2. 每一路在全部选定作品范围内统一排序，最多保留 300 条，并多取 1 条判断窗口截断。不能先各作品取固定配额或先分别计算 RRF 再混排。
3. 字面通道使用完整查询、显式 `terms` 及从查询分词获得的最多 12 个有效词，去重后匹配。自动词过滤请求套语、标点和单字，不扩展同义词；否定词所在分句中，从否定词开始停止自动提词，防止把“没有发作”单独扩成“发作”。这是保守的字面补召回，不保证理解所有否定或情节条件。完整查询始终用于语义推理。`full.diagnostics.keyword_terms` 返回实际使用的词，`terms` 仍表示用户显式输入。
4. 字面通道按命中词数降序；同词数时，原文字面候选按包含该段的原文向量窗口与完整查询的最小余弦距离升序，线索字面候选按当前有效线索向量距离升序，没有有效向量的线索排在同词数有向量者之后。向量通道继续按余弦距离。每路同分顺序包含稳定且唯一的作品、章节、端点和来源身份；输入 scope 的排列不构成权重。复用本次查询向量，不增加推理次数。
5. 将四路最多 1200 条原始候选整体按加权 RRF 融合，常数 60，每通道保留最佳名次。两个语义通道权重各为 1，两个字面通道权重各为 0.25；缺少的通道计零。分词只反映局部词义，字面作为完整查询语义的辅助，避免一个词同时出现于原文和说明就获得两份完整语义证据的权重。权重是固定的工程启发式，不表示概率。同作品同章节重叠达到较短范围 80% 时合并，真实端点和全部关联标记身份保留。沿用桥接候选的完整去重规则，不跨作品或章节合并。
6. 最终按融合分数降序，再按作品 ID、章节顺序、章节 ID、起止段落顺序和端点 ID 稳定排序，保存整个融合结果后分页；同一保存列表中的每一项只占一个位置。

检索优化验收：自然语言查询无需手填 `terms` 即能形成有效字面候选；完整查询仍只推理一次；候选中后部命中能够展示未经改写的原句；无命中回退、范围隔离、排除和冻结分页不退化。以固定的多主题查询集回读原文，对比优化前后的相关性和耗时；公开验证范围和失败案例，不以字面命中或单一主题证明总体文学相关性。

候选池与 `format/limit` 无关，不设置每作品保底配额，不把 RRF 分数解释为文学质量或概率。相同冻结候选输入在不同 `limit` 下应得到相同融合列表；独立新查询可能因模型数值或数据变化产生不同结果，不承诺跨独立推理结果逐位相同。

`next_cursor=null` 仅表示本轮保存列表已结束。`candidate_window_limited=true` 时仍可能存在未纳入列表的候选，AI 可调整问法、范围或已读排除后新查。不得把空结果或翻页结束描述为已经穷尽全部相关原文。

## 6. 搜索快照与稳定续查

### 6.1 保存与重放

搜索快照复用 PostgreSQL，保存规范化查询、范围与排除条件、固定页大小、有序候选、预览及诊断快照和业务变更标识，不保存整部正文或查询向量。不引入 Redis、长时间数据库事务或客户端后台任务。

新查询在推理前做输入预检，网络推理在数据库事务外进行；候选查询、必要范围和业务状态的再次校验、快照保存使用同一一致性事务，全部成功才返回。失败不留下半份可用搜索；不因快照写入更新作品、分析进度或索引待办。

续查只读取已保存结果，不重新调用 embedding，不重新排序或补入新候选。`search_id` 不带 `cursor` 表示重读第一页；下一页游标绑定搜索 ID 和页位置，不接受客户端任意偏移。错误、篡改或混用游标返回 `INVALID_CURSOR`。

游标校验依据须在同一数据库服务的不同进程及重启后有效，不能依赖单个进程的临时密钥或内存映射。

重复及并发请求同一页返回同一候选和相同下一页，不维护“读到哪一页”的可变指针。格式不绑定游标，可对同一页切换 `compact/full`。响应丢失时，有已知搜索 ID 或游标即可安全重读；首轮响应完全丢失可重做新查询，不增加检索幂等键。

### 6.2 有效性与变更

快照自创建起固定有效 30 分钟，续页不延长；进程重启且快照仍有效时可以继续。续页检查与读取快照在同一数据库事务中完成，以该事务的一致性状态为准，不长期持锁等待 AI 阅读。

以下变更使旧搜索失效：所选作品隐藏、删除或原文追加/修改；有关标记、引用或标签修订、撤回；服务当前配置的模型契约改变。失效返回 `REFERENCE_SEARCH_STALE`，不悄悄重查，不跳过旧条目后伪装为原来的页。

本期允许按所选作品的业务 revision 保守判定，因此同作品未选范围的业务变更也可能使搜索失效；不要求维护精细到每个查询范围的依赖图。版本标识必须覆盖共享标签变更和可见性变化，不能依赖可回退状态值而遗漏隐藏后恢复等变化。只改变准备进度或读取状态不使搜索失效。

同一业务内容下的索引继续计算、线索向量发布、全文代切换或旧派生代清理，不使搜索失效。旧页继续展示创建时的结果和诊断，不把新发布的结果插入旧排序；快照不依赖旧派生行继续存在。续查只核对本地模型契约身份，不以模型进程在线为前提，也不借此为新查询提供降级路径。

过期、清理后不存在或未知搜索统一返回 `REFERENCE_SEARCH_UNAVAILABLE`，不假报空页。作品删除可删除其相关搜索快照，此时允许返回该错误；任何失效或不可读路径均不返回缓存正文。全局已读状态不存在，AI 可在新查询中继续提交本次有效的已读范围。

### 6.3 资源与失败边界

- 每会话最多 1200 个融合结果，存储载荷最多 4 MiB；超限返回 `REFERENCE_SEARCH_TOO_LARGE`，建议缩小 scope 或线索，不静默删减候选或标记身份。
- 同一数据库最多保留 256 个未过期会话。创建时先有界回收过期或已标记失效的记录，再原子检查并占用名额；并发不能突破上限。达到上限返回可重试的 `REFERENCE_SEARCH_CAPACITY`，不驱逐其他有效搜索。
- 过期记录由服务周期有界清理，并在创建时补充清理；不只依赖下一次用户调用。清理只影响搜索快照，不触碰原文、标记或分析进度。失败创建不占永久名额。
- 沿用单结果 1 MiB 上限。创建时按固定页大小校验所有页的 `full` 投影均满足上限，包括诊断与分页元数据；否则首轮即返回 `RESULT_TOO_LARGE`，建议减小 `limit` 或缩小范围。不得等切 full 才截断或更换候选。4 MiB 会话上限与 1 MiB 页上限独立检查。
- 查询、预览及完整响应不写日志；快照只是有期限的业务数据，不额外扩展对外权限。部署若已有访问隔离，快照读写须沿用同一隔离边界，随机 ID 不能代替授权。

上述数值是本期明确的工程上限，不是召回效果保证；实施验收发现不合适时须说明证据并修订规格，不在客户端不知情时静默放宽范围或截断结果。

## 7. AI 调用流程与同步范围

1. 用 `library_browse` 选择用户允许的参考作品与必要范围，普通导航使用 compact。
2. 发起 `reference_query`，根据候选原文入口选择需要阅读的材料。
3. 用 `source_read` 取得完整段落，按需要扩展上下文或续读；预览与短说明不替代理解。
4. 需要同一问法的更多候选时，用 `search_id/next_cursor` 继续；不必重新提交查询或重做向量。
5. 需要换问法、作品范围或排除已读时，新查并携带适用的 `exclude_ranges`。必要时主动回读，不把排除清单当永久禁读名单。
6. 仅检查诊断时对原搜索相应页切换 full。过期或业务变更则新查，并如实区分新旧搜索。

不固定查询轮数、阅读数量或必须翻完的页数；不要求用户手动决定参数。上下文压缩后，已读位置只用于导航，不能当作当前仍记得原文的证明。停止条件仍是当前创作需要得到满足，而非遍历整个参考库。

实施时同步共享输入输出、HTTP 及默认 MCP schema、客户端调用、接口说明、需求基线与 Spec 08/13、两份 Skill 及其接口参考、迁移和必要测试。新字段发布前不提前把未实现示例写入生效 Skill；维护工具保持原契约。数据库快照结构采用最小必要设计，不另建文学分析或阅读历史系统。
