# 05 实体与跨章节关系

状态：已实现；2026-09-19 完成 Windows、真实 PostgreSQL 18.6 及官方 MCP 客户端验证，包含实体、跨章节关系和关系撤回恢复。共享开发库已升级至 0003 并通过结构与数据核验，实际 AI 客户端宿主尚未联调。

依据：[需求与设计基线](../docs/小说分析与创作知识服务_需求与设计基线.md)第 3、8、11–13、22.4–22.5、22.9、35.3 节，以及 [Spec 04](04-分析标注与标签管理.md)的事务、版本和写入恢复契约。原文与传输规则沿用 [Spec 02](02-小说导入与原文读取.md)及 [Spec 03](03-本地MCP原文能力接入.md)。

## 1. 目标与范围

外部 AI 能记录作品中值得持续追踪的对象，把标注关联到这些对象，并将不同位置的原文组织成可核验的关系。例如：找到某个人物 → 找回相关标注及关系 → 查看“建立、提醒、回收”等节点 → 选择必要节点读取原文。

本期包含 Entity 的创建、修改与查询，Annotation 的实体关联，Relation 及其有序节点的创建、修改、检索、概览展开、撤回和恢复。Relation 不依赖 Annotation 存在，可以直接连接尚未标注的原文。

继续使用同一个本地 FastAPI / MCP 应用和 PostgreSQL，复用资产写入请求键、事务、版本校验及结果恢复。不引入图数据库、向量模型、全文搜索扩展、新进程或新客户端入口。

本期不包含实体自动识别、逐词 Mention、实体合并或删除、关系物理删除、自动推断伏笔、跨作品关系、StyleGuide、Coverage、AnalysisJob 或分析 Skill。是否建立实体、节点为何相连、关系确认到什么程度均由外部 AI 判断。尚无证据支持的单点线索不预先保存成已确认关系；本期不提供其专用接续存储。

## 2. Entity：作品内的对象身份

### 2.1 字段与范围

| 字段 | 规则 |
| --- | --- |
| id / work_id | 稳定 UUID 与所属作品；服务生成 id，创建后不得更换 work_id |
| type | character、location、item、organization、concept 五种之一 |
| canonical_name | 必填，1–256 个 Unicode 码点，不含首尾空白 |
| aliases | 默认 []，每项 1–256 个码点，不含首尾空白；精确去重并排序 |
| note | 可选身份说明，默认 null；帮助区分对象，不作为大型人物分析档案 |
| version / created_at / updated_at | 版本从 1 开始；时间、修改条件和重放行为沿用 Spec 04 |

文本拒绝 NUL，不自动裁剪或做大小写、Unicode、同义词归一化。note 为 null 或非空白文本，按输入保留换行；说明应简短，但不另设文学字数规则，容量沿用完整资产响应上限。

实体按作品隔离，不像 Tag 那样跨作品共享。不同作品中的相同姓名或别名不视为同一对象；同一作品内也允许同名、同类型对象，以 id 区分，必要时在 note 说明身份。不能为了名称唯一而迫使 AI 修改原作姓名。

不对 canonical_name 或 aliases 建立语义唯一约束，不自动合并别名相同的对象。相同请求键的重复创建由幂等机制阻止；新请求键创建同名对象允许成功。调用方应先搜索并判断是否复用，不能把名称相等当作身份相同的证据。

### 2.2 修改与查询

entity_update 要求 expected_version，完整提交 type、canonical_name、aliases、note；修改身份描述不改变 id，不自动修改已关联的原文、标注或关系。清空别名传 []，清空说明传 null。

所有实体接口都要求 work_id。entity_get 或 update 使用其他作品的 entity_id，按 ENTITY_NOT_FOUND 处理，不返回该对象的内容。entity_list 可按 type 精确过滤；entity_search 另要求非空白 query，对 canonical_name、aliases、note 做不区分大小写的字面子串匹配，模式字符按普通字符处理。同名或同别名候选全部返回，不替 AI 选择身份。

列表返回完整轻量 Entity，分页默认 100、上限 1000，按 created_at、id 排序，游标绑定查询类型、作品及全部过滤条件。不存在的作品与没有匹配实体分别返回错误和空页。

## 3. Annotation 的实体关联与兼容

给现有 Annotation 增加 entity_ids 集合，关联的全部 Entity 必须属于标注的 work_id。只有身份关联，不代表服务已识别正文中的每次人物出现，也不自动创建或修改 Entity。

- annotation_create 新增可选 entity_ids，缺省为 []；与范围、标签和说明在同一事务提交。
- annotation_get 的当前详情及新写入的标注快照返回 entity_ids；annotation_list 的 full 摘要包含 entity_count，默认 compact 省略该计数，不自动展开实体详情。阅读格式由 Spec 04 维护。
- annotation_list 新增可选 entity_ids 过滤，要求同时具有全部指定实体；可与标签和位置过滤组合。空集合表示不过滤，不存在或跨作品的实体 ID 返回 ENTITY_NOT_FOUND。
- annotation_update 可显式提交 entity_ids 完整替换；[] 表示清空。旧客户端省略该字段时保留当前关联，不能因为旧请求不了解新字段而删除关联。原有 source_ranges、tag_ids、note 的显式完整替换规则不变。
- 同次修改中的实体、标签、范围和说明使用同一 expected_version；不提供绕过版本检查的独立关联写接口。

实体更新不增加引用它的 Annotation 或 Relation 版本：这些资产保存稳定实体 ID，不保存一份随实体名称变化的副本。需要当前实体名称或说明时调用 entity_get。

### 3.1 旧请求与游标

新增可选字段不能让已有成功请求的相同输入重试变成 REQUEST_CONFLICT。实施时必须覆盖以下兼容行为：

1. annotation_create 的 entity_ids 缺省或 []，继续采用 Spec 04 的原请求指纹，不把空集合加入旧指纹。
2. annotation_update 省略 entity_ids 时，沿用原指纹及“保留关联”语义；显式提交 entity_ids 时，在新版指纹中包含该字段。省略与显式 [] 不等价，不能在计算指纹前丢失字段是否出现的信息。
3. 带非空实体的创建、显式设置实体的修改及新实体/关系操作，使用明确的新契约版本及规范化输入计算指纹。集合排序去重，节点顺序保留；不能先检查当前版本再识别已提交重放。
4. 历史请求结果按保存时的 result 快照返回，不批量追加 entity_ids 或改写历史 JSON。历史 Annotation 快照可以不含 entity_ids，schema 须允许该格式；当前详情返回新格式。缺少历史字段不表示当前标注没有实体关联。
5. 已有无实体过滤的 annotation_list 游标继续有效；新增过滤集合为空时，不改变原有过滤摘要。使用非空实体过滤时将其纳入游标范围，不得串用。

兼容验证必须使用真实 0002 数据和按旧契约生成的请求记录、指纹及游标，不能只用升级后的代码创建“旧样例”再验证自己。

## 4. Relation：可核验的原文关联

### 4.1 字段与节点

| 字段 | 规则 |
| --- | --- |
| id / work_id | 稳定 UUID 与所属作品；创建后不可更换 work_id |
| title | 必填，1–256 个码点，不含首尾空白，用于辨认这条关系 |
| relation_type | 必填，1–64 个码点，不含首尾空白，例如“伏笔回收”；开放文本，不固定文学分类枚举 |
| tag_ids / entity_ids | 默认 []；标签复用共享词表，实体必须属于关系所在作品 |
| nodes | 有序列表，至少两个不同的原文范围；节点顺序由调用方指定 |
| note | 必填、非空白的关系说明，解释节点为何相连以及判断边界；不强制固定表单 |
| status | active 或 withdrawn；创建时为 active，通过 relation_set_status 撤回或恢复 |
| version / created_at / updated_at | 沿用资产版本与时间规则 |

每个节点输入为 `source_range、role`。SourceRange 沿用已有四个 UUID 字段；role 可省略或为 null，有值时为不含首尾空白的 1–64 字符文本，例如“建立”“提醒”“回收”。所有文字拒绝 NUL。

全部节点范围必须属于 work_id，单范围内部不能跨 Section，端点真实存在且顺序正确。节点可以分布于多个章节，也可以位于同章；允许范围相交，但同一关系内完全相同的 SourceRange 不重复保存。不同关系可使用相同范围，服务不按标题或原文重叠自动去重。

输出为节点增加从 1 开始的 ordinal。ordinal 只表示当前关系版本中的位置，不是跨版本稳定 ID；本期不创建独立节点 UUID 或逐节点更新接口。节点排列不被程序解释成必然的时间或因果顺序，也不自动补充图上的边。多处铺垫对应一次回收，可用多个节点和 role、note 表达。

relation_update 要求 expected_version，完整提交 title、relation_type、tag_ids、entity_ids、nodes、note；原子替换并增加版本。不能留下关系主记录已更新、部分节点仍属旧版本的状态。

### 4.2 撤回与恢复

relation_set_status 只修改 status，要求 request_id、work_id、relation_id、expected_version 及目标 status；withdrawn 表示撤回，active 表示恢复。保留标题、说明、原文节点和全部关联，不物理删除记录。每次成功的新请求增加版本并更新时间，包括目标状态与当前相同的请求；同键重放返回原快照，不再次修改。状态修改与内容修改竞争同一个版本，普通 relation_update 保留现有状态，不隐式恢复关系。

普通 relation_search 默认 status=active，可显式选 withdrawn，或传 null 查询全部状态；游标绑定状态过滤。摘要、详情、节点概览和写入快照均返回 status。已撤回关系仍可按 ID 获取或展开；状态变化使旧 expected_version 失效，避免撤回期间继续把旧概览当成当前关系。撤回和恢复不表示文学判断通过验证，也不推进分析进度。

### 4.3 查找与按需展开

relation_search 必须指定 work_id，可组合以下可选条件：query（非空白时匹配 title、note）、relation_type 精确值、source_range 相交、tag_ids 全部匹配、entity_ids 全部匹配及 status。未提供过滤条件时返回该作品的 active 关系页；不再添加功能重复的 relation_list。

query 采用与其他资产查询相同的字面子串规则，不进行语义检索；传入空白 query 无效，省略或 null 表示不按文本过滤。所有传入坐标、标签和实体均校验；实体不得跨作品。位置匹配表示任一节点与查询范围在同 Section 内相交，含边界。返回摘要：id、work_id、title、relation_type、version、created_at、updated_at、first_source_range、node_count、tag_count、entity_count、note_preview、note_truncated。说明预览最多 200 个码点，裁剪状态明确返回。

relation_get 返回当前完整关系说明、标签 ID、实体 ID、节点总数及版本，不展开节点列表或正文。relation_expand 按页返回指定关系版本的节点概览，包含 ordinal、source_range、role；不默认读取任一节点的正文。

典型调用顺序：

```text
relation_search：选择候选
    → relation_get：读取完整说明、node_count 与 version
    → relation_expand：按页取得节点范围与角色
    → source_read / source_get_context：选择必要节点读取真实正文
```

relation_expand 必须带 expected_version，避免从概览到翻页期间关系已修改而混合节点。返回 work_id、relation_id、version、status、items、next_cursor；游标绑定该关系和版本。当前版本不匹配返回 VERSION_CONFLICT，调用方重新获取关系后决定是否继续。游标与请求范围不一致时优先返回 INVALID_CURSOR。

关系搜索分页按 created_at、id，节点分页按 ordinal；limit 默认 100、上限 1000。单次读取保证同一快照，多页搜索不承诺一致快照。传输体积仍受 1 MiB 上限限制，超限返回 RESULT_TOO_LARGE，不截断正文或完整说明。

已有关系说明是库内保存的判断，不表示当前调用方核验过所有节点。工具不生成“已读”“已确认”或完成分析的进度记录。

## 5. 写入恢复与 MCP 工具

五个新增写工具要求 request_id，与 Spec 04 共用资产请求键空间及 asset_write_get。实体或关系主记录、关联、节点和成功请求结果必须在一个事务内提交；失败全部回滚，已有独立实体或标签不受影响。

同键同输入返回原提交快照，同键异输入或不同操作返回 REQUEST_CONFLICT。实体和关系修改沿用 expected_version、并发冲突和重放先行规则；旧请求在后续修改后重放不得覆盖当前状态。

写入结果沿用 `request_id、operation、status、replayed、result`。实体 result 为完整 Entity；关系 result 为包含全部节点范围和角色的提交快照，不含节点正文。快照与 relation_get 的概览结构不同，必须在 outputSchema 中分别声明，不能在重试或查询写入结果时读取当前关系拼装旧结果。

成功结果在提交前按紧凑 UTF-8 JSON 计量，包含封装不得超过 1 MiB；超限以 ASSET_TOO_LARGE 回滚。历史快照不加字段，避免升级将原本可恢复的临界大小响应扩大至超限。继续区分 HTTP 传输错误、MCP 协议错误与 isError=true 的业务错误，不泄露正文、说明、SQL 或凭据。

| 新工具 | 输入 | 结果 |
| --- | --- | --- |
| entity_create | request_id、work_id、type、canonical_name；可选 aliases、note | 写入结果 |
| entity_update | request_id、work_id、entity_id、expected_version、type、canonical_name、aliases、note | 写入结果 |
| entity_get | work_id、entity_id | 当前完整 Entity |
| entity_list | work_id；可选 type、limit、cursor | Entity 页 |
| entity_search | work_id、query；可选 type、limit、cursor | Entity 页 |
| relation_create | request_id、work_id、title、relation_type、nodes、note；可选 tag_ids、entity_ids | 写入结果 |
| relation_update | request_id、work_id、relation_id、expected_version、title、relation_type、nodes、note、tag_ids、entity_ids | 写入结果 |
| relation_get | work_id、relation_id | 当前关系说明与计数，不含节点列表和正文 |
| relation_search | work_id；可选 query、relation_type、source_range、tag_ids、entity_ids、status（默认 active，null 表示全部）、limit、cursor | 关系摘要页 |
| relation_expand | work_id、relation_id、expected_version；可选 limit、cursor | 当前指定版本的节点概览页 |
| relation_set_status | request_id、work_id、relation_id、expected_version、status | 保留全部内容的写入快照 |

另扩展现有 annotation_create、annotation_update、annotation_get、annotation_list 和 asset_write_get 的字段或结果类型，不新建相同用途的工具。当前工具总数从 18 增至 29。

新增 ENTITY_NOT_FOUND、RELATION_NOT_FOUND；其余沿用 INVALID_INPUT、INVALID_RANGE、INVALID_CURSOR、VERSION_CONFLICT、REQUEST_CONFLICT、WRITE_NOT_COMMITTED、ASSET_TOO_LARGE、RESULT_TOO_LARGE、标签/原文归属和数据库错误。未知参数拒绝；集合、版本、分页和源坐标不允许绕过已有校验。

## 6. 实施边界与迁移

迁移 0003 增加 entities、annotation_entities、relations、relation_nodes、relation_tags、relation_entities。实体和关系主表保存作品归属、版本和时间，关系主表另保存 status；别名使用 JSONB；节点表保存有序范围及 role，不复制正文。关联去重、外键、正版本、合法类型与状态、节点序号约束在数据库落实，跨作品与范围顺序在事务内核验。

不修改已有作品或原文坐标，不改写 0001、0002 迁移。已有标注在升级后没有实体关联；历史成功请求的指纹和快照保留。增加查询索引时应对应实际筛选和分页条件，不预建全文或图遍历索引。

修改现有资产输出模型、指纹计算和游标构造时，必须按第 3.1 节保持旧契约兼容。复用事务与结果保存机制时，只作实体和关系所需的扩展，不改造为通用工作流框架。

实现同步维护 Spec 04 的 Annotation 当前字段、请求兼容规则、MCP schema、README、迁移和回归验证。历史验证记录保留当时范围，新增验证单独记录。
