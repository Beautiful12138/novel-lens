# 06 轻量风格导航

状态：已实现；2026-09-20 完成 Windows、真实 PostgreSQL 18.6 及官方 MCP 客户端验证。共享开发库已从 0003 升级至 0004，并通过结构、既有数据及 MCP 只读核验；实际 AI 客户端宿主尚未联调。

依据：需求与设计基线第 8.6、21.8、35 章；沿用 Spec 02–05 的原文定位、MCP、事务、版本和写入恢复契约。

## 1. 目标与边界

每部作品最多维护一份轻量风格导航，帮助外部 AI 恢复对作品叙述方式的理解，并按条目返回原文核验。文学判断、证据是否充分及适用范围由调用方负责；服务只校验结构、引用与写入一致性。

本期提供导航创建、按作品读取和整体修订。仅引用 SourceRange，不增加 Annotation / Relation 关联、标签、逐条编辑、自动合并、独立历史版本浏览、搜索、Web 或业务 CLI。不执行文学分析，不改变原文，不更新 Coverage / AnalysisJob 或声明全书完成。

## 2. 数据契约

导航以 work_id 唯一定位，不另外生成导航 ID。字段为 work_id、scope_note、entries、version、created_at、updated_at。

- scope_note：必填非空白文本，说明实际分析范围与局限；是调用方声明，不是服务验证的分析进度。
- entries：必填有序数组；每项含 title、kind、description、applicability、source_ranges。
- title：1–256 个 Unicode 码点，不含首尾空白；允许不同条目同名。
- kind：baseline（常态）、variation（条件性变化）、exception（例外）。常态也受实际分析范围限定。
- description、applicability：必填非空白自由文本；服务不规定文学维度或字数模板。
- source_ranges：至少一处，结构沿用 SourceRange；全部属于导航作品，单范围不得跨 Section，端点合法且起点不晚于终点。条目内完全重复引用拒绝，不同条目可引用相同范围，允许范围重叠。
- 文本拒绝 NUL，说明保留换行与原输入，不自动裁剪或归一化。
- 数组按输入顺序保存。条目及证据不提供稳定独立 ID，顺序不表示强度或频率。
- entries 可为 []，用于尚无可保留结论或撤除全部旧判断；scope_note 仍须明确范围和局限。导航存在或条目数量均不代表完成分析。

每项文学判断应写成独立条目并提供相应证据。服务无法判断一个文本是否混入多个无证据判断，也不根据标签占比生成风格频率。

## 3. MCP 与写入行为

| 工具 | 参数与返回 |
| --- | --- |
| style_guide_create | request_id、work_id、scope_note、entries；返回 AssetWriteOut，result 为完整导航 |
| style_guide_get | work_id；返回当前完整导航，不携带小说正文 |
| style_guide_update | request_id、work_id、expected_version、scope_note、entries；整体替换并返回 AssetWriteOut |

创建版本为 1。已存在导航时，新键创建返回 STYLE_GUIDE_EXISTS；同键同输入重试仍返回原提交快照。更新须显式提交完整 scope_note 和 entries；无导航时不自动创建。每次成功的新更新请求使版本加一，即使内容相同；版本不符返回 VERSION_CONFLICT，不自动覆盖或合并。

作品不存在返回 WORK_NOT_FOUND；作品存在但尚无导航时 get / update 返回 STYLE_GUIDE_NOT_FOUND。引用校验沿用 INVALID_RANGE、SECTION_NOT_FOUND、PARAGRAPH_NOT_FOUND；不返回其他作品正文。非法结构、未知字段和重复引用在 MCP 返回 INVALID_INPUT。

写工具共用资产请求键空间和 asset_write_get；同键不同操作或输入返回 REQUEST_CONFLICT。顺序属于输入语义，重试不得更改条目或引用顺序。提交快照保留当次全部条目和引用，不代表当前版本。失败事务不消耗请求键，不留下部分导航或引用。

完整 AssetWriteOut 上限沿用 1 MiB；超限提交前回滚并返回 ASSET_TOO_LARGE，不截断。get 返回的导航小于该写入信封，不需分页。创建、更新与恢复继续使用现有 HTTP MCP 服务，无新增依赖或监听端口。

## 4. 存储与一致性

迁移 0004 新增 style_guides、style_guide_entries、style_guide_ranges 三张表，分别保存导航主记录、有序条目、有序原文引用；不复制小说正文。主表以 work_id 为主键并引用 works；条目和范围使用包含父级顺序的复合主键及外键，重复引用通过唯一约束防御。

写入事务先竞争资产请求键；创建通过 work_id 唯一约束裁决并发，更新锁定导航主记录并检查版本。范围归属和端点顺序在同一事务内核验，主记录、条目、引用和请求快照原子提交。读取使用一致快照，避免并发修订时拼接新旧内容。

迁移仅增加本期表，不重写既有资产、指纹、快照或游标。共享开发库的升级属于单独操作，不随本地实现自动执行。显式 downgrade 删除本期导航表，保留其他资产与历史写入快照。

## 5. 验收

1. 通过真实 PostgreSQL 与官方 MCP 客户端创建、读取、整体修改导航，保留中文、换行、条目及证据顺序；source_read 能按返回引用读取原文。
2. 不存在作品、缺失导航、重复创建、无证据条目、跨作品或跨章节端点、倒序范围、重复引用、未知字段和非法类型得到明确错误；失败后无部分数据。
3. 同键并发创建或更新只提交一次；不同键并发创建只有一份导航；同版本并发修改仅一次成功。旧键在后续修改及重启后仍恢复原快照。
4. 整体修改可删除、重排条目和证据，显式 [] 清空结论；读取不混合并发版本。
5. 超限与写入中途数据库故障完整回滚，原导航保留且原键可重试。
6. 0003 → 0004 迁移保留既有资产与请求恢复能力，结构与 metadata 一致；原有 MCP 工具和历史快照契约回归通过。
