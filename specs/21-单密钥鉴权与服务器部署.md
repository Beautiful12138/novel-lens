# 21 单密钥鉴权与服务器部署

状态：实施中。用户已授权本地实现、提交推送及部署到 jiege 服务器的 10003 端口。密钥仅保存于私有配置，不进入源码、示例、日志或文档。

## 范围

在原有本机服务上增加可选的单密钥鉴权。HTTP 与 MCP 使用同一 Bearer 密钥；网页提供密钥登录、会话过期重新登录和退出入口。不增加用户、注册、角色、权限表或 OAuth 服务。仅支持允许手工配置 Bearer 请求头的 AI/MCP 客户端；所有持有密钥的调用方拥有同等业务能力。

应用仍只监听回环地址。公网入口通过 HTTPS 反向代理，配置唯一的公开 origin；配置公开 origin 必须同时配置访问密钥，禁止误部署为匿名公网服务。未配置公开入口及密钥的本机实例保持原行为。

## 鉴权与网页行为

- `NOVEL_LENS_ACCESS_KEY` 为私有密钥配置；`NOVEL_LENS_PUBLIC_ORIGIN` 为可选 HTTPS origin，不含路径、查询、用户信息或片段。配置错误不得回显密钥。
- 全部业务、下载、维护、MCP、完整及精简 OpenAPI 接口统一校验。仅存活检查、登录状态、登录/退出和网页静态壳无需业务认证；未登录不得读取作品、原文、资产或执行写入。
- API 采用 Authorization: Bearer；错误凭据统一返回 HTTP 401 及安全业务错误。不能使用查询参数中的密钥，错误的 Authorization 不回退到 Cookie。连续失败有有界的短期限流。
- 网页登录后使用有效期 8 小时的签名 Cookie，HttpOnly、SameSite=Strict，公开部署设置 Secure。不将原密钥保存到 Cookie、浏览器存储或前端构建产物。改密钥使旧会话失效；退出清除浏览器 Cookie。
- Cookie 认证的写入及登录/退出核验请求来源，不接受其他 origin。Bearer 调用不依赖浏览器会话。反向代理须保留正确 Host，MCP 接受已配置的公开 Host/Origin，不放宽为任意来源。
- 网页在确认认证状态前不请求业务数据；登录失败、网络失败和会话失效提供明确反馈，可重试；失效后隐藏业务视图并保留页面定位。沿用现有 PC 界面样式。

## 部署与数据

部署复用服务器现有 PostgreSQL，版本仍为 0017，不执行初始化、清库或迁移。10003 作为 HTTPS 的统一 WebUI、HTTP、MCP 入口，应用在服务器独立回环端口运行。新增应用与代理配置前核实路径、监听及证书，保留部署记录和可回滚版本，不覆盖其他应用配置。

部署使用经本地验证并推送的具体 Git 提交；前端构建和后端产物与该提交对应。凭据放于 Git 之外的权限受限配置。服务使用限定权限的运行账号，仅提供部署指定目录的文件访问。服务器导入路径指服务器文件；本机路径不自动上传。

## 验收

验证未认证 HTTP/MCP/下载/文档被拒绝；正确 Bearer、Cookie 登录与退出、过期、伪造、密钥轮换、错误 Authorization 不回退和跨来源写入拒绝；验证旧本机模式及公开配置缺失密钥时拒绝启动。验证 OpenAPI 的认证声明与实际行为一致。

在隔离数据库与真实 HTTP/MCP 验证鉴权后原有业务正常。前端验证未登录不读业务、错误提示、成功登录、会话失效和退出，执行构建与 PC 浏览器检查。

部署后从外部实际验证 HTTPS 证书、10003 可达、匿名拒绝、认证后目录和原文只读、15 项 MCP 及应用重启恢复；比对部署前后业务表摘要。检查 Git 远程 SHA、运行版本及构建产物摘要，不以进程存活代替验收。
