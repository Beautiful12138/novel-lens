# 07 分析进度与中断接续

当前分部增量见 [Spec 12](12-作品分部与追加导入.md)：原文归分部，资产归作品；目录及搜索支持分部范围，任务固定创建时目标，来源追加使语义代过期。目录写入回执、全部分部及原文件随作品删除。旧数据与接口不再兼容；下方历史验证记录保留当时语义。


状态：任务与 Coverage 能力已实现；结构在 0005 阶段引入，该阶段升级与验证见第 11 节，当前部署版本见部署指南。本文定义底层任务与维护入口契约；默认导入任务、批次标记、索引核对和完成由 Spec 13 定义，不要求日常 AI 手工组合维护接口。

依据：[需求与设计基线](../docs/小说分析与创作知识服务_需求与设计基线.md)第 19、20、22.7、22.9、25.2、35 章，以及 [Spec 04](04-分析标注与标签管理.md)、[Spec 05](05-实体与跨章节关系.md)、[Spec 06](06-轻量风格导航.md)的资产写入和恢复契约。

## 1. 目标与范围

外部 AI 可以在指定作品及目标范围内持续分析，记录处理进度、需要回看的位置和必要接续信息。进程重启或会话更换后，可以核对已提交成果，恢复事实入口和未决问题，再继续处理。

第一版任务表示对整本作品或选定原文范围进行完整深读；目标可以是若干章节或其他样本范围，不要求每次分析全书。“完整”指完成所选范围的阅读处理和必要成果保存，不要求穷尽文学解读或强制建立风格导航；显式提供导航版本时才按第 6 节核验。仅核对某条伏笔或某个人物的专项分析使用现有原文、标注、实体和关系工具，本期不为其新增任务类型或进度体系。

本期包含 AnalysisJob、任务范围内 Coverage、接续信息、成果与进度的原子提交，以及任务完成和重新打开。继续使用现有 PostgreSQL 和本地 MCP 服务。本任务模块不执行文学分析、不自动读取下一章，也不负责 AI 停止后的恢复；Spec 13 的服务后台索引独立维护检索表示。本文不扩展 Web、业务 CLI 或通用工作流引擎。

核心验收行为：本批成果或接续信息保存失败时，不推进 processed；完成进度不等于文学质量证明，没有值得新增的资产也可以完成处理。

## 2. AnalysisJob 与目标范围

一部作品允许多个分析任务，各任务拥有独立目标、进度和接续信息。Annotation、Entity、Relation、StyleGuide 仍是作品共享资产；新任务的全部目标段落从 unprocessed 开始，不继承旧任务进度，任务间不自动合并或计算“全书总完成率”。

继续上次分析时恢复原任务，保留其 Coverage 和接续信息；对同一范围重新开展一轮分析时新建任务，可以查询、核验并复用已有资产，无需重复生成标注。goal 说明本轮完整深读的目标与关注点，不改变第 6 节的完成条件，也不将任务转换为专项分析。

| 字段 | 规则 |
| --- | --- |
| id / work_id | 服务生成稳定任务 UUID；作品确定后不可更换 |
| title / goal | 简短任务名称及分析目标，均必填；允许同作品同名任务 |
| target | whole_work、part 或 ranges；part 指定 part_id，ranges 包含同作品 SourceRange |
| status | running、paused、completed；创建时 running |
| recovery | 当前接续信息，见第 4 节 |
| completion | 完成说明；未完成时为 null，见第 6 节 |
| version / 时间 | 正整数版本、创建和修改时间；创建版本为 1 |

目标以自然段为最小单位，创建后固定。whole_work 覆盖创建时作品全部正文自然段，part 覆盖指定部；追加新部不扩展旧任务、不改变旧完成记录；空 Section 不计入处理量。ranges 中每个范围仍不得跨 Section，同 Section 内重叠或相邻的目标范围合并，按作品目录和段落顺序规范化。目标不得为空。更换目标范围应新建任务，避免改变已有完成率的含义。

任务进度只覆盖目标范围，目标外段落不能被标记为已处理。接续信息和分析资产的证据可以引用同作品目标范围外的原文，用于回读、比较及跨章节关系；不因此扩展任务目标。

title 沿用 1–256 个 Unicode 码点及无首尾空白规则；goal 和各必填说明使用非空白文本，拒绝 NUL，保留原输入和换行，不设置文学字数模板。

## 3. Coverage 的粒度与状态

Coverage 的逻辑身份为 `(job_id, paragraph_id)`。未保存状态的目标段落视为 unprocessed；目标外段落不参与统计，也不应被返回为 unprocessed。内部可使用稀疏段落记录，查询将同 Section 内相邻且同状态的段落合并成 SourceRange，避免要求调用方逐段标记。

| 状态 | 含义与进入方式 |
| --- | --- |
| unprocessed | 任务内尚未声明处理的初始状态 |
| read | 调用方声明已经阅读；coverage_mark 可以将 unprocessed 改为 read |
| processed | 当前已知材料下完成本次处理；只能由 analysis_checkpoint 进入 |
| needs_revisit | 已读或已处理范围需要回看；coverage_mark 标记时须说明原因 |

读取原文不会自动改变 Coverage。read 只是调用方声明，服务无法确认模型是否理解了原文。

- 标记 read 不会把 processed 降为 read，也不会消除 needs_revisit；只推进原为 unprocessed 的段落。
- 标记 needs_revisit 的范围必须已读或已处理；包含 unprocessed 时整次请求拒绝，不部分修改。再次标记可替换回看原因。
- analysis_checkpoint 可以把目标范围中的任意现有状态变为 processed，包括重新分析 processed 范围；同时清除该范围旧的回看原因。
- 本期不提供重置为 unprocessed、物理删除进度或冻结原文的操作。processed 不限制后续修订资产。
- 范围必须完整位于任务目标内；不能静默忽略范围中的非目标段落。覆盖范围使用单个 SourceRange，一次提交不跨 Section。

任务摘要返回 target_paragraph_count 及四类状态计数，按目标段落集合去重，四类之和等于目标总数。计数只说明进度，不按标注数量计算，不作为风格质量分数。

coverage_get 可按任务、Section 和状态过滤并分页返回范围、状态及回看原因。相邻段落只有状态及原因相同才合并。返回任务版本；续页游标绑定过滤条件和任务版本，修改后继续旧页返回 VERSION_CONFLICT，调用方从新版本重新查询。默认 limit=100，最大 1000。

## 4. 接续信息

recovery 保存以下轻量内容，不复制整章正文，不保存完整推理过程、大量中间草稿或全书事实库：

| 字段 | 规则 |
| --- | --- |
| facts | 有序的重要事实入口；每项为说明和至少一个同作品 SourceRange |
| open_questions | 有序的待核对问题；每项为观察、待核对问题及至少一个同作品 SourceRange |
| next_action | 下一步具体操作，必填非空白文本 |
| next_range | 可选的同作品 SourceRange；可以指向目标外需要补读的证据，不代表进度 |

创建时 facts、open_questions 可以为空，next_action 必填。更新时完整替换 recovery，空数组明确清空旧条目。已解决、被否定或不再值得追踪的问题应从当前 open_questions 移除，需要保留的确认结果转为事实入口或分析资产；服务不自动判定问题是否解决。

“已成功保存的范围”由 Coverage 与写入回执确定，不在恢复文本中维护第二套权威进度。恢复文本中的描述不能覆盖真实写入结果。事实和未决问题分开返回，避免把待核对推测当成已确认结论。

第一版仅在接续条目中直接引用 SourceRange。已有 Annotation / Relation 可由作品和原文位置查询；暂不建立独立线索对象或可变资产引用同步机制。

## 5. 成果与进度如何保持一致

### 5.1 本批原子提交

新增 analysis_checkpoint，在一个数据库事务内保存本批资产写入、完整 recovery、目标范围的 processed 状态，以及写入回执。单独的 coverage_mark 不接受 processed，也不能通过 analysis_job_update 修改进度。

典型流程：

```text
读取任务与当前版本 → 按需阅读原文、查询已有资产
    → 准备本批资产写入、接续信息及处理范围
    → analysis_checkpoint
    → 原子提交全部结果，或全部回滚
```

checkpoint 参数包含 request_id、work_id、job_id、expected_version、source_range、writes、recovery。writes 是固定资产操作集合中的有序请求列表，复用 Spec 04–06 已有写入参数和校验，包括标签、实体、标注、关系及风格导航写入；不接受任意 MCP 工具名称、SQL 或动态插件调用。

- 每项资产写入保留独立 request_id；各子请求键互不重复，也不能等于 checkpoint 的外层请求键。
- 除跨作品共享的 Tag 外，所有资产目标必须属于任务作品。资产证据可以超出当前处理范围，但不能跨作品。
- 批内只引用调用前已知的稳定 ID；不引入临时 ID、占位符或批内变量引用。需要新标签或实体 ID 时，先用现有工具创建，再在 checkpoint 中引用；这些预先提交的资产不会随 checkpoint 失败撤销。
- 单独的资产工具继续可用且不自动推进进度。先前单独调用中结果不明的写入，可以将原键、原输入放入 writes，事务内按已有规则恢复快照；不同输入仍返回 REQUEST_CONFLICT。
- 已提交的子请求只恢复历史结果，新子请求才执行写入；后续任一校验失败，回滚本次新写入、进度、接续信息和外层回执，保留此前已提交的历史资产。
- 存在版本冲突、非法引用、数据库故障或结果超限时，整个 checkpoint 失败。不能先提交若干新资产，再单独提交进度。
- writes=[] 时必须提供非空白 outcome_note，说明本批无需新增或修订资产的结论；允许“没有值得保存的标注”或“核对后沿用已有成果”，不能要求伪造标注。

此事务保证提交的本批操作全部成功，不证明调用方列出了所有应有文学成果。调用方必须把本批尚需保存的操作纳入 writes；不能遗漏失败操作后宣称已处理。服务不能推断未提交的文学意图。

### 5.2 重试与恢复

复用 asset_write_get 和共享资产请求键空间，新增任务操作对应的回执类型。旧资产请求指纹、快照格式、单独写工具及旧客户端行为保持不变，不重新解释历史请求。

外层指纹包含目标、任务版本、处理范围、有序子请求及其输入、recovery 和 outcome_note。同键同输入恢复原回执，不再次执行子操作或推进版本；同键不同输入返回 REQUEST_CONFLICT。重复请求识别先于当前任务版本检查。

checkpoint 回执包含提交时的任务版本、处理范围和各子请求的 operation、request_id；不打包复制所有资产正文或说明。完整子请求快照仍可用 asset_write_get 查询。当前任务与当前资产分别通过各自 get 工具读取。

进程重启后的恢复顺序：查询已知外层请求键 → 获取当前任务和 Coverage → 阅读 recovery → 按需读取原文或资产 → 决定继续或修订。WRITE_NOT_COMMITTED 仅表示查询时无提交结果，不证明并发请求不会稍后提交；仍以原键原输入重试，不盲目换键。

## 6. 任务状态、并发与完成

analysis_job_update 允许 running 与 paused 切换及完整更新 recovery；paused 不表示正在执行的 AI 进程被终止，只限制该任务的新 checkpoint 和 coverage_mark。恢复为 running 后才能继续推进。

analysis_job_complete 只接受 running 任务，并在同一事务中核验：目标所有段落均为 processed；任务没有 needs_revisit。style_guide_version 可省略；显式提供时，核验同作品 StyleGuide 已存在且版本一致。调用方还须提交 calibration_note、limitations 和最终 recovery，说明处理结果与判断限制。limitations 可为 null，其他说明非空白。Spec 13 的准备任务不强制风格导航，prepare_finish 另外检查原文与标记索引同步；旧的独立完成入口只代表阅读处理完成。

open_questions 可以保留原文尚不能解释的问题，不要求全部清空或强行转成 Relation。服务核验进度和导航版本，不能自动判断校准是否充分、导航范围文字是否真实或文学效果是否达标。样本任务完成只代表目标样本完成。

completed 任务拒绝 checkpoint、coverage_mark 和普通内容更新；analysis_job_update 可显式重新打开为 running，须提供 reopen_reason 和完整 recovery，清除当前 completion 并保留既有 Coverage，再按实际需要标记回看范围。旧完成请求快照继续可恢复。

所有任务写入要求 request_id，修改要求 expected_version；成功的新请求使任务版本加一，即使内容相同，同键重放不加版本。锁定任务主记录后校验版本，使进度、接续信息、暂停和完成共享同一次竞争。完成与新标记回看并发时不能同时按旧版本成功。资产写入仍检查各资产自己的 expected_version。

完成记录中的 style_guide_version 是完成当时的依据，不保证导航以后不变。其他任务或独立工具修订共享资产，不自动修改本任务进度。继续原任务的回看或校准时，显式重新打开并保留其进度；重新开展一轮独立分析时新建任务，进度从零开始。读取多表详情和摘要使用一致快照，不能混合不同任务版本。

## 7. MCP 与实施边界

| 工具 | 职责 |
| --- | --- |
| analysis_job_create | 创建作品内任务、固定目标和初始接续信息 |
| analysis_job_get | 读取任务、当前接续信息、目标、版本、进度计数及完成说明 |
| analysis_job_list | 按作品及可选状态分页返回任务摘要，不返回完整接续文本 |
| analysis_job_update | 更新接续信息、暂停或恢复，以及显式重新打开 |
| coverage_get | 按任务分页查询合并后的进度范围 |
| coverage_mark | 显式标记 read 或 needs_revisit，不接受 processed |
| analysis_checkpoint | 原子保存本批资产、接续信息和 processed 进度 |
| analysis_job_complete | 核验目标进度与导航版本后保存完成说明 |

所有任务查询都明确指定 work_id，其他作品的 job_id 按不存在处理。缺少资源、越出目标、非法状态转换、版本冲突、请求键冲突和响应超限应有可区分的错误；具体参数和错误码见第 10 节，不透出正文、请求体、SQL 或凭据。

复用现有 AssetService 写入校验，将资产事务执行与单次接口封装分开，使 checkpoint 复用同一连接；不能通过循环调用现有 MCP 工具模拟事务。外层和子请求占键、资产锁与任务锁应有一致的获取顺序，验证并发竞争不会留下部分写入；不是新增通用执行引擎。

持久化需要任务主记录、固定目标范围及稀疏段落进度；recovery 和 completion 可作为任务的结构化内容保存，引用在事务内校验，不为事实和问题建立独立资产系统。复用现有写入请求表记录幂等结果。物理结构及约束见第 10 节，不能用 JSON 文本取代必要外键和版本约束。

沿用单个完整业务响应 1 MiB 上限。任务创建和修改在提交前保证完整任务可读取；每个资产子结果及 checkpoint 回执分别满足已有响应上限。查询分页超限时明确报错，不能静默截断恢复信息。分页和大目标范围的响应投影见第 10 节，整本进度通过分页查询。

当前采用 Spec 12 的 0011 空库结构，不转换旧数据。迁移及范围快照行为先在独立测试库验证；共享库升级按明确目标和授权执行，数据库迁移不修改 AI 客户端配置。

## 8. 验收场景

1. 同作品两个任务使用相同或不同目标时进度均独立；新任务全部从 unprocessed 开始，恢复原任务保留进度，复用已有资产不自动复制进度。越出目标、跨作品及跨章节非法范围均拒绝。重叠目标去重，空 Section 不计数。
2. 阅读接口无进度副作用；read 不覆盖 processed 或 needs_revisit；仅 checkpoint 能推进 processed。状态计数正确，混合状态范围不会部分失败部分成功。
3. 一个 checkpoint 写入多项成果及 recovery 后，处理范围与所有新写入同时可见。末项失败、版本冲突、结果超限或提交失败时，旧任务、旧进度和旧接续信息保留，没有新增部分成果或成功回执。
4. checkpoint 部分子请求在此前独立提交时，复用原键恢复其结果；新子请求失败不删除旧成果；同键异输入拒绝，跨作品资产拒绝。
5. writes=[] 配合明确 outcome_note 可以完成没有新增资产的范围，无需虚构 Annotation；缺少说明不能提交。
6. 同键并发及重启后重试不重复写入，不重复推进任务版本；不同键同版本竞争仅一次成功。checkpoint 与暂停、完成、回看标记的竞争均符合状态及版本约束。
7. 新会话可通过任务列表、当前接续信息、Coverage 和请求回执恢复；事实与待核对问题分开，目标外的同作品补读证据可用。分页期间任务版本变化要求重新查询。
8. 目标有遗漏或 needs_revisit 时不能完成；导航不存在或版本不符时不能完成；未决问题允许保留，但必须记录校准结论和限制。样本完成不宣称全书完成。
9. completed 任务须显式重新打开后才能推进；重新打开保留历史回执及当前 Coverage。后续资产修订不静默改写旧完成依据。
10. 真实 PostgreSQL 上验证迁移、约束、事务及并发；官方 MCP 客户端和真实服务重启验证协议、恢复与日志边界；回归现有独立资产工具、旧请求指纹、快照和原文保真。

## 9. 已确认决策与当前交付状态

2026-09-20 确认以下范围和设计：

1. **第一版聚焦指定范围的完整深读**，支持全书或样本范围，不为专项核对新增任务类型。
2. **进度按分析任务隔离，作品资产共享**；继续分析恢复原任务，独立重分析新建任务，不提供自动继承或作品级进度合并。
3. **通过原子 checkpoint 提交本批成果、接续信息与 processed 进度**。实现需要复用现有资产校验和事务执行逻辑，增加一个批次提交入口。
4. **任务完成要求目标全部 processed 且已有对应范围的导航校准声明**；允许仍有无法确认的问题，不将完成等同于文学质量达标。

任务、进度、原子 checkpoint、八个 MCP 工具及迁移 0005 已实现，必要验证与既有功能回归已通过。迁移已在独立测试库验证；共享开发库随后经单独授权升级至 0005，结构和只读 MCP 验证通过。


## 10. 参数、持久化与错误契约

所有写入保留 `request_id`；除创建外，任务修改传 `work_id、job_id、expected_version`。每个工具拒绝未知字段，版本和分页参数使用严格整数。title 沿用 Alias 约束，goal、next_action、说明与回看原因沿用 Nonblank 约束。

| 工具 | 其他参数 | 结果 |
| --- | --- | --- |
| analysis_job_create | work_id、title、goal、target、recovery | 包含完整任务的写入快照 |
| analysis_job_get | work_id、job_id | 当前完整任务 |
| analysis_job_list | work_id；可选 status、limit、cursor | 任务摘要页 |
| analysis_job_update | status、recovery；重开时提供 reopen_reason | 包含完整任务的写入快照 |
| coverage_get | work_id、job_id；可选 section_id、status、limit、cursor | work_id、job_id、version、items、next_cursor |
| coverage_mark | source_range、status；needs_revisit 必填 reason | 包含完整任务的写入快照 |
| analysis_checkpoint | source_range、writes、recovery；无写入时必填 outcome_note | 精简批次回执 |
| analysis_job_complete | recovery、style_guide_version、calibration_note、limitations | 包含完整任务的写入快照 |

`target={kind: "whole_work"}` 不接受非空 source_ranges，详情也不展开全书范围；`target={kind: "ranges", source_ranges: [...]}` 返回按原文顺序合并后的目标。任务详情中的 counts 固定包含 unprocessed、read、processed、needs_revisit 四项。任务摘要包含 id、work_id、title、status、version、时间、target_paragraph_count、counts，以及最多 200 个 Unicode 码点的 goal_preview 和 goal_truncated；不返回完整 recovery 或目标范围。

recovery 的 facts 条目为 `{note, source_ranges}`，open_questions 条目为 `{observation, question, source_ranges}`，每项证据至少一处；next_action 必填，next_range 可省略或为 null。完整替换时，缺省 facts、open_questions 视为空数组，缺省 next_range 视为 null。read 不接受 reason；非完成任务不接受 reopen_reason。limitations 必须显式提交，允许 null。

writes 使用 operation 判别的固定结构 `{operation, input}`，支持 tag_create、tag_update、annotation_create、annotation_update、annotation_set_status、entity_create、entity_update、relation_create、relation_update、relation_set_status、style_guide_create、style_guide_update。input 直接使用原工具参数模型；尤其 annotation_update 省略 entity_ids 保留关联，显式 [] 清空关联，批次指纹和子写入都保留此区别。标签修改和标注状态操作由 Spec 04 的 0009 纠错增量扩展，同样参与版本校验和整批回滚；服务不根据撤回结果自动改动其他范围的 Coverage。

checkpoint 的 result 包含 work_id、job_id、version、source_range、writes、outcome_note，writes 仅包含 operation 和 request_id。其他新写入 result 为 AnalysisJob 当前提交快照。完整任务读取、资产子结果和外层回执分别检查 1 MiB 容量，超限回滚新写入；MCP 分页查询结果超限返回 RESULT_TOO_LARGE。

coverage_get 按目录、段落顺序排列，只在章节、状态、原因均相同且段落相邻时合并。游标绑定 work_id、job_id、section_id、status 以及任务版本，limit 不参与范围绑定。查询使用一致快照；版本变化返回 VERSION_CONFLICT，过滤条件不匹配或游标格式错误返回 INVALID_CURSOR。

| 错误码 | 含义 |
| --- | --- |
| JOB_NOT_FOUND | 指定作品中没有该任务 |
| INVALID_TARGET | 目标没有任何正文段落 |
| RANGE_OUTSIDE_TARGET | 进度范围包含任务目标外的段落 |
| INVALID_COVERAGE_TRANSITION | 标记回看的范围仍含 unprocessed |
| JOB_STATE_CONFLICT | 暂停或完成状态不允许当前操作，或重开参数不符合状态 |
| JOB_INCOMPLETE | 完成时仍有未处理、仅读或待回看段落 |
| VERSION_CONFLICT | 任务、资产、导航版本不符，或续页时任务已变化 |
| REQUEST_CONFLICT | 同一请求键的操作或输入不同 |
| ASSET_TOO_LARGE | 新写入的完整任务、资产结果或批次回执超过容量 |

沿用 INVALID_INPUT、INVALID_RANGE、INVALID_CURSOR、STYLE_GUIDE_NOT_FOUND、WRITE_NOT_COMMITTED 及现有资源和数据库错误。错误不返回请求体、SQL、原文或接续内容；VERSION_CONFLICT 可提供 current_version。

迁移 0005 新增三张表：analysis_jobs 保存作品归属、名称、目标类型、状态、recovery / completion JSONB、版本和时间；analysis_targets 保存固定的去重范围、稳定端点及原文序号；analysis_coverage 以 `(job_id, paragraph_id)` 为主键保存非默认状态和回看原因。外键保证引用存在，检查约束保护版本、状态、完成说明与回看原因，目标表的唯一约束防止同任务重复范围起点。引用归属、范围包含及规范化由事务内业务校验完成。共享 asset_write_requests 保存幂等快照，既有表及请求数据不迁移改写。

checkpoint 与独立写工具采用相同锁次序：先按固定哈希顺序取得全部请求键的事务 advisory lock，再取得全部修改资源的事务 advisory lock，随后占键和执行业务。checkpoint 预先包含全部子请求和资源，子写入复用同一连接；任务及资产仍保留版本条件和行锁。对不修改主键的资源使用 NO KEY UPDATE，使外键检查与跨批次实体引用兼容；风格导航完成校验与导航修改使用相同资源锁。锁在事务结束时释放，不新增后台进程或分布式协调服务。
