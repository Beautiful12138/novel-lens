# Spec 12：作品分部与追加导入

状态：已实现并完成隔离验证，2026-09-24 经授权清空旧业务数据后部署至共享开发库。当前确认的结构为 Work → Part → Section → Paragraph，不建立内部卷、系列或世界观对象。本规格修订 Spec 02–03 的单文件作品导入、Spec 07 的目标范围、Spec 09–10 的作品检索及 Spec 11 的清理范围；未涉及的原文保真、资产归属、幂等、版本和事务要求继续有效。

## 1. 范围与取舍

- 同一主线故事的前后几部属于一个 Work；人物、标注、关系和风格导航归作品，可用多个 SourceRange 引用不同部。单个 SourceRange 仍限定一个章节，段落 ID 不因追加或改名改变。
- 分部名称可以是独立书名、上篇/下篇等，不要求出现“第一部、第二部”，程序不解析名称推断顺序。Part 保存名称、不可变的追加顺序、版本、原文摘要及统计。章节同时归属作品和分部，保留作品内连续追加的 ordinal；标题可重复。第一版仅修改作品和分部名称，不移动、排序、替换或向已有部补写正文。
- 不分部小说导入一个名为“正文”的默认部。内部卷由 AI 在独立准备的 Canonical TXT 中去掉分组标记，不拼到章名；卷首序言、引文及正文必须以章节容器保留。不得修改源素材文件、正文、标点、自然段或顺序，程序不猜结构或删除文本。
- 每次导入一个完整分部，上传字节独立永久保存。文件首条非空行为 `分部：名称`，后续沿用 `标题：章节名` 和逐行自然段。作品名称由独立创建接口指定，上传文件不得隐式创建、改名或合并作品。
- 开发阶段不兼容旧导入接口、不迁移旧原文或分析。0011 仅允许空业务库升级，遇到作品或资产数据明确拒绝，不自动清空。使用新的空数据库，或另外授权清理后重新导入分析。

## 2. 接口与原子性

- HTTP/MCP 提供 work_create、work_update、part_import_validate、part_import、part_import_get、part_list、part_get、part_update；HTTP 下载原始文件改为作品下指定分部。移除 work_import 系列及作品单文件下载入口。
- 创建、改名和导入均需 request_id；改名需 expected_version。同键同输入返回提交时快照，同键异输入冲突；另设目录写入回执，与资产回执职责分开，作品删除时一起清理。
- 创建空作品合法；名称全局精确唯一，分部名称在作品内精确唯一。导入指纹绑定作品与上传字节，预检检查格式、作品存在及部名冲突，正式提交重复校验。
- 导入事务串行锁定作品，保存分部、完整文件、章节、段落、聚合统计及回执，失败全部回滚。竞争的不同部依提交顺序追加；同键仅一次成功。与作品删除互斥；语义索引创建/构建期间拒绝追加，避免模型跨事务处理时来源改变。
- 作品 source_sha256 改为按部顺序的原文摘要清单哈希，source_bytes 为总字节数；单文件摘要只在 Part 上。改名不改变原文或清单哈希。

## 3. 读取、检索和分析范围

- 目录可按 part_id 筛选，游标绑定作品与筛选范围。原文来源由 Section → Part → 上传文件确定，目录与搜索返回部名与章名以便定位；已有 SourceRange 无需增加冗余 part_id。
- 原文关键词、标注说明关键词及两层语义搜索默认覆盖作品，支持可选 part_id。标注说明按引用是否落在该部筛选，返回该部的首个引用及其名称；返回的总引用数量仍表示标注全部引用。跨作品的部 ID 按不存在拒绝。
- 分析目标支持 whole_work、part、ranges。whole_work 固定创建时已有段落；part 固定指定部的段落，ranges 保持既有行为。追加不改变旧目标、Coverage 或完成记录，新任务独立从零开始。
- 追加后已有语义代来源清单不匹配，不继续当作完整索引搜索或构建；状态明确报告来源过期，需显式创建新代。关键词与按坐标阅读立即可用，已有分析资产不自动撤回。
