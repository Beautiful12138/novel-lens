# 02 小说导入与原文读取

状态：已实现；2026-09-18 完成 Windows、真实 PostgreSQL 18.6 与真实 HTTP 进程验证。环境和执行方式见 [README](../README.md#验证)。MCP 适配不在本规格实现范围。

依据：[需求与设计基线](../docs/小说分析与创作知识服务_需求与设计基线.md)第 4–6、11、15–16、22.9 章及 [Spec 01](01-工程基础与运行约定.md)。

## 1. 目标与范围

AI 通过接口上传一份结构已确认的 Canonical TXT，服务将收到的字节作为系统原文，原子保存作品、目录与自然段，并提供稳定坐标读取。本期不接收整理前的第二份文件，不判断上传前是否发生改写。保真边界为上传后的解析、存储、读取与下载。

本期包含预检、导入、请求结果查询、作品与目录查询、段落分页、范围读取、上下文补读和文件下载。先实现共享业务规则及 HTTP 接口；客户端接入阶段先做 MCP，CLI 延后。不包含 Web 导入、结构猜测、AI 分析、标注、检索、向量和分析进度。

## 2. 输入契约

- 本规格的 REST 上传接口使用 multipart 上传 `file`；正式导入还须提交调用方生成的 UUID `request_id`。
- REST 上传接口不接受服务器路径、URL、第二份文件或 `confirmed` 等替代内容校验的开关。未知字段、重复字段及错误字段类型均拒绝。[Spec 03](03-本地MCP原文能力接入.md)另行定义同一应用内的本地 HTTP MCP 工具：按调用方路径读取任意目录中有权限访问的普通文件，复用本规格的字节导入规则，不改变既有 REST 上传契约。
- UTF-8 编码，可含文件头 BOM；保留所有上传字节。只将 CRLF、CR、LF 识别为换行，不将其他 Unicode 分隔符拆段；拒绝 NUL。
- 只含半角空格、制表符或全角空格的行是格式空行，不建立 Paragraph；文件下载仍保留这些字节。
- 首个非空行为 `书名：作品名称`。名称为 1–256 个 Unicode 码点，不允许首尾格式空白；一个文件只能出现一次书名字段。
- 至少一个 `标题：标题文本`，标题不为空且不含首尾格式空白。标题可重复；空 Section 保留，但整部作品须有正文。
- 每条其他非空物理行代表调用方已确认的一个自然段。正文前必须有标题；不自动合并硬换行，不裁剪正文空白，不做 Unicode 归一化。
- 行首 `书名：`、`标题：` 是保留标记，调用方须确认它们的结构用途；服务不能从格式有效推断文学结构或上游整理正确。
- 文件默认上限 64 MiB，整个 HTTP 请求默认上限 65 MiB，分别由 `NOVEL_LENS_MAX_FILE_BYTES`、`NOVEL_LENS_MAX_REQUEST_BYTES` 配置。接收时累计字节，不信任 Content-Length；临时文件随请求关闭。
- 单文件最多 200000 个非空行，作为解析对象数量的技术边界，超限拒绝。名称和字节上限不等于自然段数限制。

示例：

```text
书名：测试作品

标题：序章
　　第一自然段。
第二自然段。

标题：第一章
另一自然段。
```

## 3. 预检与保真

返回 `status`（`valid` / `invalid`）、`source_sha256`、`rule_version`、`issue_count`、`issues`、`next_cursor`。本版遇到首个可靠定位的问题即停止；issue_count 是此次报告的问题数，next_cursor 固定为空，不声称找出了全部问题。

每项问题包含 code、message、可选 source_position。位置使用上传文件中的零起始、左闭右开字节区间及一起始行号；BOM 与不同换行宽度计入偏移。错误不回显正文。每段正文的 text 必须等于对应字节区间按 UTF-8 解码的结果。下载文件必须与上传逐字节相同，SHA-256 可复核。

预检检查格式和当前作品名称占用；名称预检不是预留，正式导入仍须依靠数据库唯一约束。格式无效的预检返回 HTTP 200 和 invalid；正式导入返回 422 `IMPORT_VALIDATION_ERROR`，details 为同一报告。

## 4. 存储与可靠写入

采用 PostgreSQL 18、SQLAlchemy Core、psycopg 与 Alembic。开发数据库在远程 Linux 服务器独立部署，本机通过公网端口 10002 直连；网络连接使用 SCRAM 密码认证，关闭 TLS，客户端使用 `sslmode=disable`；凭据不提交 Git。开发电脑不要求本地 Docker，具体部署与连接步骤见 README。启动与模块导入不连接数据库，不自动执行迁移；迁移通过显式命令执行。`/health` 仅检查进程存活。

| 表 | 职责 |
| --- | --- |
| works | UUID、名称、已提交请求键、请求指纹、时间、结构计数及文件摘要 |
| work_sources | 上传文件 bytea、解析规则版本和标题位置依据 |
| sections | 固定 UUID、作品归属、一起始 ordinal、标题和段落数 |
| paragraphs | 固定 UUID、Section 归属、一起始 ordinal、完整正文和字节位置 |

作品名称按数据库 C 排序规则精确唯一；不做大小写或 Unicode 归一化。同名输入不得覆盖，另一个版本需使用不同名称。Section / Paragraph 的归属由外键、归属内序号由唯一约束保证。原文当前无修改、删除接口。

完整文件和所有结构在一个事务内保存，提交后才返回 completed。中途失败不得留下部分作品或文件。请求指纹为协议版本与文件 SHA-256 的组合摘要，文件名不影响指纹。

- 相同 request_id、相同输入：返回原作品和固定坐标，replayed=true，不重复导入。
- 相同 request_id、不同输入：409 `REQUEST_CONFLICT`。
- 不同 request_id、相同名称：409 `WORK_NAME_CONFLICT`。
- 并发请求依靠数据库唯一约束裁决；唯一冲突回滚后查询已提交结果，再判断重放或冲突。其他数据库故障不得伪装成重名。
- 返回丢失时可查询请求结果或以原 request_id 重试。未发现已提交请求返回 404 `IMPORT_NOT_COMMITTED`，details.status=not_committed；这不能证明另一个并发请求不会稍后提交。

## 5. 读取与定位

元数据、目录、正文和完整文件分开查询。character_count 是所有正文的 Unicode 码点数，包含正文空白，不含标题、书名和换行；不是汉字数。

作品列表按 created_at、id 排序；目录和段落按 ordinal 排序。分页默认 100、上限 1000，返回 items、next_cursor。游标限定查询类型、作品及 Section 或范围，不能用于另一个范围；游标不是鉴权凭据。服务本期用于本地可信调用，无多用户权限体系。

SourceRange 显式包含 work_id、section_id、start_paragraph_id、end_paragraph_id。范围两端包含在内，须同属指定作品和 Section，起点不能晚于终点。范围读取分页返回 requested_range 和本页 actual_range，始终返回完整自然段，不按字符截断。

上下文读取以单段为锚，before / after 各为 0–100，最多返回 201 段，不跨 Section；返回 actual_range、at_section_start、at_section_end。空 Section 的段落列表为空，无虚构锚点。

## 6. HTTP 接口

| 方法与路径 | 输入 / 输出 |
| --- | --- |
| POST /work-imports/validate | multipart file → 校验报告 |
| POST /work-imports | multipart file、request_id → request_id、status、replayed、work；首次 201，重放 200 |
| GET /work-imports/{request_id} | 已提交导入结果 |
| GET /works | limit、cursor → 作品页 |
| GET /works/{work_id} | 作品元数据 |
| GET /works/{work_id}/sections | limit、cursor → 目录页 |
| GET /works/{work_id}/sections/{section_id}/paragraphs | limit、cursor → 段落页 |
| POST /works/{work_id}/source/read | JSON source_range、limit、cursor → 范围页 |
| POST /works/{work_id}/source/context | JSON section_id、paragraph_id、before、after → 上下文 |
| GET /works/{work_id}/file | 上传原始字节 |

错误统一为 code、message、details。输入错误 422；体积超限 413；坐标或资源不存在 404；业务唯一性冲突 409；数据库不可连接 503。其他数据库错误返回不含 SQL、凭据或正文的 500，不记录完整请求、SQL 参数或输入验证值。

## 7. 验收

1. 单文件可预检、原子导入、查询目录、按稳定坐标读段和下载；BOM、多种换行、中文、正文首尾空白均保真。
2. 无效编码、NUL、缺少结构、空正文、额外字段和大小超限不能创建作品；报告位置可定位原字节。
3. 空 Section、重名标题、段落顺序、正文计数和游标翻页符合契约；跨作品或跨 Section 坐标不能混读。
4. 相同键重放返回相同 UUID；同键异内容、异键同名返回相应冲突；真实 PostgreSQL 并发验证两类唯一性。
5. 真实 PostgreSQL 中注入写入中途失败，完整文件、作品与结构均回滚；提交结果未接收时仍可查询和重放。
6. 独立空测试数据库执行 Alembic 迁移；真实 HTTP 进程完成上传、读取、下载与重启后读取，数据库不可用时健康接口仍可响应。
7. 无 Content-Length 的流式请求仍受总字节上限约束；失败响应与日志不泄露凭据、正文或 SQL。

测试使用独立小样例与隔离数据库，不修改 data/ 中小说，不清空开发数据。交付记录实际执行的验证和未覆盖边界。
