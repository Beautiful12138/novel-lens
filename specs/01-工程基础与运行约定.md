# 01 工程基础与运行约定

状态：已实现；2026-09-18 完成 Windows 与 WSL Linux 验证。环境和结果见 [README](../README.md#验证)。

依据：[需求与设计基线](../docs/小说分析与创作知识服务_需求与设计基线.md)第 23、31、32、35 章，以及根目录 [AGENTS.md](../AGENTS.md)。本文定义 NovelLens 首个工程增量，技术选择限于本规格范围。

## 1. 目标与范围

建立可安装、可启动、可验证的 Python HTTP 服务基础，使后续小说导入和原文读取具有明确的运行入口与配置方式。

本次实现包括依赖管理、Python 包、配置校验、日志、存活检查和开发说明。不包含小说导入、数据库、业务接口、MCP、业务 CLI、Web 前端、模型下载或推理；这些能力按各自 Spec 引入。进程启动不读取小说、不连接数据库或模型服务，不依赖 GPU。

## 2. 实施选型

| 用途 | 本规格采用 | 依据 |
| --- | --- | --- |
| 后端运行时 | Python 3.12 | 作为首个可复现的开发与验证版本，其他版本不自动视为已验证 |
| 项目与依赖管理 | uv、pyproject.toml、uv.lock | 使用项目虚拟环境并锁定依赖 |
| HTTP 服务 | FastAPI、Uvicorn | 提供后续业务 HTTP 入口与当前存活检查 |
| 类型与配置校验 | Pydantic、pydantic-settings | 明确配置类型、来源和启动失败行为 |
| 日志 | Python 标准库 logging | 当前仅需控制台日志与日志级别 |
| 开发验证 | pytest、Ruff、mypy | 验证项目行为、代码规范与核心类型，不设覆盖率配额 |

安装包名为 `novel-lens`，导入包名为 `novel_lens`。实现时在 `.python-version` 声明运行版本，在 `pyproject.toml` 声明适用的 Python 范围、构建后端和直接依赖，由 uv 生成锁文件；README 记录实际验证的 Python 与 uv 版本。依赖版本以完成兼容验证的锁文件为准，不在本文编造版本号。

不引入尚无调用方的数据库驱动、任务队列、模型工具库或框架全量可选依赖。验证工具作为开发依赖，与服务运行依赖区分。

## 3. 文件组织

```text
AGENTS.md                 长期开发规则
```

包内只建立启动、应用和配置等实际需要的模块，不预建空的分层目录。项目包应通过声明的构建后端安装，不依赖手动修改 `PYTHONPATH`。开发环境使用项目内 `.venv`；安装和运行不修改全局 Python 环境或覆盖小说素材。

## 4. 配置与启动

从项目根目录执行命令，配置优先级为：进程环境变量高于根目录 `.env`，`.env` 高于内置默认值。`.env` 不存在时仍可启动；存在时按 UTF-8 读取。不向上级目录搜索其他 `.env`。

| 配置键 | 默认值 | 校验与用途 |
| --- | --- | --- |
| `NOVEL_LENS_HOST` | `127.0.0.1` | 回环 IP 或 localhost；非回环配置、解析或绑定失败时明确报错退出 |
| `NOVEL_LENS_PORT` | `8000` | 1–65535 的整数 |
| `NOVEL_LENS_LOG_LEVEL` | `INFO` | 接受 DEBUG、INFO、WARNING、ERROR、CRITICAL，不区分大小写 |

上述为基础运行配置；Spec 02 增加数据库连接和上传容量配置，完整列表见[部署指南](../docs/部署指南.md)。未声明的进程环境变量不参与项目配置；`.env` 仅用于项目配置，未知键（包括拼错的 `NOVEL_LENS_` 配置项）应报错，避免人工输入错误被静默忽略。不打印完整配置、环境变量或原始校验输入值；错误应指出配置键及违反的规则。

[Spec 03](03-本地MCP原文能力接入.md)将本地 HTTP MCP 纳入同一应用、端口与生命周期，并将 HOST 限定为回环 IP 或 localhost。该接入及绑定校验已实现，沿用本规格的统一启动命令；文件路径规则和验证范围见 Spec 03 与 README。

配置校验在监听 HTTP 端口前完成。非法端口、非法日志级别等配置错误导致非零退出，不悄悄回退到默认值；端口占用等启动错误也必须可见并非零退出。

提供以下统一命令，Windows PowerShell 与 Linux 从项目根目录使用相同入口：

```text
uv sync --locked
uv run --locked python -m novel_lens
```

`--locked` 要求锁文件与项目声明一致，发现不一致时失败，不在安装或启动过程中自动改写锁文件。依赖调整时显式重新生成锁文件并验证。正常启动使用单进程，不默认启用热重载；Ctrl+C 可停止服务并释放监听端口。

## 5. HTTP 与日志行为

### 新用户部署入口

README 面向独立部署者，默认路径为本机 Python 应用与本机 Docker PostgreSQL / PGroonga，另提供用户已有数据库路径。公开部署不得依赖维护者的服务器、私有归档、历史会话或本机说明。数据库要求仍由 Spec 02 / 09 定义。

`scripts/init_local.py` 仅为首次安装生成匹配的 `.env` 和 `data/postgres/password`，使用随机密码，不打印凭据、不覆盖已有文件；写入失败清理本次创建的文件。重复执行应明确拒绝且原配置不变。该脚本不执行数据库迁移、下载模型或探测 embedding 硬件参数。

默认 Compose 从公开基础镜像及仓库 Dockerfile 构建，数据库只发布回环端口，数据存于项目命名卷。部署文档须说明初始化、迁移、验证、停止、数据位置及旧部署兼容边界；新工作区和空数据库的实际验证不能以已有开发库的历史结果替代。

### 运行时行为

- `GET /health` 返回 HTTP 200，JSON 为 `{"status":"ok"}`。该接口只表示当前 HTTP 进程能响应，不表示数据库、模型或业务功能已就绪；后续依赖就绪检查另行定义。
- 应用创建不绑定端口，不启动后台线程，不在模块导入时执行网络请求或读取小说。实际配置读取和日志初始化由启动入口执行，应用可以在测试中独立创建。
- 应用日志及 Uvicorn 日志统一写入 stderr，至少包含时间、级别和消息；本阶段不创建日志文件，不建立日志平台。
- 启动日志包含服务绑定地址；错误日志提供定位原因，不输出密钥、完整请求体、正文或完整环境变量。默认关闭访问日志，避免查询参数进入日志。
- 存活检查之外不提供返回假业务数据的接口，不以空函数或 TODO 声称业务能力已经实现。

## 6. 验收条件

| 编号 | 可观察结果 | 验证方式 |
| --- | --- | --- |
| A1 | 在具备指定 Python 与 uv 的干净项目环境中，按锁文件安装成功；锁文件与项目声明不匹配时明确失败 | 实际安装与锁文件检查，保留命令结果 |
| A2 | 不提供 `.env`、数据库或模型服务时可启动；真实 HTTP 请求取得约定的存活响应 | 启动进程并发送 HTTP 请求，不只调用应用函数 |
| A3 | `.env` 能覆盖默认值，进程环境变量能覆盖 `.env`；UTF-8 文件正常读取 | 在独立临时目录验证项目配置加载，不使用真实素材 |
| A4 | 非法配置和未知的 `.env` 项按第 4 节失败；启动报错不回显原始输入值 | 有针对性的配置测试；至少一次真实进程配置错误验证 |
| A5 | 启动日志写入 stderr，端口被占用时非零退出，停止后端口可重新使用 | 实际进程验证，不重复测试 Uvicorn 内部实现 |
| A6 | Python 包能够通过规定命令导入和运行；有价值的测试、Ruff 检查与格式检查、mypy 检查通过 | 运行对应检查并记录结果，不编写源码字符串断言 |
| A7 | README 与 `.env.example` 对应实际实现，记录已验证的平台及工具版本；未运行的平台检查明确标记 | 核对说明与执行证据；Windows 和 Linux 分别验证启动、存活与停止行为 |

本阶段的自动化测试重点是项目自行定义的配置优先级、校验与敏感输入隐藏行为。简单存活接口和进程运行通过真实命令验证，不为框架自带路由、类型校验机制编写重复测试。不修改全局工具配置；验证所需缓存可通过进程级配置定向至项目忽略目录。
