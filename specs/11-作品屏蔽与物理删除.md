# 11 作品屏蔽与物理删除

当前分部增量见 [Spec 12](12-作品分部与追加导入.md)：原文归分部，资产归作品；目录及搜索支持分部范围，任务固定创建时目标，来源追加使语义代过期。目录写入回执、全部分部及原文件随作品删除。旧数据与接口不再兼容；下方历史验证记录保留当时语义。


状态：已实现并在隔离数据库验证，当前分部模型使用 0011 空库结构，验证记录按当时版本保留。依据需求基线第 5 章；本规格扩展 Spec 02 的作品管理能力，供后续 WebUI 调用。

## 范围与行为

- HTTP 提供作品屏蔽、恢复显示和物理删除；屏蔽和物理删除不新增 MCP 写入工具或 WebUI，目录创建改名由 Spec 12 定义。
- `works.visibility` 为 `visible|hidden`，既有作品默认 visible。屏蔽保留原文、分析资产、进度、索引及名称占用。
- HTTP `GET /works?visibility=visible|hidden|all` 默认 visible；MCP work_list 同样默认排除 hidden。分页游标绑定筛选条件；升级前取得的作品列表游标需从首页重新获取。作品详情返回 visibility。
- 屏蔽作品不参与原文关键词、写法说明关键词、两层语义检索，显式按旧 ID 搜索返回 409 `WORK_HIDDEN`，不能用 full 格式或部分索引绕过。按 ID 直接读取、下载、分析资产维护仍可用，便于复核；屏蔽是检索开关，不是权限控制。已开始的查询可能返回屏蔽前快照。
- `PATCH /works/{work_id}/visibility`，JSON `{"visibility":"hidden"}` 或 visible，返回更新后的作品元数据。重复设置同值幂等；并发设置按数据库锁顺序串行，最后提交状态生效。
- `DELETE /works/{work_id}` 无请求体，成功返回 204。物理删除作品、上传字节、目录、自然段、全部作品内资产及关联、任务与进度、所有语义索引代及回执、包含该 work_id 的资产写入回执。全库共享标签及其独立回执保留，不删除磁盘文件或外部备份。不是软删除，不设置回收站。
- 删除与重复删除均返回 204；未知合法 UUID 也返回 204，不声称曾存在。无额外删除回执残留。删除后旧导入请求结果不存在；同名同文件可重新导入，使用新请求键并获得新作品及坐标 ID。
- 删除在一个事务内完成，失败整体回滚。资产写入在作品行上持共享锁，删除持排他锁，避免写入与清理交错。删除与两层语义构建共用既有互斥键；任一层正在创建或构建时返回 409 `WORK_BUSY`，稍后重试，不终止推理进程。其他作品和共享标签仍可使用。
- 迁移 0010 只增加 visibility 字段和枚举约束；不自动迁移共享库，不自动重启已运行服务。部署需先执行迁移再启动新代码。

## 验收

1. 屏蔽后默认列表及所有检索路径不可召回；管理列表可找到，直接原文读取保真，恢复后相同坐标、资产和索引可用。
2. HTTP 物理删除后数据库无目标作品原文、资产、关联、进度、索引和作品回执；其他作品及共享标签保持不变；可重新导入同一文件。
3. 并发资产写入与删除不留孤立回执；构建中删除返回冲突；中途注入失败完整回滚；重复删除幂等。
4. 真实 PostgreSQL 及扩展上验证迁移、约束和 HTTP；另将用户指定作品的删除前备份恢复至独立测试库，经真实 HTTP 进程验证删除，不覆盖共享库。
