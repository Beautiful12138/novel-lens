# 04 分析标注与标签管理

状态：已实现；基础能力与 0009 纠错增量已完成 Windows、真实 PostgreSQL 18.6 及官方 MCP 客户端验证，记录见第 8 节。共享开发库已于 2026-09-24 经授权升级至 0009 并重启应用；实际 AI 客户端宿主和文学效果验证不在本次运行记录范围内。

依据：[需求与设计基线](../docs/小说分析与创作知识服务_需求与设计基线.md)第 3、8、10、11、22.2–22.3、22.9、35.3 节，以及 [Spec 02](02-小说导入与原文读取.md)、[Spec 03](03-本地MCP原文能力接入.md)。

## 1. 目标与范围

让外部 AI 通过 MCP 完成：读取已有作品 → 查询或创建标签 → 保存带原文引用的分析标注 → 按作品、位置或标签找回标注 → 获取完整说明并复读原文 → 修订标注。

本期实现 Annotation、可选 Note、Tag、标注与标签的关联，以及写入结果查询。标注只保存引用和分析资产，不复制原文、不修改 Work / Section / Paragraph。文学判断、是否值得标注、是否应复用标签仍由外部 AI 决定。

Entity、Relation 及标注实体关联由 [Spec 05](05-实体与跨章节关系.md)扩展，StyleGuide 由 [Spec 06](06-轻量风格导航.md)扩展；本规格同步维护 Annotation 的当前契约。Coverage、AnalysisJob 及原子 checkpoint 由 [Spec 07](07-分析进度与中断接续.md)扩展，关键词与语义检索见 Spec 09–10。不提供自动分析、标签语义合并或质量评分。标注撤回／恢复和标签修改由本规格的纠错增量定义；合并、永久删除、版本历史浏览与一键恢复暂不包含。保存或撤回标注本身不推进分析进度。

## 纠错增量（0009）

- `annotation_set_status` 接收 request_id、work_id、annotation_id、expected_version、status（active / withdrawn）。创建及迁移后的既有标注默认 active；撤回保留全部说明、引用、关联和历史回执。状态修改与内容修改共用版本条件，新请求成功加一，同键重放不加版本。普通内容修改保留状态，不隐式恢复。
- `annotation_get` 可读取任意状态并返回 status；列表和关键词搜索默认 active，可显式指定 withdrawn 或 null（全部），游标绑定状态。默认 active 沿用旧游标范围，新增的其他状态不可混用。详情、摘要与关键词候选均包含状态。
- 标注语义层只以当前 active 标注计算快照、有效候选和动态覆盖；撤回后已有向量也不得继续召回，推理期间撤回导致该批丢弃。恢复时若已有同证据向量可复用，否则如实报告未索引／待构建／过期，不能假称恢复即索引完整。全文检索与全文语义层仍可返回对应原文。
- `tag_update` 接收 request_id、tag_id、expected_version、name、description、aliases，后三项完整替换。namespace、id、created_at 保持不变；aliases=[] 清空别名。名称仍在原 namespace 内唯一，冲突返回 TAG_NAME_CONFLICT；跨作品使用相同标签 ID 的关联自动读取新定义，不批量改动标注版本或引用。
- Tag 当前输出新增 version 与 updated_at；创建／迁移版本为 1，迁移更新时间取 created_at。旧 Tag 快照和无 status 的旧 Annotation 快照保持原样；asset_write_get 不给旧快照补充当前状态。原写入指纹保持兼容，旧请求重放不改写新数据。
- 两个新操作可独立调用或作为 analysis_checkpoint 子写入；批次版本冲突、名称冲突或其他失败时，本批资产、回执和进度一并回滚。
- 关系、风格导航及接续结论是否受影响，由 AI 判断并使用已有接口更新；服务不自动连带撤回或改动 Coverage。撤回后的原文也不删除。
- 迁移 0009 增加上述字段和约束，不改原文、引用、既有版本及历史请求。部署前显式升级；开发验证使用隔离数据库，不自动升级共享库。

验收覆盖：真实 MCP 创建、修改、撤回与恢复；状态筛选和跨状态游标拒绝；默认关键词／语义排除；全文仍可读；内容更新不恢复；版本竞争和旧键重放；标签重名回滚及共享关联保留；checkpoint 原子性；0008 数据升级和历史回执原样恢复。恢复索引缺口与推理期间撤回须有真实数据库验证。

新增能力先通过现有 `/mcp` 提供，共用 FastAPI 进程、业务服务及 PostgreSQL 连接池，不额外建设一套 REST 资产接口。已有 REST 原文接口保持兼容；后续入口可复用本期业务层。

## 2. 数据契约

### 2.1 Annotation

| 字段 | 规则 |
| --- | --- |
| id | 服务生成的稳定 UUID |
| work_id | 必填，标注所属作品；创建后不可更换 |
| source_ranges | 必填且至少一项，使用现有 SourceRange 的四个 UUID 字段 |
| tag_ids | 标签 UUID 集合，创建时默认空，可不打标签 |
| entity_ids | 同作品实体 UUID 集合，创建时默认空；当前详情和新快照必含此字段 |
| note | 可选写法说明，创建时默认 null；自由文本，允许必要的多段说明 |
| status | active / withdrawn；默认 active，内容修改不改变状态 |
| version | 创建时为 1，每次成功的新修改请求加 1 |
| created_at / updated_at | 服务生成的带时区时间；重放不修改时间 |

一条标注的全部范围必须属于 work_id 指定的作品。不同范围可以位于不同 Section；每个范围内部仍须同 Section、起点不晚于终点，包含两端完整自然段。坐标必须真实存在，不能凭 UUID 格式有效就保存引用。

source_ranges 按输入顺序保存，不自动合并重叠范围；同一请求内完全相同的范围拒绝为 INVALID_INPUT，提示移除重复引用。不同标注允许使用相同或重叠的原文范围，不能以原文重叠为由判为重复写入。

Note 保留输入内容和换行，不自动总结、改写或强制填写“机制、效果、适用条件、边界”四字段；服务不判断说明是否文学上成立。null 表示没有说明；空白字符串拒绝，调用方可改传 null。Note 不设置文学意义上的统一字数上限，技术容量规则见第 5 节。

修改采用完整替换 source_ranges、tag_ids、note 的方式，三者均须显式提交；清空标签传 []，清空说明传 null，不能清空全部原文引用。id、work_id、created_at 不可修改。

entity_ids 显式提交时完整替换，[] 表示清空；省略时保留现有实体关联。实体必须属于 work_id，否则返回 ENTITY_NOT_FOUND。实体关联、原文范围、标签和说明共用同一版本条件与事务；实体自身改名不改变标注版本。

### 2.2 Tag

采用跨作品共享的标签词表，便于相同写法在不同作品中复用；Tag 不带 work_id，作品隔离在 Annotation 查询和引用层执行。

| 字段 | 规则 |
| --- | --- |
| id | 服务生成的稳定 UUID |
| namespace | 必填，1–64 个 Unicode 码点，例如“机制” |
| name | 必填，1–256 个 Unicode 码点，例如“话题恢复” |
| full_name | 服务派生为 namespace/name，不接受客户端赋值 |
| description | 必填且非空白，说明标签的含义和使用边界 |
| aliases | 默认空列表；每项为非空的 1–256 字符名称 |
| version | 创建时为 1，每次成功的新修改请求加 1 |
| created_at / updated_at | 服务生成的带时区时间；重放不修改时间 |

namespace 和 name 禁止首尾空白及 `/`，避免 full_name 歧义；aliases 禁止首尾空白，完全相同的别名去重并按确定性顺序保存。名称和别名不自动进行大小写、Unicode 或同义词归一化。文字字段拒绝 NUL；不静默裁剪输入。

namespace、name 按 PostgreSQL C 排序规则组合唯一。不同请求键创建同名标签返回 TAG_NAME_CONFLICT，调用方查询后选择复用，不自动覆盖 description 或 aliases。不同标签可以具有相同别名，查询须返回全部匹配候选，不能据此自动合并。

标签创建前应先搜索已有名称、定义和别名；这是调用方的分析工作规则，服务不以“必须先调用一次搜索”作为写入授权令牌。

## 3. 查询与原文定位

开发期阅读格式调整：annotation_get、annotation_list 默认 format=compact，显式 full 返回本节完整字段。compact 详情保留 id、work_id、version、status、完整 note、全部 tag_ids / entity_ids 和全部证据范围，省略创建／修改时间及范围中的重复 work_id；范围与顶层 work_id 合成 SourceRange。compact 列表顶层集中 work_id，候选保留 id、version、status、首个范围、范围数量、说明预览及截断标记，省略时间和标签／实体计数。格式不改变状态筛选、排序和游标；修改前按 Skill 显式读取 full。写入参数、写入结果与历史回执保持完整，不接受 format 参数。

- `tag_get` 返回一个完整标签。`tag_list` 返回标签页，可按 namespace 精确过滤。
- `tag_search` 必须提供非空白 query；对 full_name、description、aliases 做不区分大小写的字面子串匹配，多个字段命中只返回一次。`%`、`_` 等按普通字符处理。可同时按 namespace 精确过滤；不分词、不做语义相似度或相关性评分。
- `annotation_get` 要求 work_id、annotation_id，返回完整标注、source_ranges、tag_ids 和 entity_ids，不展开原文。ID 属于其他作品时与不存在一样返回 ANNOTATION_NOT_FOUND。
- `annotation_list` 必须指定 work_id，可组合 source_range、tag_ids、entity_ids 和 status 过滤。status 默认 active，withdrawn 只查撤回项，null 查全部。位置匹配表示任一引用与查询范围在同 Section 内相交，含边界；标签和实体各要求同时具有全部指定项。[] 表示不按该集合过滤。
- 查询范围、标签和实体 ID 均校验真实存在，实体还须属于当前作品；不存在或跨作品时返回相应错误。资源存在但没有匹配标注时返回空页。
- full 格式标注列表返回候选摘要：id、work_id、version、status、created_at、updated_at、first_source_range、source_range_count、tag_count、entity_count、note_preview、note_truncated；默认 compact 字段见本节开头。note_preview 最多 200 个 Unicode 码点，仅供选择候选；完整说明通过 annotation_get 获取，原文通过现有 source_read 获取。无 Note 时 preview=null、truncated=false。

分页沿用 limit 默认 100、范围 1–1000，返回 items、next_cursor。列表按 created_at、id 升序；修改不改变创建顺序。游标绑定工具类型和全部有效过滤条件，不能跨作品、查询词或过滤范围复用；过滤条件使用确定性序列化摘要，避免长查询导致游标无限增长。limit 可在续页时改变。

entity_ids 为空时保留原有游标过滤摘要，因此升级前无实体过滤的游标继续有效；非空实体过滤参与摘要，不允许与旧条件串用。

本期不提供跨多页的一致快照：并发创建或修改可能改变后续页的匹配集合。单次详情读取必须返回同一版本的 Note、范围和标签，不能拼接修改前后的数据。

## 4. 写入、修改与结果恢复

五个写工具 tag_create、tag_update、annotation_create、annotation_update、annotation_set_status 都要求调用方提前生成并保存 request_id（UUID）。本期资产写入使用一个共享的请求键空间；与 Spec 02 的原文导入请求键空间分别查询，不改动既有 work_import_get。

业务对象、关联记录及成功请求记录在一个 PostgreSQL 事务中提交；任何校验或数据库步骤失败都不留下部分成果或成功请求记录。失败请求键不被占用。标签创建与标注创建是独立操作；标注失败不回滚此前已成功创建的独立标签。

请求指纹包含契约版本、操作名、目标、全部有效输入及修改版本条件，不包含 request_id。采用确定性 JSON：对象字段顺序无关，tag_ids、entity_ids 和 aliases 按集合排序去重，source_ranges 保留顺序，Note 等文本逐字保留。不同操作或目标不能复用同一请求键。

兼容 0002 的 asset-v1 契约：annotation_create 缺省 entity_ids 或传 [] 时从指纹输入中移除此字段；annotation_update 省略 entity_ids 时同样使用旧指纹。创建时非空实体集合、修改时显式提交 entity_ids 均使用 asset-v2，并包含该字段；修改时省略与显式 [] 不等价，不能先展开默认值而丢失字段是否出现的信息。tag_create 继续使用 asset-v1；tag_update 与 annotation_set_status 使用 asset-v2。历史快照按原格式恢复，不补写 entity_ids、status 或标签版本；历史字段缺失不能解释为资产当前状态。详见 Spec 05 第 3.1 节及本规格纠错增量。

- 相同 request_id 和相同指纹：返回该次已提交结果，replayed=true，不再执行写入。
- 相同 request_id、不同指纹：REQUEST_CONFLICT。
- 不同请求键创建相同标签名：TAG_NAME_CONFLICT；并发时依靠数据库唯一约束裁决。
- 不同请求键创建相同或重叠范围的标注：允许，服务不替 AI 判定两条标注是否重复。

annotation_update 还须提交 expected_version，必须为正整数。数据库以版本条件原子更新；与当前版本不一致返回 VERSION_CONFLICT，不覆盖既有说明或关联。成功更新增加版本，即使新内容与旧内容相同；同键重放不增加版本。

重复请求识别先于当前版本检查：同一次修改响应丢失后重试，应取得旧请求结果，不能误报版本冲突。两个不同请求键同时修改同一版本时，只能一个成功，另一个完整回滚；不是“最后写入覆盖”。

写入返回 `request_id、operation、status=completed、replayed、result`，本规格五个写工具的 result 为该次提交时的完整 Tag 或 Annotation 快照。`asset_write_get` 按 request_id 返回同一快照，replayed=true；即使资产后来已修改，也不把当前状态冒充旧请求的结果。Spec 05、06 扩展了共享恢复入口，分别支持 Entity / Relation 和 StyleGuide 快照；Spec 07 增加任务快照与精简 checkpoint 回执，子资产仍用各自请求键恢复完整快照。需要当前状态时另调 annotation_get 或 tag_get。该记录用于可靠重试，不提供完整编辑历史浏览功能。

没有已提交记录时返回 WRITE_NOT_COMMITTED；仅表示查询时尚无结果，不能证明并发写入不会稍后提交。超时、断开或取消后先查询原键，再以原键和原输入重试，不自动换键。

## 5. MCP 工具与错误

| 工具 | 输入 | 返回 |
| --- | --- | --- |
| tag_create | request_id、namespace、name、description；可选 aliases | 写入结果 |
| tag_update | request_id、tag_id、expected_version、name、description、aliases | 写入结果 |
| tag_get | tag_id | 完整 Tag |
| tag_list | 可选 namespace、limit、cursor | Tag 页 |
| tag_search | query；可选 namespace、limit、cursor | Tag 页 |
| annotation_create | request_id、work_id、source_ranges；可选 tag_ids、entity_ids、note | 写入结果 |
| annotation_update | request_id、work_id、annotation_id、expected_version、source_ranges、tag_ids、note；可选 entity_ids | 写入结果 |
| annotation_set_status | request_id、work_id、annotation_id、expected_version、status | 写入结果 |
| annotation_get | work_id、annotation_id；可选 format=compact\|full | 完整说明和证据，按格式返回元数据 |
| annotation_list | work_id；可选 source_range、tag_ids、entity_ids、status、limit、cursor、format=compact\|full | 标注摘要页 |
| asset_write_get | request_id | 已提交写入结果 |

工具名以表为准，不新增同义入口。五个写工具标明写入副作用与幂等条件；其他工具只读。参数模型、业务层和 schema 使用同一约束，拒绝未知参数及类型错误，版本与分页不把 true 或数字字符串当整数。

沿用 Spec 03 的 structuredContent、相同对象的 JSON 文本副本、isError 和 outputSchema 规则。查询结果超过 1 MiB 返回 RESULT_TOO_LARGE，不截断完整标注或假装分页完成。摘要裁剪是明确字段契约，不适用于正文、完整 Note 或范围引用。

单条资产写入必须保证最终成功响应（含完整资产快照及请求结果封装）的紧凑 UTF-8 JSON 不超过 1 MiB；在事务提交前完成计量，超限返回 ASSET_TOO_LARGE 并回滚。该规则是数据传输容量限制，不是 Note 的文学字数要求，也不能出现“已提交但因为已知结果超限而无法恢复”的情况。HTTP 请求体总上限继续沿用现有配置。

新增错误为 TAG_NOT_FOUND、ANNOTATION_NOT_FOUND、TAG_NAME_CONFLICT、VERSION_CONFLICT、WRITE_NOT_COMMITTED、ASSET_TOO_LARGE。沿用 INVALID_INPUT、INVALID_RANGE、INVALID_CURSOR、REQUEST_CONFLICT、原文归属错误和数据库错误分类。业务错误统一 code、message、details，不输出完整输入、SQL、凭据或底层异常；VERSION_CONFLICT 可在 details 返回当前版本号。

## 6. 实施约束

沿用 PostgreSQL、SQLAlchemy Core 和 Alembic，不引入搜索扩展或新运行服务。迁移 0002 增加 tags、annotations、annotation_ranges、annotation_tags、asset_write_requests；aliases 使用 JSONB，Note 为 Annotation 的可空文本字段，不单独创建大型报告表。

数据库提供标签名称唯一、请求键唯一、关联唯一、必要外键和版本正数约束。范围子表保留输入 ordinal 和四个坐标字段；业务层在事务内核验作品、Section、端点归属与顺序。原文当前不可变，不能通过拷贝正文替代引用校验。修改主记录、范围及标签必须原子可见；选择事务快照或单条聚合查询保证详情读取一致。

请求表保存指纹和提交结果；在事务内以 ON CONFLICT 对唯一请求键竞争，取得键后保存业务和结果，失败整体回滚，不依赖进程内字典或锁。修改锁定标注行并检查版本；详情和摘要使用 REPEATABLE READ 事务快照。迁移同时验证空库升级与已有 Spec 02 数据的升级，保留作品 UUID、文件字节和坐标。显式执行迁移，启动不自动改表。

业务实现与协议适配分离，扩展现有 MCP 注册与共享契约；仅复用确有调用方的校验，不预建 Entity、Relation 或进度框架。实现完成后同步 README、配置或接口说明及本规格验证记录。

Spec 05 使用迁移 0003 增加实体关联及关系；当前详情和摘要在同一读取快照中包含实体关联。历史 0002 数据由旧提交生成的独立样例验证升级兼容，不改写 0001、0002 迁移或旧请求记录。
