# 20 AI 分析操作与 HTTP 对等接口

状态：已实现并通过独立数据库与真实 HTTP/MCP 验证；尚未重启当前运行服务以启用本次能力。补充 Spec 04、07、08、17、18 的寻址、修订和追溯能力；原文保真、作品隔离、幂等和批次原子性继续有效。

## 目标与边界

AI 无需从聊天转录提取段落映射或重建未修改的引用，即可阅读、修订、预检和接续分析。MCP 与普通 HTTP 调用同一业务实现。本规格定义操作与传输对等能力；服务器鉴权与部署由 Spec 21 补充。应用不直接开放公网监听，不提供远程文件上传；导入路径仍为服务可读的文件路径。

## 寻址、查询和分页

- 业务原文读取、标注引用、准备批次范围及标注范围过滤接受完整 UUID 范围或 `work_id + section_id + start_ordinal/end_ordinal`。段号从 1 开始，范围包含两端；两个寻址方式互斥，端点必须完整，归属和越界由服务核验。存储及结果中的证据身份仍采用原文 UUID。
- `library_browse(view=annotations)` 支持对 title、scope_note、note 的字面关键词查询，与其他过滤共同绑定游标。source_range 匹配任一证据范围相交，包含端点；不按 reading_range 匹配。不同标注可引用相同原文。
- 有界批量详情返回完整标注、版本、标签及每处证据/阅读范围的段号，单次最多 50 条，指定作品且保持请求顺序；缺失或不属于作品的 ID 明确报错。
- 原文页返回可直接用于下一次调用的 `next_request`，保留原请求定位、上下文和格式参数；原有游标的范围绑定继续有效。

## 修订、预检和错误

- 原完整修订继续有效。新增显式 `operation=patch` 标记，省略的内容、引用、标签和状态保留；允许完整替换 references 或使用 add_references/remove_references，二者互斥。移除不存在的引用或重复添加同一证据明确拒绝，最终仍须至少一处合法引用。只修改 note 或撤回无需重发旧引用。
- prepare_batch 与 prepare_read 以 expected_job_version 明确任务版本，marks 以 expected_annotation_version 明确标注版本；prepare_finish 保留仅指任务版本的 expected_version。旧 expected_version 输入继续接受，双名同时提供拒绝。幂等指纹仍以原规范字段形成，已有完整请求可重放。
- `prepare_validate` 只读验证当前批次的任务版本与状态、范围、接续信息和各条标记，返回结构化问题及 mark/reference 位置；不会占用请求键、创建资产或推进进度。同键同规范输入已有回执时返回 already_committed=true，不受后续版本变化影响；同键不同输入返回 REQUEST_CONFLICT 问题。服务端不判断文学重复，也不要求保留失效引用。正式提交在事务和锁内重新校验，预检不保证并发后仍能提交。
- 参数错误返回安全的字段路径和错误类别，不回显输入正文、任意未知键、SQL 或底层异常。批次业务错误附带对应条目路径，失败仍整体回滚。

## 追溯、导出和已读暂存

- 按标注列出可取得的历史版本、读取指定版本，并比较两个实际存在版本的内容字段、引用、标签和状态。复用已有不可变提交快照和当前对象，不伪造缺失版本；明确报告可见历史是否完整。版本快照不冒充当前标签定义或当前任务状态。
- 按任务分页列出已提交 prepare_batch，返回请求键、处理范围、结果标注版本、任务版本变化和 outcome_note。复用准备与 checkpoint 回执，按任务版本排序，翻页上界固定；当前批次重放不会重复出现。
- 标注导出以分页完整详情交付，含版本和全部引用段号，可导出指定作品或该任务的准备批次实际写过的标注当前版本；后者不是引用范围归属。提供快照校验，导出期间内容变化须明确重试，不能静默混合不同版本。不提供无上限的单次 JSON 返回。
- `prepare_read` 显式持久保存 read 范围及接续信息，复用任务版本和请求幂等；不能把 processed 降级，不将阅读请求自动记为已读，不把 read 当作处理完成。完成任务仍要求所有目标 processed。

## HTTP 与 AI 使用说明

为全部日常 MCP 能力提供普通 HTTP 对应入口，包括标签更新和本次新增操作；共享参数模型、业务错误与事务规则。提供只包含日常能力及必要模型的 `/ai/openapi.json`，operationId 对应 MCP 工具名。完整维护接口继续存在，精简描述不是权限边界。

README、接口说明和两份 Skill 说明 MCP/HTTP 的调用映射、原文读取、预检、局部修订、超时回执、历史及接续；分析和创作方法不因传输方式改变。采用 HTTP 时客户端须能访问服务所在电脑，导入路径仍是服务可读的文件路径。
