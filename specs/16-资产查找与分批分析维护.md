# 16 资产查找与分批分析维护

状态：实现与必要验证完成，运行和外部宿主边界见下文。WebUI 保持暂停，本期只修改服务读取能力与分析 Skill；不新增模型分析、人物覆盖评分、合并工具或数据库结构。

## 目标

AI 分批阅读时可以低成本找到已有标签和观察，根据新证据补充、修订或撤回，并保存必要接续信息。文学完整性由 AI 对原文判断，原文进度与索引覆盖不作为文学完整性的证明。

## 服务契约

默认 MCP 仍为八项，HTTP 与 MCP 共用 `library_browse`。

- 新增 `view="tags"`，浏览全库共享词表，不接受 work_id。可选 namespace 精确筛选、query 对名称/完整名称/定义/别名做不区分大小写的字面子串匹配；不做语义合并。空白 query 拒绝，省略 query 表示浏览。使用已有标签排序、分页和游标规则。
- 标签视图返回 `tag_page: {items,next_cursor}`，与标注详情的 `tags` 定义列表区分。compact 标签包含 id、namespace、name、full_name、description、aliases；full 另保留版本和时间。没有虚构的使用次数或人物完整性统计。
- `view="annotations"` 列表新增 tag_ids、source_range、status 条件。必须提供 work_id；多个标签要求同时具有，位置匹配任一引用与范围相交。status 为 active、withdrawn 或 null，省略保持原目录查询全部状态的行为。详情使用 annotation_id，不接受列表过滤条件。
- namespace/query 仅用于标签视图，tag_ids/source_range/status 仅用于标注列表；不适用的输入明确拒绝，不静默忽略。非法标签和跨作品引用沿用既有错误；游标绑定所有筛选，compact/full 不影响成员及排序。
- 共享标注列表摘要增加 `tags: [{id,full_name}]`，包括业务目录与维护 annotation_list 的 compact/full 投影；无标签返回 []。在同一数据库读取快照中取得版本、引用摘要及标签身份，不能逐条读取完整 Note 后拼装。列表仍不是完整修订对象，修改前须读当前详情。
- 标签名和别名只帮助定位候选；共享标签查找不表示该标签已用于某作品，须再查该作品标注。相同标签可以关联不同观察，不能据此判定重复。

## Skill 调整

每批根据实际观察查找相关已有资产，决定新建、补充证据、修订判断或撤回；不要求每段标注、每个人物建卡或每次遍历全部资产。新证据支持同一观察时也应考虑补充，不限于发现错误时修订。

接续读取实际状态、上一批 recovery 和相关资产。已知未写入事项记录具体待办、资产 ID 和证据位置，可先使用 recovery.next_action；事实与文学未决问题分别使用已有字段。不把接续记录替代真正写入，不把既有 recovery 当增量追加字段：提交新接续信息时须保留仍有效的未完成项。

阶段或全书结束时针对性核对待办、前后变化和相关旧观察。能完成的保存操作完成后再结束；依赖未读后文的问题可以有据保留。当前任务持续运行时自动分批推进，停止后不声称服务会唤醒 AI。范围、版本、完整替换、回执与原子批次契约不变。

## 验收

在独立真实 PostgreSQL 测试库验证标签名称/别名/分组查找、普通模式字符、分页和游标错用、标签交集与范围/状态组合、作品隔离、空结果、无标签摘要、标签改名后的名称更新。验证 compact/full 一致及 HTTP/MCP 契约，默认工具数量不变。

检查分批创建与修订、多引用完整保留、进度和接续相关回归。更新接口说明、受影响 Spec、Skill 及通过生成流程维护的参考资料。Skill 规则检查不冒充其他 AI 平台执行效果；不改共享库小说或替执行 AI 补卡。
