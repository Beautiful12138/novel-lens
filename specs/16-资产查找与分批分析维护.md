# 16 资产查找与分批分析维护

状态：资产查找与分批维护的现行要求，浏览与标签修订由 [Spec 17](17-分类标签与原文浏览.md) 扩展。下文历史记录对应此前版本；不新增模型分析、人物覆盖评分或自动合并。

## 目标

AI 分批阅读时可以低成本找到已有标签和观察，根据新证据补充、修订或撤回，并保存必要接续信息。文学完整性由 AI 对原文判断，原文进度与分类覆盖不作为文学完整性的证明。

## 服务契约

HTTP 与 MCP 共用 library_browse，固定分类、共享标签写入与可见性按 Spec 17。

- categories、tags、annotations 列表支持 work_id 或非空 work_ids，互斥；省略表示全库可见范围。parts、sections、jobs 与标注详情继续要求单作品。
- categories 只返回当前范围有效标注实际使用的分类及去重计数，另有未分类计数。tags 接受 category、namespace、query 字面子串过滤；全库词表包含零使用标签，指定范围只返回实际有效使用的标签。category=unclassified 对应空分类，省略不限分类。
- 标签返回身份、名称、定义、别名、categories 与范围内 annotation_count；full 包含当前版本和时间。标签多分类不复制身份，计数不表示文学质量或原文频率。
- annotations 支持 kind=observation/comparison 过滤，省略查询两种，按 Spec 18 与其他条件共同绑定游标；默认 active，可显式查 withdrawn 或 null（全部状态）。tag_ids 默认 tag_match=any，显式 all 求交集，结果去重；part_id、section_id、source_range 过滤必须单作品，source_range 匹配任一引用相交。详情使用 work_id+annotation_id，不接受列表过滤。
- 列表提供作品名、部章、kind、title、scope_note、观察摘要、标签和原文入口，详情提供全部引用、各引用用途、连续阅读范围与当前版本；修改前须读完整详情，不能以列表摘要覆盖完整说明与引用。原文通过 source_read 按稳定坐标继续阅读。
- 不适用或冲突输入明确拒绝；分页绑定全部筛选，compact/full 不改变成员。查询范围不包含屏蔽作品，有效计数不包括撤回标注。
- prepare_batch 新建标签接受 categories 和 aliases；已有标签按 namespace/name 精确复用，不隐式更新共享内容。tag_update 使用请求键、当前版本及完整名称、定义、别名修订；categories 省略保留，[] 清空。具体协议见 Spec 17。
- 相同标签可以关联不同观察，不能据此判定重复。全库共享词表存在不证明某作品已使用；标签定义与分类按共享含义维护，不将单作品纠错信息写入共享概念。

## Skill 调整

每批根据实际观察查找相关已有资产，决定新建、补充证据、修订判断或撤回；不要求每段标注、每个人物建卡或每次遍历全部资产。新证据支持同一观察时也应考虑补充，不限于发现错误时修订。

接续读取实际状态、上一批 recovery 和相关资产。已知未写入事项记录具体待办、资产 ID 和证据位置，可先使用 recovery.next_action；事实与文学未决问题分别使用已有字段。不把接续记录替代真正写入，不把既有 recovery 当增量追加字段：提交新接续信息时须保留仍有效的未完成项。

阶段或全书结束时针对性核对待办、前后变化和相关旧观察。能完成的保存操作完成后再结束；依赖未读后文的问题可以有据保留。当前任务持续运行时自动分批推进，停止后不声称服务会唤醒 AI。范围、版本、完整替换、回执与原子批次契约不变。

## 验收

在独立真实 PostgreSQL 测试库验证分类与多分类、名称/别名/分组查找、普通模式字符、分页和游标错用、标签 any/all 与范围/状态组合、跨作品与单作品过滤、空结果、零使用标签、无标签标注、第二处引用匹配、标签修订幂等及版本冲突。验证 compact/full 一致及 HTTP/MCP 契约。

检查分批创建与修订、多引用完整保留、进度和接续相关回归。更新接口说明、受影响 Spec、Skill 及通过生成流程维护的参考资料。Skill 规则检查不冒充其他 AI 平台执行效果；不改共享库小说或替执行 AI 补卡。

## 验证记录（2026-09-26）

- 本机 Python 3.12 项目虚拟环境，真实 PostgreSQL 上由既有测试框架创建并清理随机独立库，未向共享库小说资产写入。无需数据库迁移。
- 新增 test_library_assets.py 的 8 项验证通过，包含真实官方 MCP Client 与 HTTP 对照，工具仍为八项。资产、业务阅读、准备与 compact 等受影响回归 42 项通过，共 50 项；只出现既有 Starlette/AnyIO 弃用警告。
- Ruff 检查、格式检查、严格 mypy 通过。Skill 通过 quick_validate.py；项目虚拟环境没有 YAML 依赖，因此校验脚本使用本机已有带 PyYAML 的 Python 执行，未安装或更改全局依赖。写作原则生成副本同步检查通过，没有修改该副本。
- 已检查差异与文档，未提交或推送 Git；WebUI 样稿继续暂停。本轮没有创建结构化待办表、自动合并、人物识别或文学质量评分。
- 接口验证使用独立临时服务；常用 127.0.0.1:8000 回环连接检查时未运行，本轮未启动常驻服务。外部 AI 宿主需要重新加载服务工具定义和新版分析 Skill；尚未验证该宿主后续是否稳定执行新指引，工程通过不代表文学分析不会遗漏。
