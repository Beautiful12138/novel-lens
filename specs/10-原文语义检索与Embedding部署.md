## 1. 目标与范围

开发期阅读格式调整：source_semantic_search 默认 format=compact，显式 full 保留完整结果。compact 顶层返回 work_id、kind、coverage、partial、candidate_window_limited，省略索引 ID、模型契约 ID 和历史代状态；候选保留原文摘录、截断标记、分数、可回读范围，标注层另保留标注 ID、当前版本和范围序号。范围省略重复 work_id，候选省略与顶层相同的 kind；不改变召回、排序、覆盖判断或错误。索引管理及状态接口保持完整。

通过自然语言检索作品中的原文候选，并返回能够重新读取原文的稳定引用。覆盖未标注的全文和已标注的精选原文；语义相似不代表写法适用，文学判断仍由外部 AI 完成。

本 Spec 的完整目标包括 TechnicalChunk、Annotation 引用原文向量、显式索引构建与状态查询、限定作品的语义查询，以及对应 HTTP / MCP 入口。独立运行入口、全文切片与标注原文闭环均已实现。继续保留 Spec 09 的关键词搜索；不扩展到 Web UI、第三套说明向量、复杂融合排序或远程 MCP 账号体系。

## 2. 部署与换电脑

在同一仓库维护 NovelLens 与独立 embedding 服务的配置，通过明确的启动入口组合运行。两项服务运行在使用者本机，NovelLens 通过本机地址调用 embedding 服务生成向量；AI 客户端仍只使用 NovelLens MCP，无需直接调用模型服务。默认创建用户自己的 PostgreSQL 实例，也支持连接已有实例；多电脑共享数据库是可选模式，不依赖维护者服务器。

| 组件 | 职责 | 持久内容 |
| --- | --- | --- |
| NovelLens | 原文与资产管理、索引构建、查询、HTTP / MCP | 配置由运行环境提供 |
| Embedding 服务 | 将查询或原文转换为向量 | 模型权重与必要的模型配置，保存在独立目录或卷 |
| PostgreSQL | 保存业务数据与可重建的检索数据 | 原文、资产、索引状态、来源映射及向量 |

使用哪台电脑，就在该电脑启动 embedding。型号、显存和驱动以实机探测为准，部署规则不绑定维护者电脑或特定处理器、显卡。按实际硬件选择 CPU 或 GPU 执行方式，不因更换设备自动更换模型。具体运行依赖、内存和显存预算须验证，不承诺未经实测的模型大小与吞吐。

模型权重、凭据与数据库卷不进入 Git。每台电脑显式准备本地模型权重目录，可以下载固定版本或复制已核验文件；后续启动复用本机权重。模型标识、不可变版本、维度及预处理约定必须可以核对，服务地址不能代替模型身份。

两台电脑连接同一数据库或迁移完整备份，并采用相同模型身份与文本处理规则时，可复用已完成的向量索引；迁移工作区或 CPU / GPU 切换本身不触发全库重建。只克隆代码不会复制业务数据或向量。查询与构建前核对模型身份，发现不兼容则明确拒绝使用既有索引，不能静默混用不同模型空间。CPU / GPU 的数值误差及跨设备查询一致性纳入验证。

NovelLens 与 embedding 的主机端口只对本机开放。把 NovelLens HTTP / MCP 或 embedding 暴露到远程网络不属于本增量；本地模型服务无需部署到共享数据库服务器。

### 2.1 首次初始化与配置复用（已确认）

部署由 AI 按仓库指引协助操作，用户无需逐项手工推导硬件参数。仓库提供独立于历史会话的部署指引、配置模板及确定性的读取、启动与验证命令；不实现自动硬件探测或自动调参器。AI 阅读部署指南，调用本机已有命令检查资源、选择参数、试运行、调整并告知用户。不依赖维护者的全局 Skill，现有两份小说分析与写作 Skill 继续负责业务使用。

1. 没有本机部署配置时，AI 按部署指南使用操作系统命令检查 CPU、总内存与当前可用内存、GPU 型号与可用显存、驱动、运行依赖和磁盘空间；检测结果不等同于性能验证，不预设固定的跨平台探测脚本。
2. AI 写出候选配置，确定执行后端、线程数、上下文与批量上限、并发、端口及本地权重路径，并说明依据。保留系统与其他应用所需资源，不按硬件标称总容量直接分配全部资源。
3. 使用固定模型执行小规模加载与真实向量生成验证，记录资源占用、耗时和有效配置。资源不足时优先降低批量或并发；不能把失败配置标记为可用，也不能自动更换模型来绕过不兼容。
4. 验证通过后保存本机配置，AI 告知用户所选参数、配置位置、启动方式、已验证结果及限制；后续普通启动读取配置并做必要兼容性检查，不每次重新探测调优、下载权重或重建索引。
5. 已有配置与当前环境不兼容时，说明具体原因，由初始化或修复流程重新验证；不得静默覆盖有效配置。已有配置文件损坏时也不能当作首次运行直接覆盖。

配置分为共享的模型与索引契约，以及各电脑独立的运行参数。模型不可变版本、向量维度、tokenizer、文本预处理和切片规则须与既有索引一致；CPU / GPU、线程、批量、并发、端口和路径可按机器调整。数值精度或推理后端变化须经过兼容性验证，不能仅因维度相同就认定可混用。

配置模板与部署规则随代码提交，本机配置、凭据、权重及检查记录不进入 Git。另一台电脑首次使用时由 AI 重新检查环境并准备本机配置，读取已有模型与索引契约；不复制旧电脑的设备号、绝对路径或性能参数。

### 2.2 已实现增量：独立运行入口

独立运行入口为 `python -m novel_lens.embedding_runtime`，该进程不直接操作应用业务、数据库或索引；NovelLens 通过模型适配器调用它。公开模板为根目录 `embedding.example.toml`，验证后保存至被 Git 忽略的 `embedding.local.toml`。候选配置可放在 `tmp/`；相对路径按候选文件目录解析，保存时转为绝对路径，避免移动配置后指向不同文件。

- `check --config PATH`：只读校验 TOML、路径、模型 SHA-256、固定 llama.cpp build / commit 和设备选择，输出有效参数；不启动、下载、调参或修改文件。
- `verify --config PATH [--save PATH]`：启动临时服务，检查模型标识、真实短文本与较长文本的 1024 维归一化向量，以及超长输入拒绝行为；停止本次进程后才可保存配置。保存采用独占创建，已有文件（包括损坏文件）不覆盖；失败不保存有效配置。
- `run [--config PATH]`：缺省读取 `embedding.local.toml`，校验后以前台父进程管理单个服务。完成健康与短文本验证才报告就绪，Ctrl+C 或失败时回收自己创建的子进程；不管理后台 PID 文件或终止其他进程。
- `status [--config PATH]`：检查配置对应本机服务的健康与模型别名，不启动服务或改写配置。仅确认端点状态，不替代模型文件校验和完整验证。

此增量固定候选模型契约为官方 Qwen3-Embedding-0.6B Q8_0 的已验证修订，运行时为 llama.cpp b10964 / b29c606e2，详情与哈希见选型文档。参数可选 CPU 或显式 CUDA 设备，CUDA 必须在指定可执行文件的设备列表中出现，不静默回退 CPU；真实 GPU 性能与跨设备一致性仍待实机验收。服务固定监听 `127.0.0.1`、单 slot、last pooling 与 L2 归一化；上下文最多 4096 token，逻辑与物理批量 token 上限与上下文相同，不引入尚未验证的任意启动参数。模型指令与未来切片规则不由本机参数调整。

运行命令清除传给子进程的 `LLAMA_ARG_*` 参数环境覆盖，并显式传入受支持参数。权重、运行时由 AI 按公开链接准备并核验；运行命令不安装驱动或修改全局环境。端口占用、模型损坏、版本不符、服务退出及响应异常均非零退出，保留现有配置。

## 3. 两层原文索引

### 3.1 模型身份与输入契约

首版使用第 2.2 节固定的 1024 维 Q8_0 模型。索引契约包含模型仓库与不可变修订、GGUF SHA-256、tokenizer 所在 GGUF 身份、量化方式、运行时兼容版本、last pooling、L2 归一化、查询指令、文本拼接方式、token 化选项及切片策略版本。规范化 JSON 的 SHA-256 作为 `contract_id`；不把服务地址、线程数、路径或 CPU/GPU 名称当作模型身份。尚未通过兼容性验证的推理后端不得复用已有代。

- 正文输入使用同一 Section 内按原顺序读取的 `Paragraph.text`，段间以单个 LF 拼接。不修剪空白、不做 Unicode 归一化、不添加标题、标签、说明或聊天模板。LF 是派生索引的分隔规则，不改写上传文件。
- 查询保留既有实验指令：`Instruct: Given a Chinese fiction writing query, retrieve relevant passages from novels\nQuery: <查询正文>`，其中 `\n` 表示实际换行。查询前缀只用于查询向量。
- 用固定服务的 `/tokenize`，显式指定 `add_special=true`、`parse_special=false`，再把返回的完整 token ID 数组交给 `/v1/embeddings`。原文中形似特殊 token 的字面文本按普通文本处理；不能退回默认字符串解析而不改变契约。
- token 预算按最终拼接文本分词，包含模型特殊 token；查询还包含指令前缀。不能把各段 token 数相加代替最终分词，也不能以字符数代替 token 数。校验模型返回的 `usage.prompt_tokens` 与提交 token 数一致。
- 当前 4096 上下文的已验证最大输入为 **4095 token**；4096 和 4097 均被拒绝。语义索引首版要求本机配置 `context_tokens=4096`；较小上下文仍可用于独立运行入口，但接入该索引契约时明确拒绝，不静默缩短切片或跳过本来可处理的段落。
- NovelLens 接入配置增加可选 `NOVEL_LENS_EMBEDDING_CONFIG`，指向已验证的本机 TOML；未配置时基础功能照常使用。应用不启动模型、不下载文件；首次使用语义能力时核验产物、模型别名及运行上下文，使用当前独立入口启动的本机服务。端点别名只是部署一致性检查，不能证明任意第三方服务所加载的权重；本增量不支持任意 OpenAI-compatible 服务冒充该固定模型。

### 3.2 全文切片规则 `paragraph-window-v1`

以完整自然段组成 TechnicalChunk，不跨 Section，不视为文学场景或分析边界。首版目标为 **1024 token**，重叠预算为 **128 token**；这两个值来自现有 CPU 成本与机械边界实验，用于首版验证，不宣称是文学召回最优参数。

1. 按 Section、段落顺序贪心加入尚未覆盖的完整段落，使最终输入不超过 1024 token。到章节末尾时输出不足目标长度的片段，不强行跨章补齐。
2. 下一块可复用上一块末尾总量不超过 128 token 的最长完整段落后缀；至少加入一个新段落。如果重叠导致新段落无法放入目标预算，先减少重叠，不能只输出重复后缀或陷入不前进的循环。
3. 单段超过 1024、但不超过 4095 token 时单独成块，不携带重叠。单段超过 4095 时记录 `INPUT_TOO_LONG`、准确的段落范围及 token 数，并继续下一段；不拆改自然段、不截断，也不跨越该缺口拼接两边原文。
4. 单段文本超过 1 MiB UTF-8 字节时不送入 tokenizer，记录 `TOKENIZATION_INPUT_TOO_LARGE` 及字节数；这是显式资源限制，token 数为未知，不能伪报超出 token 上限。所有未覆盖范围均可从索引状态分页读取。
5. 切片保留完整 `SourceRange`、最终输入文本摘要值、token 数及策略版本。原始字节、Paragraph ID、段落坐标、分析资产及分析进度保持不变。

### 3.3 标注原文

`kind=annotation` 只对 Annotation 引用的原文建立向量。每个 `source_range` 独立处理；连续范围超出目标长度时复用第 3.2 节规则，多处不连续范围绝不拼成一个文本。每个切片保存 `annotation_id`、原范围标识、实际子范围及标注证据身份。

证据身份由按固定顺序规范化的完整范围集合、来源文件身份及对应原文摘要值计算，不包含 note、标签或 Annotation 的一般版本号。仅修改说明或标签时复用向量。范围变化时原身份下的结果整体失效，后续显式构建新代；不因普通标注写入触发推理。新的代可以复用同契约、同文本及同范围的已有有效向量，但仍须核对当前归属和身份。

查询以当前标注为准：在查询快照内核对证据身份，不返回已经失效的引用；构建发布也在短事务中重新核对。接口返回查询时的 `annotation_version`，其后发生的修改由现有资产读取接口反映，不承诺跨请求快照。

标注层实现细化：创建代时用单条 SQL 快照保存每条标注的有序范围及证据身份。范围按章节顺序、起止段落顺序规范化，身份包含来源文件摘要、端点和对应原文摘要；仅调整引用数组顺序不改变身份。首版不跨代复制向量，说明／标签修改直接复用当前代，新建代则显式重算。

标注覆盖返回 `total`、`covered`、`stale`、`not_indexed`、`blocked`、`pending`、`complete`，covered、stale、not_indexed、blocked、pending 五类互斥，合计为 total。先分类未纳入快照与证据过期，再判断其余标注的所有范围是否均被有效向量覆盖；存在超长范围时计入 blocked，其余未完成计入 pending。部分查询可返回身份仍有效的已完成切片，即使所属标注的其他范围尚有缺口；同标注仍只返回一个最佳命中。

构建游标按快照标注 ID、规范化范围序号及范围内段落推进，跳过当前身份已失效的快照。发布时按 ID 顺序锁定本批涉及的标注并再次核对身份；若任一身份改变，本批待发布切片全部丢弃、游标与切片均不推进，提交带 `batch_discarded` 的成功回执；`batch_tokens` 保留已提交给模型的输入量。下一请求按原游标重新规划并跳过过期快照；同请求重放不会重新计算。历史 ready 状态与实时完整性分别报告。阻塞列表只列当前仍有效的证据，并附 `annotation_id`、`annotation_version` 与 `range_ordinal`；过期和新增缺口由覆盖统计说明。

标注层迁移为 `0008`，增加每代每标注的快照及切片来源字段，扩展 kind 约束；应用更新后两层语义入口均要求该迁移。降级至 0007 只删除 annotation 派生代、指针、回执、切片与快照，保留 fulltext 的既有数据、原文、资产和扩展。HTTP / MCP 工具数量不变，扩展 kind 与响应字段。

### 3.4 向量存储

采用 PostgreSQL 内的 **pgvector 0.8.6**，列类型 `vector(1024)`；与 PGroonga 分别负责向量距离和关键词检索。官方安装路径支持 PGDG 软件包；本次验证包版本为 `0.8.6-1.pgdg13+1`。正式 Dockerfile 与 0007 迁移已包含该扩展；升级既有实例仍需独立部署操作。

首版按作品、索引代和当前有效证据过滤，再做余弦距离的精确排序；为范围字段建立 B-tree 索引，暂不建立 HNSW / IVFFlat。这样可验证精确候选和作品隔离，避免提前引入近似检索的召回取舍；全书规模的耗时与是否需要近似索引仍须实测。[pgvector 官方过滤说明](https://github.com/pgvector/pgvector#filtering)

所有待保存向量必须具有 1024 个有限数值，范数接近 1（绝对误差不超过 `1e-3`），零向量拒绝。数据库以向量维度、非空条件及范数 CHECK 提供第二层约束；输入次序、响应条目数量、token 用量在服务层核验。

## 4. 构建、更新与失败行为

### 4.1 索引代与最小数据结构

全文、标注两层分别维护索引代，以 `(work_id, kind)` 隔离。`create` 是明确的新建／重建操作，`build` 是执行有限批次；应用启动、导入和标注写入不隐式执行全书推理，不引入后台队列。

| 数据结构 | 职责与必要约束 |
| --- | --- |
| `semantic_index_heads` | 每作品、每层一行，保存 `active_index_id` 与 `target_index_id`；指针必须引用同作品同层的代 |
| `semantic_indexes` | 保存代 ID、模型／策略契约、源文件身份、规划游标和状态；覆盖计数在同一读快照中按自然段或标注及其证据去重计算。创建请求 ID 在作品与层内唯一，重放时核对请求摘要 |
| `semantic_annotation_snapshots` | 0008 增加，每代每标注一行，保存有序范围及证据身份，不保存正文；用于明确构建目标、新增／修订缺口及一条标注是否全部完成，避免把全书标注快照堆入单行 JSON |
| `semantic_index_items` | 每条记录对应一个连续原文片段，保存范围、文本摘要、证据身份、token 数、向量或阻塞原因；`(index_id, source_key)` 唯一，复合外键／短事务校验防止跨作品范围；不复制完整正文 |
| `semantic_build_receipts` | 保存 `(index_id, request_id)`、请求摘要和已提交批次的结果；与向量、游标和计数在同一事务提交，重放不执行下一批 |

`source_key` 包含层、标注 ID（若有）、原范围及切片实际范围；同一代不能写出重复切片。待处理或阻塞项的向量为空，只有已核验的 `ready` 项有向量。索引状态与 AnalysisJob / Coverage 无关，不复用分析进度表或推进阅读任务。

代状态为 `building`、`ready`、`partial`、`failed`、`superseded`：`ready` 表示发布时目标快照全部有效覆盖；`partial` 表示已扫描目标但存在阻塞、过期或新增来源缺口；`failed` 表示推理、tokenizer 或存储失败，修复后可在同一代接续；`superseded` 表示已被显式新建的目标代替代，旧工作不得继续发布。

### 4.2 批次、重试与并发

- `build` 每次最多处理 4 个切片（默认 4），本批提交给模型的总 token 不超过 4095；长单段可能独占一批。预算是确定性的资源上限，不是部署自动调参。待处理项优先于继续扫描；计划已保存但未生成向量的项保持待处理。
- 每批先读取原文、范围与预期身份，再调用模型，最后在短事务内核对并写入。向量、相应计数／游标和成功回执原子提交；当前批失败时保留先前已提交的批次，不发布半批向量。若只遇到阻塞段落，也提交范围、原因和扫描进度，避免重试永远卡在同一段。
- 同一 `(work_id, kind)` 的创建和构建操作使用 PostgreSQL 会话级 advisory lock，非阻塞获取，冲突返回 `INDEX_BUSY`。锁连接独占于本次操作，网络推理期间不保持写事务；必须在归还连接池前解锁。锁连接断开则丢弃未提交结果，不可换连接继续发布。首版不实现分布式工作队列或额外租约框架。
- 构建回执只记录已提交批次。网络超时后按同一个 `request_id` 重试：已有回执就返回原结果；没有回执则执行待处理批次。同 ID 携带不同参数返回 `IDEMPOTENCY_CONFLICT`，不静默作为新任务。模型失败等未提交尝试可以使用原 ID 重试。
- 标注写入不持有索引锁。发布阶段锁定所涉标注并重新计算证据身份；不一致时丢弃该批待发布向量、将失效来源记为缺口，不能将旧结果绑定到新引用。只改说明不导致失效。查询阶段仍需核对当前身份，不能只信构建时的版本。

### 4.3 发布与部分覆盖

显式 `create` 分配新目标代，相同请求 ID 返回已有代；新的创建请求会把原未完成目标标记为 `superseded`，但不删除其记录。接续必须对已有 `index_id` 调用 `build`，不能靠重复 `create` 接续。

新代达到 `ready` 时，在同一短事务中重新确认它仍是目标代，核对源快照并切换 `active_index_id`。重建过程中保留旧完整代可查，前提是它与当前可用模型契约相同且证据仍有效；模型已切换时不得使用新查询向量搜索旧模型代。`partial` 或 `failed` 不替换旧完整代；首代未完成时无默认可用的完整索引。

查询默认 `allow_partial=false`。调用方明确设置为 true 后，可以查询指定代已提交且当前仍有效的部分；没有 active 代时可选择 target 代，不能混合两代候选。使用部分结果不把状态改为完成。

全文覆盖按唯一自然段计数，重叠不重复累计，返回总数、已覆盖、阻塞和待处理数。标注层返回当前标注总数、完整索引数、过期数、未纳入快照数、阻塞数和待处理数：先分出未纳入与过期，再在身份一致的快照中区分完整、阻塞和待处理，类别互斥。一条标注只有所有当前证据范围有效覆盖才计为完整。新增或修订标注会使当前覆盖不完整，即使该代历史状态曾是 `ready`；返回 `generation_status` 和动态 `coverage.complete`，默认查询不得隐瞒这个差异。

## 5. 查询与兼容

### 5.1 HTTP / MCP 契约

下表四个接口共用于 fulltext 和 annotation 两层，默认 fulltext。HTTP 和 MCP 使用相同请求模型、业务服务、错误码与响应上限；HTTP 路径中的作品／索引 ID 与请求归属必须一致。

| MCP 工具 | HTTP | 核心输入 |
| --- | --- | --- |
| `semantic_index_create` | `POST /works/{work_id}/semantic-indexes` | `work_id`、`kind=fulltext\|annotation`、`request_id`；契约由服务核验，调用者不能自报向量或模型身份 |
| `semantic_index_build` | `POST /works/{work_id}/semantic-indexes/{index_id}/build` | `work_id`、`index_id`、`request_id`、`max_items=4`（1—4） |
| `semantic_index_get` | `GET /works/{work_id}/semantic-indexes/status` | `work_id`、`kind`（默认 fulltext）、`index_id?`、阻塞范围分页 `limit=100`（1—100）、`cursor` |
| `source_semantic_search` | `POST /works/{work_id}/semantic-search` | `work_id`、`kind=fulltext\|annotation`（默认 fulltext）、`query`、`limit=10`（1—50）、`index_id?`、`allow_partial=false`、`format=compact\|full`（默认 compact） |

创建／构建返回 `index_id`、契约 ID、代状态、当前覆盖、active／target 指针、本批结果及是否回执重放。回执重放返回原提交时的快照并标记 `replayed=true`，最新覆盖另行读取状态，不能把旧回执冒充当前状态。即使没有新向量也不能丢失阻塞进度。

状态读取不要求模型服务运行：只给作品与层即可发现 active／target 代及其摘要，二者都没有时返回 `state=missing`；指定 `index_id` 后返回该代明细与阻塞范围分页，游标绑定作品、层和代，不承诺跨页快照。这样新会话不必从聊天记录找回索引 ID。

未提供 `index_id` 的搜索优先选择 active，仅当没有 active 且显式允许部分结果时才选择 target。指定代必须属于请求作品和层，并符合当前模型契约；已被替代的代不能重新构建或被默认选择。

查询文本为 1—8192 个 Unicode 码点，不得全为空白或包含 NUL；带前缀后超过 4095 token 则拒绝。首版提供有界 Top-K，不提供语义搜索分页，不宣称分数达到某值就一定相关。

### 5.2 结果与去重

返回选用的 `index_id`、`contract_id`、代状态、动态覆盖和 `partial` 标识。每条候选包含来源层、实际 `SourceRange`、原文摘录（段首最多 200 个 Unicode 码点并标明截断）、`score=1-cosine_distance`；标注候选另带 `annotation_id`、当前版本及具体命中证据范围。分数不是概率或文学质量，语义检索也没有可伪造的“关键词命中位置”。响应沿用现有 1 MiB 上限，超限返回 `RESULT_TOO_LARGE`。

过滤作品、代及失效证据后按距离升序、章节／段落顺序和稳定 ID 打破平局；先选最多 `10×limit` 条原始候选再去重，响应报告是否受此候选窗口限制。全文候选按得分保留，若与已保留候选在同一 Section 的段落交集占较短范围的 80% 及以上，则跳过重复候选；允许去重后不足 limit，不补入其他作品。标注层按 `annotation_id` 聚合，取最高分及其实际命中范围，不将不同标注混为一条，也不拼接不连续证据。首版分别查询两层，不做跨层融合排序。

### 5.3 错误与兼容

| 错误 | 行为 |
| --- | --- |
| `EMBEDDING_NOT_CONFIGURED` / `EMBEDDING_UNAVAILABLE`（503） | 缺少配置或端点不可用；普通读取、资产和关键词接口仍可使用 |
| `EMBEDDING_CONTRACT_MISMATCH`（409） | 权重、tokenizer、上下文、模型／策略或未验证后端不兼容；不混用向量空间 |
| `SEMANTIC_SCHEMA_NOT_READY`（503） | 缺少所需迁移或 vector 扩展；不自动迁移，不伪装空结果 |
| `INDEX_NOT_FOUND`（404） / `INDEX_NOT_READY`（409） | 指定作品中无该代，或尚无可选索引；不扩大作品范围 |
| `INDEX_INCOMPLETE`（409） | 有缺口且未显式允许部分查询；返回可读的索引状态入口 |
| `INDEX_BUSY` / `INDEX_SUPERSEDED` / `IDEMPOTENCY_CONFLICT`（409） | 构建互斥、目标已被替代或请求 ID 冲突；不错误推进游标 |
| `QUERY_TOO_LONG`（400） / `EMBEDDING_INVALID_RESPONSE`（502） | 查询超预算，或模型响应数量、维度、数值、归一化／token 用量不符；不保存假向量 |

超长原文和 tokenizer 资源上限按第 3.2 节作为逐范围阻塞记录，不能把一处缺口转换为“整书无结果”。实际服务异常使本批失败；只有索引有效且搜索确实无候选时，才返回正常空集合。沿用既有输入、作品缺失、归属错误及响应限额错误。

0007 仅新增派生索引表和 `vector` 扩展，不改原文或分析表语义。降级只移除本增量表，不自动 `DROP EXTENSION ... CASCADE`，以免删除其他使用方数据；所需扩展版本检查失败应在写入前明确报错。共享库升级需要后续独立部署操作；正式 0007 的隔离迁移和恢复验收见第 10 节。

### 9.1 Token 与自然段边界

| 项目 | 观察与结论 |
| --- | --- |
| 普通中文、空白与换行 | 以 `add_special=true, parse_special=false` 分词，再传 ID 数组，返回的 token 用量与计数一致；普通文本的字符串／ID 输入向量一致到浮点误差 |
