# 10 原文语义检索与 Embedding 部署

状态：部分实现。第 2.1—2.2 节的 AI 部署指引与独立运行入口已实现并通过 Windows CPU 验证；AI 检查环境、选择候选参数，程序校验、试运行并保存配置。模型实验见[选型与验证记录](../docs/Embedding选型与CPU验证.md)。两层原文语义索引沿用需求基线第 17 章，接口与索引仍待实现；现行 NovelLens 尚不调用 embedding，数据库版本未改变。

## 1. 目标与范围

通过自然语言检索作品中的原文候选，并返回能够重新读取原文的稳定引用。覆盖未标注的全文和已标注的精选原文；语义相似不代表写法适用，文学判断仍由外部 AI 完成。

本 Spec 的完整目标包括 TechnicalChunk、Annotation 引用原文向量、显式索引构建与状态查询、限定作品的语义查询，以及对应 HTTP / MCP 入口。本次仅交付第 2.2 节独立运行入口，其余范围分步实施。继续保留 Spec 09 的关键词搜索；不扩展到 Web UI、第三套说明向量、复杂融合排序或远程 MCP 账号体系。

## 2. 部署与换电脑

在同一仓库维护 NovelLens 与独立 embedding 服务的配置，通过明确的启动入口组合运行。两项服务运行在使用者本机，NovelLens 通过本机地址调用 embedding 服务生成向量；AI 客户端仍只使用 NovelLens MCP，无需直接调用模型服务。默认创建用户自己的 PostgreSQL 实例，也支持连接已有实例；多电脑共享数据库是可选模式，不依赖维护者服务器。

| 组件 | 职责 | 持久内容 |
| --- | --- | --- |
| NovelLens | 原文与资产管理、索引构建、查询、HTTP / MCP | 配置由运行环境提供 |
| Embedding 服务 | 将查询或原文转换为向量 | 模型权重与必要的模型配置，保存在独立目录或卷 |
| PostgreSQL | 保存业务数据与可重建的检索数据 | 原文、资产、索引状态、来源映射及向量 |

使用哪台电脑，就在该电脑启动 embedding。型号、显存和驱动以实机探测为准，部署规则不绑定维护者电脑或特定处理器、显卡。按实际硬件选择 CPU 或 GPU 执行方式，不因更换设备自动更换模型。具体运行依赖、内存和显存预算须验证，不承诺未经实测的模型大小与吞吐。

模型权重、凭据与数据库卷不进入 Git。每台电脑显式准备本地模型权重目录，可以下载固定版本或复制已核验文件；后续启动复用本机权重。模型标识、不可变版本、维度及预处理约定必须可以核对，服务地址不能代替模型身份。

两台电脑连接同一数据库或迁移完整备份，并采用相同模型身份与文本处理规则时，可复用已完成的向量索引；迁移工作区或 CPU / GPU 切换本身不触发全库重建。只克隆代码不会复制业务数据或向量。查询与构建前核对模型身份，发现不兼容则明确拒绝使用既有索引，不能静默混用不同模型空间。CPU / GPU 的数值误差及跨设备查询一致性纳入验证。

NovelLens 与 embedding 的主机端口只对本机开放。把 NovelLens HTTP / MCP 或 embedding 暴露到远程网络不属于本增量；本地模型服务无需部署到共享数据库服务器。

### 2.1 首次初始化与配置复用（已确认）

部署由 AI 按仓库指引协助操作，用户无需逐项手工推导硬件参数。仓库提供独立于历史会话的部署指引、配置模板及确定性的读取、启动与验证命令；不实现自动硬件探测或自动调参器。AI 阅读部署指南，调用本机已有命令检查资源、选择参数、试运行、调整并告知用户。不依赖维护者的全局 Skill，现有两份小说分析与写作 Skill 继续负责业务使用。

1. 没有本机部署配置时，AI 按部署指南使用操作系统命令检查 CPU、总内存与当前可用内存、GPU 型号与可用显存、驱动、运行依赖和磁盘空间；检测结果不等同于性能验证，不预设固定的跨平台探测脚本。
2. AI 写出候选配置，确定执行后端、线程数、上下文与批量上限、并发、端口及本地权重路径，并说明依据。保留系统与其他应用所需资源，不按硬件标称总容量直接分配全部资源。
3. 使用固定模型执行小规模加载与真实向量生成验证，记录资源占用、耗时和有效配置。资源不足时优先降低批量或并发；不能把失败配置标记为可用，也不能自动更换模型来绕过不兼容。
4. 验证通过后保存本机配置，AI 告知用户所选参数、配置位置、启动方式、已验证结果及限制；后续普通启动读取配置并做必要兼容性检查，不每次重新探测调优、下载权重或重建索引。
5. 已有配置与当前环境不兼容时，说明具体原因，由初始化或修复流程重新验证；不得静默覆盖有效配置。已有配置文件损坏时也不能当作首次运行直接覆盖。

配置分为共享的模型与索引契约，以及各电脑独立的运行参数。模型不可变版本、向量维度、tokenizer、文本预处理和切片规则须与既有索引一致；CPU / GPU、线程、批量、并发、端口和路径可按机器调整。数值精度或推理后端变化须经过兼容性验证，不能仅因维度相同就认定可混用。

配置模板与部署规则随代码提交，本机配置、凭据、权重及检查记录不进入 Git。另一台电脑首次使用时由 AI 重新检查环境并准备本机配置，读取已有模型与索引契约；不复制旧电脑的设备号、绝对路径或性能参数。

### 2.2 本次实现增量：独立运行入口

本增量实现 `python -m novel_lens.embedding_runtime`，不接入应用业务、数据库或索引。公开模板为根目录 `embedding.example.toml`，验证后保存至被 Git 忽略的 `embedding.local.toml`。候选配置可放在 `tmp/`；相对路径按候选文件目录解析，保存时转为绝对路径，避免移动配置后指向不同文件。

- `check --config PATH`：只读校验 TOML、路径、模型 SHA-256、固定 llama.cpp build / commit 和设备选择，输出有效参数；不启动、下载、调参或修改文件。
- `verify --config PATH [--save PATH]`：启动临时服务，检查模型标识、真实短文本与较长文本的 1024 维归一化向量，以及超长输入拒绝行为；停止本次进程后才可保存配置。保存采用独占创建，已有文件（包括损坏文件）不覆盖；失败不保存有效配置。
- `run [--config PATH]`：缺省读取 `embedding.local.toml`，校验后以前台父进程管理单个服务。完成健康与短文本验证才报告就绪，Ctrl+C 或失败时回收自己创建的子进程；不管理后台 PID 文件或终止其他进程。
- `status [--config PATH]`：检查配置对应本机服务的健康与模型别名，不启动服务或改写配置。仅确认端点状态，不替代模型文件校验和完整验证。

此增量固定候选模型契约为官方 Qwen3-Embedding-0.6B Q8_0 的已验证修订，运行时为 llama.cpp b10964 / b29c606e2，详情与哈希见选型文档。参数可选 CPU 或显式 CUDA 设备，CUDA 必须在指定可执行文件的设备列表中出现，不静默回退 CPU；真实 GPU 性能与跨设备一致性仍待实机验收。服务固定监听 `127.0.0.1`、单 slot、last pooling 与 L2 归一化；上下文最多 4096 token，逻辑与物理批量 token 上限与上下文相同，不引入尚未验证的任意启动参数。模型指令与未来切片规则不由本机参数调整。

运行命令清除传给子进程的 `LLAMA_ARG_*` 参数环境覆盖，并显式传入受支持参数。权重、运行时由 AI 按公开链接准备并核验；运行命令不安装驱动或修改全局环境。端口占用、模型损坏、版本不符、服务退出及响应异常均非零退出，保留现有配置。

## 3. 两层原文索引

- TechnicalChunk 从连续自然段生成，保留自然段和稳定映射，不作为文学场景或分析边界。建议先不跨章节；长度与重叠参数由最终模型的 tokenizer 和样例测试确定。
- Annotation 向量来自其引用的小说原文，不拼入说明、标签或实体描述。多处非连续证据分别保留定位；具体拆分与候选聚合规则须在实现前明确，不把非连续原文伪装成连续片段。
- 输入长度计入模型规定的特殊 token 和查询前缀等开销。禁止模型静默截断。单段已超上限时明确暴露未索引范围与原因，不拆改原始段落，也不能把缺失覆盖报告为完成；替代处理方式另行明确。
- 保留原文引用、内容摘要值、模型身份和切片策略版本，能够判断向量是否仍适用于当前源数据。索引是派生数据，重建不修改原文字节、段落坐标、分析资产或分析进度。

## 4. 构建、更新与失败行为

索引构建由明确操作触发，应用启动、小说导入和普通资产写入不隐式下载模型或执行全书推理。首版优先采用显式批次构建与接续，不为此预设独立队列系统。

构建需要可查询的覆盖和失败状态。相同源内容、模型与策略的重复执行不产生重复结果；中断后可以接续。模型失败时只保存已验证的结果，不发布半批结果或假向量；网络调用不长期占用业务写事务。

资产提交后，旧证据范围的向量不得作为新范围的命中返回。构建期间再次修改资产，发布前核对源版本或内容身份，过期结果丢弃或重试。只修改说明且引用原文不变时，不必重新计算原文向量。

模型或切片策略变化时需要显式重建，查询不得混合不同向量空间。重建期间能否继续查询旧的完整索引，以及如何原子切换，将在物理设计中明确；不把不完整新索引报告为全量可用。

## 5. 查询与兼容

拟新增独立的语义查询入口，共用业务层；最终工具名、字段、范围上限与错误码随实现细化。请求显式限定作品，首版可先保持与 Spec 09 一致的单作品查询范围；不能在无结果时自动扩大到其他作品。

结果提供命中来源、原文引用、实际原文摘要、相似度与索引覆盖状态，Annotation 命中还需提供可读取的资产标识。相似度不表述为置信概率或文学质量。重叠候选需控制重复，并保留来源信息；不能虚构未存在的 Annotation。

缺少模型配置、模型不可用、索引未准备好或数据库尚未升级时，语义能力返回明确状态，不伪装为正常空结果，也不返回固定模拟候选。既有原文读取、资产管理和关键词搜索继续遵循原契约。部分覆盖是否允许查询及其响应标识须在接口定稿时确定。

## 6. 实现前的待决项

1. Windows CPU 已验证固定修订的 Qwen3-Embedding-0.6B Q8_0：1024 维、last pooling、L2 归一化，4 / 8 / 12 / 16 线程记录见选型文档；第 2.2 节已固定此独立运行入口的模型契约。情境查询与写法查询结果分开报告，不以冒烟结果替代真实文学效果评估。继续验证真实段落、GPU 与跨设备一致性；其他平台启动方案在实测后确认，不把未测试设备或更大上下文标记为通过。
2. 用最终 tokenizer 确定切片长度、重叠、多范围标注处理和超长段落行为，并记录未覆盖范围；不以字符数假冒 token 数。
3. 评估 PostgreSQL 内的向量存储与查询方案，优先考察 pgvector；核实与 PostgreSQL 18.6、PGroonga 共存后的构建、恢复和迁移行为。当前公开部署配置尚不包含 pgvector。
4. 明确构建接续、并发发布、失效检测、候选聚合与覆盖状态的最小数据结构及 HTTP / MCP 契约，再编写迁移和业务实现。

## 7. 验收条件

- 未标注原文和标注原文均能被查询命中；返回引用可通过 source_read 回读，原始字节和坐标保持不变。
- 多作品隔离、重复构建、失败接续、并发修订、模型身份或维度不符、超长输入均有可观察且一致的行为，不留下被误用的过期结果。
- 使用真实模型验证实际向量、中文样例召回、服务重启与模型不可用行为；模拟响应不能替代部署验收。记录实测资源与延迟，文学效果评估仍另行进行。
- 使用选定的真实数据库扩展验证迁移、回退边界、索引重建与备份恢复，不在共享业务库写入验收素材。
- 新用户仅依靠公开仓库与依赖即可准备环境、配置和本地权重，启动本机 NovelLens / embedding 及自己的数据库；另验证连接已有数据库的路径。换电脑可重新连接原库或迁移备份，不复制旧 .venv，不仅因换电脑重建索引。同模型跨设备查询与不兼容模型拒绝行为有验证证据，CPU / GPU 启动依赖分别说明。
- 无本机配置时，AI 按公开指引检查资源、选择候选参数、执行真实试运行、保存配置并说明结果；再次启动复用有效配置，不自动改写。覆盖硬件不兼容、配置损坏和试运行失败，确保未验证结果不被当作有效配置。不了解历史会话的 AI 能依靠仓库指引和运行命令完成这些操作；不以自动探测或调参脚本代替 AI 判断。
- HTTP / 官方 MCP 对照验证通过，README、配置示例、需求基线及两份 Skill 的实际工具流程同步后，才标记实现完成。既有环境部署和数据库升级单独执行并记录。
