## 1. 范围

新增 source_search 与 annotation_search，分别检索自然段原文与 Annotation.note。HTTP 与 MCP 共用契约和业务服务；既有标签、实体、关系查询不变。无标注原文也可命中。

不引入向量、TechnicalChunk、统一搜索、相关度权重或独立搜索服务，不修改原文。数据库索引直接维护现有文本列，无第二套待同步的业务内容。

## 2. 查询与结果

开发期阅读格式调整：source_search、annotation_search 默认 format=compact，可显式 full 返回原完整结构。两种格式的命中、排序、分页与摘要内容相同，format 不绑定游标。compact 顶层集中 work_id 和 match_kind，引用范围省略重复 work_id；原文候选保留章节标题、段落序号及可回读的范围，标注候选保留 ID、版本、状态、首个范围及范围数量。摘录保留 text、前后截断及 match_located，省略 character_start；标注候选省略创建时间。默认值变更属于开发期接口调整，已有调用如依赖完整字段需显式 full。HTTP 和 MCP 使用相同投影，在投影后执行容量检查，不截断结果以满足容量。

- work_id 必填；terms 为 1–8 个非空关键词，每项最多 128 个 Unicode 码点，拒绝 NUL，去除首尾空白、去重并固定次序。关键词按普通文本匹配，不解释查询表达式。
- match 为 all / any，默认 all。all 要求各词出现在同一自然段或同一标注说明，不跨记录拼接命中。
- limit 默认 20，上限 100；cursor 绑定作品、规范化关键词、匹配模式和入口。不开放本轮尚未需要的额外过滤项。
- 原文按 Section.ordinal、Paragraph.ordinal、id 排序；标注按 created_at、id 排序。游标采用键集分页，不提供结果快照，分页期间说明修改可能影响后续命中集合。
- 原文结果包含 work_id、section_id、章节标题与序号、paragraph_id / ordinal、单段 SourceRange、命中类型和不超过 200 字符的原文摘要。
- 标注结果包含 annotation_id、version、created_at、明确的 annotation_note 命中类型、说明摘要、首个证据范围、证据范围数量；完整标注及全部证据通过 annotation_get 读取。
- 摘要使用原字段的真实子串，提供字符起点及前后截断标记；不把归一化结果或 AI 说明当作原文，也不内嵌 HTML。无法定位归一化命中的原始位置时不猜偏移。

两个工具返回 `{items, next_cursor}`。原文命中类型为 source_text，说明为 annotation_note。excerpt 字段为 text、character_start（零基 Unicode 字符位置）、truncated_before、truncated_after、match_located。使用 PGroonga 的归一化关键词位置，从首个位置前最多 40 字开始截取 200 字；找不到位置时从 0 截取并标记 match_located=false。该位置用于摘要选取，不是精确分词高亮坐标；`a OR b` 等包含空格的文本可能命中但无法映射摘要位置。单次完整响应上限 1 MiB，超限统一返回 RESULT_TOO_LARGE。

HTTP：POST /source/search、POST /annotations/search；请求体包含 work_id。MCP：source_search、annotation_search。统一校验未知字段、作品存在性、游标和结果大小；不记录关键词或正文请求。

## 3. 索引与一致性

使用 PostgreSQL 18 + PGroonga，直接索引 paragraphs.text 与 annotations.note，固定 tokenizer=TokenBigram、normalizers=NormalizerAuto。中文支持单字和连续词、人名与标点；ASCII 按词且大小写归一化，全角字母及兼容字符归一化，例如 ABC 命中 ＡＢＣ，ffi 命中 ﬃ，但 bc 不命中 abcd。词内部空白交给分词器处理，不承诺任意字符串子串或逐字短语匹配；不提供同义词、繁简转换保证或语义召回。

查询使用 `&@` 的显式索引配置，避免顺序扫描退化为更宽的子串命中。all 使用同记录 AND，any 对各词命中 ID 求 UNION，避免已验证 PGroonga 4.0.8 / PostgreSQL 18.4 组合的复合搜索条件 OR 规划错误。每次查询事务设置 `pgroonga.match_escalation_threshold=-1`、`pgroonga.force_match_escalation=off`，不使用依赖索引命中数量的隐式扩展匹配。

迁移 0006 在已安装 PGroonga 的实例中启用扩展并建立两项索引；缺少扩展文件时迁移明确失败。旧迁移不改写，应用启动不自动安装或迁移。尚未升级的库可使用既有功能，搜索返回明确的 SEARCH_UNAVAILABLE。

修改说明提交后新查询读取新内容，回滚不留下命中。索引可重建；在独立环境验证 0005 → 0006、原有数据与坐标保留、事务行为、备份恢复和索引重建。共享部署使用既有 PostgreSQL 18.6 基础镜像添加 PGroonga 4.0.8，以验证后的镜像 ID 固定运行产物；备份及隔离恢复通过后切换，保留原数据卷、端口、认证和 PostgreSQL 小版本。
