# 接口与使用

本文描述当前操作入口，分类浏览遵循 [Spec 17](../specs/17-分类标签与原文浏览.md)，标注内容与连续阅读遵循 [Spec 18](../specs/18-连续阅读与叙述选择.md)。先按[部署指南](部署指南.md)启动自己的实例。数据库要求 `0017`；服务不运行 embedding 或提供语义接口。

## 访问认证

未配置密钥的本机实例保持原调用方式。配置 NOVEL_LENS_ACCESS_KEY 后，所有业务、维护、下载、MCP、OpenAPI 和交互接口文档统一需要认证；HTTP/MCP 使用 Authorization: Bearer，密钥不进入 URL。GET /health、GET /auth/status、POST /auth/login、POST /auth/logout 和网页静态壳允许匿名到达；后者不包含作品数据。

网页在 /ui/ 输入密钥，POST /auth/login 的 JSON 为 {"access_key":"私有配置中的密钥"}，登录后使用 8 小时签名 Cookie（HttpOnly、SameSite=Strict；公开部署为 Secure）。GET /auth/status 返回 enabled 与 authenticated，POST /auth/logout 清除当前浏览器 Cookie；更换服务密钥并重启使旧密钥和旧签名会话失效。Cookie 写入必须携带与公开入口完全一致的 Origin。登录和退出会拒绝其他来源；所有持有密钥者拥有相同业务权限，不提供用户账号或 OAuth。

认证失败为 HTTP 401 / UNAUTHORIZED，连续 10 次凭据失败后该客户端短期返回 429 / AUTH_RATE_LIMITED 与 Retry-After: 60。该限制为单进程内的有界状态，当前部署使用一个应用进程。API 描述根据实例是否启用鉴权声明 securitySchemes。配置与反向代理见部署指南和 Spec 21。

## 作品准备与原文浏览入口（0017）

默认 MCP 配置为 business，提供 15 项工具。维护人员可在独立进程设置 `NOVEL_LENS_MCP_PROFILE=maintenance` 使用细粒度资产和关键词检索工具；配置不是权限边界。

| MCP 工具 | HTTP 入口 | 行为 |
| --- | --- | --- |
| `library_browse` | `POST /library/browse` | works/categories/tags/parts/sections/annotations/jobs；列表支持分页，详情提供全部引用 |
| `tag_update` | `POST /tags/update` | request_id、tag_id、expected_version、name、description、aliases；categories 可选，省略保留、[] 清空；版本检查与幂等生效 |
| `source_read` | `POST /source/read` | work_id、section_id、可选成对段落端点、before/after、limit/cursor/format；读取完整自然段 |
| `prepare_import` | `POST /preparation/import` | request_id、file_path，新作品提供 name，追加提供 work_id；原子导入分部并登记任务 |
| `prepare_status` | `POST /preparation/status` | work_id/job_id 查询状态，或 request_id 查询回执；返回剩余范围与整作品 work_ready |
| `prepare_batch` | `POST /preparation/batch` | request_id、work_id、job_id、expected_job_version、source_range、marks、recovery、outcome_note；标注与 processed 进度原子保存 |
| `prepare_finish` | `POST /preparation/finish` | 请求键、作品与任务 ID、当前版本、recovery、note；目标全部处理即可完成 |
| `prepare_cleanup` | `POST /preparation/cleanup` | work_id、confirm_work_name；明确放弃后整作品清理，失败回滚，不删除外部 TXT |
| `prepare_validate` | `POST /preparation/validate` | 完整批次只读预检，返回 valid、issues 和条目路径 |
| `prepare_read` | `POST /preparation/read` | 显式保存 read 范围、任务版本和接续信息，不代表处理完成 |
| `prepare_batches` | `POST /preparation/batches` | 按任务分页列出已提交分析批次及版本变化 |
| `annotation_get_many` | `POST /annotations/details` | 一次最多 50 个 ID 的完整标注与引用段号 |
| `annotation_history` | `POST /annotations/history` | 可取得的历史列表或指定版本快照，缺失明确报告 |
| `annotation_diff` | `POST /annotations/diff` | 比较两个实际存在版本的字段、引用、标签和状态 |
| `annotation_export` | `POST /annotations/export` | 作品或任务相关当前标注的有界分页导出，内容变化使旧快照失效 |

上述日常能力的精简 schema 由 `GET /ai/openapi.json` 提供，operationId 与 MCP 工具名一致；JSON 成功响应直接是业务对象。完整调用示例、连接条件、段号寻址、局部修订、双层版本及错误恢复见 [AI HTTP 使用指南](AI-HTTP使用指南.md)，业务契约见 [Spec 20](../specs/20-AI分析操作与HTTP对等接口.md)。HTTP 与 MCP 共用业务实现；本地地址不代表远程 AI 平台能够访问。

业务 source_read、批次范围和标注引用接受 UUID 范围，或 work_id + section_id + start_ordinal/end_ordinal，段号从 1 开始、包含两端；两种端点互斥。原文页 next_request 可直接作为下一次请求体。标注 source_range 匹配任一 evidence_range 相交，包含端点。

### 分类、标签与标注

六个固定分类为 content（内容选择与展开）、perspective（视角与信息）、interaction（人物与互动）、language（语言与声音）、structure（节奏与结构）、emotion（情绪与氛围）。标签可以多分类；categories=[] 表示未分类，不能创建新分类。

`library_browse` 的 categories、tags、annotations 视图支持可选 work_id 或非空 work_ids（最多 20 个），二者互斥；省略表示全库。屏蔽作品不参与浏览和使用统计。

1. `{"view":"categories","work_ids":["作品UUID"]}` 返回当前范围有有效标注使用的分类、去重标签数和标注数，含未分类计数。
2. `{"view":"tags","category":"language","work_ids":["作品UUID"]}` 取得标签。category 可省略或为 unclassified；可组合 namespace 和 query。query 对名称、完整名称、定义、别名作字面子串匹配。全库词表包含未使用标签，指定作品范围只返回有效标注使用的标签；annotation_count 只统计该范围有效标注。
3. `{"view":"annotations","tag_ids":["标签UUID"],"tag_match":"any","work_ids":["作品UUID"]}` 返回去重候选。any 为默认任一命中，all 为全部命中；不传 tag_ids 可直接浏览。默认 status=active，withdrawn 查撤回，null 查全部。part_id、section_id、source_range 须指定单作品，其中 part_id/section_id 互斥，任一引用匹配即可。业务 library_browse 的 query 支持标签或标注列表，标注按 title、scope_note、note 作字面查询；可选 kind=observation 或 comparison 筛选用途，省略查询两种。WebUI 使用的 `/assets/annotations/browse` 另支持 query 对标题、适用范围和说明作字面查询。
4. `{"view":"annotations","work_id":"作品UUID","annotation_id":"标注UUID"}` 返回 kind、title、scope_note、完整 note、标签定义、全部 references 及 locations（部章名、证据与阅读范围段号）。compact 引用含 evidence_range、role_note 和完整 read_target；full 引用含 evidence_range、reading_range、role_note。详情不接受列表过滤。
5. 将 compact 详情中每处 read_target 整体交给 source_read（full 使用 reading_range），按内容补读上下文。不同引用分别阅读，不拼成一个连续场景。

列表提供作品名、title、kind、scope_note、首处引用的部章名、摘要、标签身份、引用数量和原文入口。翻页须保留过滤条件，改变条件不能沿用游标。compact/full 不改变候选成员；精简原文坐标须与响应顶层 work_id、section_id 合并后使用。

“作品认识”直接使用 `{"view":"annotations","kind":"comparison","work_id":"作品UUID"}` 查询；没有条目时可沿目录连续阅读。它是标注用途，不是第七类标签；独立 StyleGuide 已退役。

### 分批分析与修订

marks 可为空；每条必填 kind（observation/comparison）、title（1–256 字符）、scope_note、note、references；文本不能空白。references 为 1–100 项，每项必填 evidence_range、role_note，reading_range 可省略并等于证据范围；提供时必须同作品、同章且包含证据，重复 evidence_range 拒绝。tags 可为空。新标签接受 namespace、name、description、aliases 和 categories；同命名空间同名称精确复用，不覆盖已有共享定义、别名或分类，需修订时单独 tag_update。标签更新需先读 full 取得当前版本。任一写入失败，整批标注、标签、进度和回执回滚，已成功批次保留。

标注完整修订携带 annotation_id 和自身 expected_annotation_version，可设 status=withdrawn；operation=patch 可仅提交改动字段，省略的引用、标签和内容保留。completed 任务修订须提供非空 reopen_reason 和至少一条标注；原子重开、保留覆盖，失败恢复原状态，之后重新完成。运行中不接受 reopen_reason。

recovery 是完整替换的简短接续信息，保留有效未决事项。任务版本冲突须重新读取状态；超时先查 `GET /preparation/receipts/{request_id}` 或用原键原输入重试，不能盲换请求键。历史回执不代替实时状态。

work_ready 表示所有分部任务已完成阅读处理；新增分部不会被当作已分析。任务完成不证明文学质量，服务不自动唤醒 AI。原统一 reference_query、搜索快照执行器和自动索引任务已移除，旧接口返回 404；既有原文、标注及任务保留；废弃向量与索引派生数据由 0017 迁移清理。

已按 [Spec 08](../specs/08-分析与创作Skill.md) 提供两份 Skill：

- [novel-analysis](../.agents/skills/novel-analysis/SKILL.md)：分析与标注标准、资产选择，以及 MCP/HTTP 保存和任务接续。依靠 LLM 自身分析能力，完整分析指南留作维护参考，不随包加载。

## 作品屏蔽与物理删除

数据库升级至 `0011` 后，可在 HTTP 接口文档 `/docs` 调用，或由 WebUI 接入。通用屏蔽和物理删除保留 HTTP 管理入口；默认 MCP 仅提供明确放弃准备时的 prepare_cleanup。作品及分部改名通过维护入口进行。

| 操作 | HTTP 请求 | 结果 |
| --- | --- | --- |
| 浏览可用作品 | `GET /works` | 默认只列 visible |
| 管理屏蔽作品 | `GET /works?visibility=hidden` | 分页列出 hidden；all 列出全部 |
| 屏蔽作品 | `PATCH /works/{work_id}/visibility`，JSON `{"visibility":"hidden"}` | 保留数据，返回作品元数据 |
| 恢复显示 | 同一路径，JSON `{"visibility":"visible"}` | 恢复默认列表和检索 |
| 物理删除 | `DELETE /works/{work_id}`，无请求体 | 204，无响应正文；重复删除仍为 204 |

屏蔽后，MCP 默认作品列表同样排除该作品；原文关键词与写法说明关键词检索返回 `409 WORK_HIDDEN`。直接按 ID 读取原文、下载和维护资产仍可用于复核，屏蔽不是权限控制。筛选条件不同的作品列表不能共用分页游标；升级前取得的作品列表游标需从首页重新获取。

物理删除清理作品、数据库中的上传文件、章节、段落、作品内分析资产及关联、任务进度、所有索引代、导入记录和作品相关写入回执，不设回收站。全库共享标签及其独立回执、本机文件与外部备份保留。索引构建期间返回 `409 WORK_BUSY`，稍后重试；其他失败整体回滚。响应丢失可重试同一 DELETE；不存在的合法 UUID 同样返回 204。

删除后旧坐标和导入请求结果失效，可用新 request_id 重新导入同名同文件，使用新返回的作品及段落 ID。WebUI 的删除按钮应明确说明上述永久删除范围并要求用户确认；“屏蔽”与“删除”使用独立操作。完整行为与验证见 [Spec 11](../specs/11-作品屏蔽与物理删除.md)。

## 导入与原文读取

同一主线故事归入一个 Work，先创建作品，再逐部导入。结构为 `Work → Part → Section → Paragraph`。Part 名称不要求编号，可以叫“火之晨曦”“悼亡者之瞳”；顺序按追加顺序保存。不分部的小说导入一部“正文”。不建模内部卷；AI 如需整理，另存派生 TXT，去掉卷分组标记，保留卷首序言、引文、正文及章节顺序，不覆盖原素材。

每次上传一份完整分部 Canonical TXT。UTF-8，可带 BOM；首个非空行为 `分部：名称`，章节使用 `标题：章节名`，每条正文非空物理行是一个已确认自然段。服务不修正文、不猜标题、不合并硬换行；按分部下载保留上传的全部字节。文件摘要在 Part.source_sha256；Work.source_sha256 是按部顺序计算的来源清单摘要。详见 [Spec 12](../specs/12-作品分部与追加导入.md)。

以下 Python 示例在已启动的服务上运行；保存创建键和导入键，超时重试沿用原键原输入：

```python
from uuid import uuid4
import httpx

data = "分部：正文\n标题：序章\n　　第一自然段。\n第二自然段。".encode("utf-8")
create_key, import_key = str(uuid4()), str(uuid4())
with httpx.Client(base_url="http://127.0.0.1:8000", timeout=120, trust_env=False) as client:
    created = client.post("/works", json={"request_id": create_key, "name": "接口演示作品"})
    created.raise_for_status()
    work_id = created.json()["result"]["id"]
    base = f"/works/{work_id}"
    check = client.post(base + "/part-imports/validate", files={"file": ("demo.txt", data)})
    check.raise_for_status()
    if check.json()["status"] != "valid":
        raise RuntimeError(check.json())
    response = client.post(
        base + "/part-imports",
        files={"file": ("demo.txt", data)},
        data={"request_id": import_key},
    )
    response.raise_for_status()
    part_id = response.json()["part"]["id"]
    directory = client.get(base + "/sections", params={"part_id": part_id}).json()
    section_id = directory["items"][0]["id"]
    paragraphs = client.get(base + f"/sections/{section_id}/paragraphs").json()
    assert client.get(base + f"/parts/{part_id}/file").content == data
```

`GET /works/{work_id}/parts` 分页列出分部；`GET /works/{work_id}/parts/{part_id}` 获取当前详情。作品或部改名分别使用 `PATCH /works/{work_id}` 和 `PATCH /works/{work_id}/parts/{part_id}`，请求体含 request_id、work_id、expected_version、name，后者另含 part_id。只改目录名称，不改原字节、顺序或证据 ID。

相同 request_id、work_id 和字节重试返回导入时快照；相同请求键换输入返回 REQUEST_CONFLICT，新键重复同作品部名返回 PART_NAME_CONFLICT。作品名全局唯一，分部名在作品内唯一。首次创建/导入 201、重放 200。导入结果丢失可查询 `GET /part-imports/{request_id}`；404 只表示当时尚无已提交结果。创建和改名响应丢失时原键原参数重试。旧 work_import 工具、旧 /work-imports 路由及作品单文件下载已移除。

目录和正文分页默认 100、最大 1000。范围读取与补读必须提供同作品、同 Section 的段落 ID；返回完整自然段和实际范围。未提供文学分析或“已分析”进度。

段落分页、范围读取和上下文补读默认 `format="compact"`；显式 `full` 返回完整结构与字节位置。compact 将 work_id、section_id 放在响应顶层，每段只返回 id、ordinal、text，保留完整正文、实际范围及续读信息。actual_range 和 requested_range 仅含两端段落 ID，需与顶层归属合并为完整 SourceRange；空章节段落页的 actual_range 为 null。HTTP 段落列表通过查询参数传 format，其余两项通过 JSON 请求体传入，MCP 三个工具均通过参数传入。

source_search、annotation_search、annotation_list、annotation_get 同样默认 compact，可显式 full。搜索候选与标注列表中的精简证据保留 section_id 与两端段落 ID，需补上同一响应顶层 work_id 才组成完整证据坐标；标注详情 references 已提供完整 read_target，可直接交给 source_read；原文关键词候选的 start_paragraph_id 即补读锚点。搜索摘录、截断提示、标注状态和版本保留；标注详情保留完整说明、所有证据与标签／实体 ID，省略时间字段。两种格式使用同一排序和游标，可跨格式续页。

以上字段清单描述维护接口；默认业务 library_browse、source_read 也接受 format，当前浏览契约见 Spec 17。标注详情保留全部证据和标签定义。依赖版本等完整字段的维护调用使用 full，写入和历史回执不精简。当前应用需 0017，已有库升级前须备份并验证恢复；0016 至 0017 只清理废弃检索派生数据，见 Spec 19。0011–0015 还会经过 Spec 18 的旧分析清理，不转换更早旧结构的数据。

AI 阅读优先选择 compact，需要核对文件字节位置时选择 full。两种格式的游标可在同一查询中互用。limit 仅控制页大小，不会扩大引用范围；补读的 before / after 是前后段落数，应根据实际内容判断是否足够，服务不自动识别完整场景。

## 本地 MCP 使用

准备一份结构已确认的 TXT，按上文配置数据库后启动应用即可，无需配置导入目录：

```powershell
uv run --locked python -m novel_lens
```

在支持 Streamable HTTP 的 AI 客户端中添加 MCP 服务，URL 填写 `http://127.0.0.1:8000/mcp`；更改应用端口时同步修改 URL。客户端无需数据库密码或 Python 子进程命令。不同客户端的配置字段由该客户端规定，本项目不自动修改客户端设置。

本节及后续 CRUD / 关键词检索表描述 maintenance 配置的维护能力（共 59 项，含准备入口），不属于默认 15 项业务工具。日常流程使用本文开头的业务表；维护配置中的十四个目录与原文工具如下，其余资产、进度和检索维护入口见后续章节：

| 用途 | 工具 |
| --- | --- |
| 文件预检、导入和结果恢复 | `part_import_validate`、`part_import`、`part_import_get` |
| 作品创建、改名、列表和元数据 | `work_create`、`work_update`、`work_list`、`work_get` |
| 分部列表、元数据和改名 | `part_list`、`part_get`、`part_update` |
| 目录、段落、范围和补读 | `source_sections`、`source_paragraphs`、`source_read`、`source_get_context` |

例如，文件位于 `D:/小说/样例.txt` 时，先用 `work_create({request_id, name})` 创建作品或用 work_list 选择已有作品；预检参数为 `{"work_id":"实际作品 UUID","file_path":"D:/小说/样例.txt"}`。正式导入使用同一路径并增加调用方生成的 UUID `request_id`。超时或丢失响应时先查询该键，再用原键和原文件重试。预检不锁定文件，导入时会重新读取和校验。

允许读取任意目录中的普通文件，使用服务进程现有的操作系统权限。推荐绝对路径；相对路径以服务进程工作目录为基准，支持 `..` 和指向其他目录的符号链接或目录联接。路径必须能被应用所在的操作系统识别。文件可读性、大小、读取期间变化和 TXT 格式仍会校验。入库后原文保存在 PostgreSQL，不再依赖本地路径。

每次工具结果的业务 JSON 上限为 1 MiB，另含同内容的兼容文本副本及协议开销。结果过大返回 `RESULT_TOO_LARGE`，可缩小分页或读取范围；单段仍超限时，本期 MCP 无法返回该完整段落。每部下载使用同服务的 REST 分部文件接口。完整参数、错误和取消恢复规则见 [Spec 03](../specs/03-本地MCP原文能力接入.md)。

协议使用官方 Python SDK 2.2.0，已通过官方客户端实测；实际 AI 客户端宿主尚未配置或联调。工具仅提供数据能力，不自动分析小说。

## 分析标注与标签

外部 AI 读取原文并判断值得保留的写法后，通过以下 MCP 工具保存分析成果。服务不生成文学判断，保存标注也不表示该段落或全书已分析完成。

| 用途 | 工具 |
| --- | --- |
| 查询标签名称、定义和别名 | `tag_search`、`tag_list`、`tag_get` |
| 创建和修改共享标签 | `tag_create`、`tag_update` |
| 保存和修订标注 | `annotation_create`、`annotation_update` |
| 撤回或恢复标注 | `annotation_set_status` |
| 查找摘要和读取完整标注 | `annotation_list`、`annotation_get` |
| 恢复某次已提交写入 | `asset_write_get` |

一条 Annotation 至少引用一个 SourceRange，可以引用同一作品的多个章节；单个范围不能跨 Section。tag_ids、entity_ids 可为空，实体必须属于该作品；note 可为 null，也可以是保留换行的多段写法说明。不同标注允许重叠。标签跨作品复用，创建前先搜索名称、定义与别名；本期搜索为字面子串匹配，不是语义检索。

`annotation_list` 必须指定作品，可组合原文范围相交、“同时具有全部指定标签”和“同时具有全部指定实体”过滤；默认只返回候选摘要，full 另含 entity_count 等元数据；note_preview 最多 200 个字符，并明确 note_truncated。选择后调用 `annotation_get` 获取完整说明、标签与实体 ID 和原文引用，再用 `source_read` 复读原文。

五个写工具都要求保存 request_id。修改内容或状态还需 expected_version。`annotation_update` 完整提交 kind、title、scope_note、note、references、tag_ids、entity_ids；清空标签或实体传 []，说明不可为空。`tag_update` 完整提交 name、description、aliases，不能更换 namespace；保持标签 ID 和既有引用，改动对所有引用作品生效。VERSION_CONFLICT 表示有其他修订已提交，需要先读取当前版本。超时或响应丢失后查询 `asset_write_get`，再使用原键和原输入重试；该工具返回当次提交的快照，不代表资产的最新版本。

`annotation_set_status` 接收 request_id、work_id、annotation_id、expected_version、status（active / withdrawn）。撤回保留原文、说明、引用和历史；普通内容修改不恢复撤回状态。`annotation_list` 和 `annotation_search` 默认 status=active，指定 withdrawn 查看已撤回项，null 查看全部；`annotation_get` 可读取任意状态。撤回和恢复立即影响默认标注查询；原文关键词检索仍可命中对应原文。历史回执只代表提交时快照，需调用当前详情接口判断现状。相关关系、作品认识及接续结论由 AI 复核并更新，服务不自动连带修改。

维护接口 annotation_update 必须显式完整提交 entity_ids，[] 清空；业务 prepare_batch 无实体编辑参数，修订时由服务保留该标注已有实体关联。响应中的 entity_ids 是当次读取或提交的关联，历史快照不代表当前关联。

单次完整写入结果上限为 1 MiB，提交前检查，超限回滚并返回 ASSET_TOO_LARGE；分页结果超限可缩小 limit。标注、关联和请求结果在一个事务中保存，失败不留下部分成果。本期资产入口仅为 MCP，已有 REST 原文接口继续可用。完整字段和错误规则见 [Spec 04](../specs/04-分析标注与标签管理.md)。

## 实体与跨章节关系

Entity 是作品内的身份入口，支持人物、地点、物品、组织、概念五类。名称和别名允许重复，以稳定 ID 区分；创建前先搜索并判断是否复用。修改实体名称不改变已有标注或关系的版本。

| 用途 | 工具 |
| --- | --- |
| 创建、修改、读取实体 | `entity_create`、`entity_update`、`entity_get` |
| 列出、搜索实体 | `entity_list`、`entity_search` |
| 创建和修改关系 | `relation_create`、`relation_update` |
| 查询说明和节点概览 | `relation_search`、`relation_get`、`relation_expand` |
| 撤回或恢复关系 | `relation_set_status` |

Relation 至少连接同作品的两个不同原文范围，可跨章节，允许直接引用尚未标注的原文。节点保留调用方给出的顺序及 role；title、relation_type 和关系 note 必填。类型和角色使用开放文本，文学依据由外部 AI 核验，服务不自动判断伏笔或完成分析。

典型读取流程：`entity_search` 找到对象 → `annotation_list` 或 `relation_search` 按 entity_ids 找到候选 → `relation_get` 读取完整说明和版本 → `relation_expand` 携带 expected_version 分页获取节点角色与范围 → `source_read` 读取选中的证据。关系详情不附带节点列表，节点概览不附带正文；翻页期间版本变化返回 VERSION_CONFLICT。

关系创建时 status=active。`relation_set_status` 要求 request_id、work_id、relation_id、expected_version、status；传 withdrawn 撤回，传 active 恢复，保留全部内容和引用。普通关系查询默认排除已撤回记录，显式 status=withdrawn 可查询撤回记录，status=null 查询全部；按 ID 获取或展开仍可查看已撤回关系。普通内容修改保留当前状态，不自动恢复。

五个实体和关系写工具共用 `asset_write_get`、请求键空间、版本检查和事务恢复。关系内容修改须完整提交标题、类型、说明、节点、标签和实体集合。状态与内容修改竞争同一版本；每个成功的新修改请求增加版本，同键重放保持原结果。写入快照包含全部节点，但不含正文；它仅代表当次提交，不代表当前关系仍有效。完整参数和验收条件见 Spec 05。

## 作品认识与连续阅读

作品认识与具体观察共用 Annotation：kind=comparison 表示有边界的跨片段认识，kind=observation 表示具体观察。title 命名关注问题，scope_note 限定已读范围与条件，note 解释实际内容和语言的联系。用途不代表质量评级，也不证明全书分析完成。

每处引用的 evidence_range 定位判断依据，reading_range 保存包含该依据的连续上下文，role_note 说明它是共同选择、对照还是条件依据等实际作用。不同章节分别引用，不拼成假连续原文。引用范围和事务校验见 [Spec 18](../specs/18-连续阅读与叙述选择.md)。

创作端先查作品认识或部章目录，沿详情 read_target 阅读连续原文，形成适用于新作的内容、人物相处与语言选择，再构思和写作。局部修订可直接通过标签或坐标入手；只读说明不算完成原文参考。文学效果由用户实际阅读判断。

## 原文与写法说明全文检索

REST 使用 `POST /source/search` 和 `POST /annotations/search`；MCP 对应 `source_search`、`annotation_search`，请求体相同：

```json
{"work_id": "<实际作品 UUID>", "terms": ["月光", "张三"], "match": "all", "limit": 20}
```

terms 为 1–8 个普通关键词，每词最多 128 字符；去除首尾空白、去重，拒绝空白词与 NUL，不解释查询表达式。all 要求同一自然段或同一条写法说明包含所有词，any 则任一词命中。中文支持单字与连续词；ASCII 按词且忽略大小写，兼容字符经归一化处理，因此 `ABC` 可命中 `ＡＢＣ`，`bc` 不命中 `abcd`。这不是同义词或语义搜索。

搜索分页默认 20、最大 100；原文按章节和段落顺序，标注按创建时间和 ID 排序。续页传 next_cursor，保持 work_id、terms、match 和入口；说明修订可能改变后续页命中集合。结果用 match_kind 区分原文与说明，excerpt 最多 200 个原始字符，含 character_start、前后截断标记及 match_located；无法定位关键词时返回段首摘要并标记 false。摘要位置仅用于摘录，不作为精确的分词高亮坐标。

原文候选返回真实单段 source_range、paragraph_id、section_id，可用 source_read 或 source_get_context 回读；标注候选返回 annotation_id、version、first_source_range 和 source_range_count，再用 annotation_get 读取完整说明及全部证据。无标注原文也可命中。两入口均只读，不推进分析进度。完整约束见 [Spec 09](../specs/09-原文与写法说明全文检索.md)。

## 分析进度与中断接续

每部作品可创建多个 AnalysisJob，target 选 `{kind:"whole_work"}`、`{kind:"part", part_id}` 或 `{kind:"ranges", source_ranges:[...]}`，创建后固定。whole_work 只包含创建时已有段落，追加新部不会扩展旧任务或改变完成记录。任务之间的 Coverage 和 recovery 独立，Annotation、Entity 和 Relation 仍为作品共享资产。新任务从 unprocessed 开始，不按现有标注数量推断进度。

| 用途 | 工具 |
| --- | --- |
| 创建、查找与读取任务 | `analysis_job_create`、`analysis_job_list`、`analysis_job_get` |
| 暂停、恢复、更新接续信息、重开 | `analysis_job_update` |
| 读取进度或显式标记已读、待回看 | `coverage_get`、`coverage_mark` |
| 原子保存本批成果、接续信息和 processed 进度 | `analysis_checkpoint` |
| 核验进度与导航版本后完成任务 | `analysis_job_complete` |

recovery 区分带原文证据的 facts、open_questions，以及必填 next_action 和可选 next_range；更新时整体替换。补读证据可在目标范围之外，但须属于同作品。读取原文没有进度副作用；read 不降级已处理状态，needs_revisit 须说明原因且不能包含未处理段落。

checkpoint 传 request_id、work_id、job_id、expected_version、一个目标内 source_range、writes 和完整 recovery。writes 的每项为 `{operation, input}`，支持现有十二个资产写操作（含 tag_update、annotation_set_status）并各自保留 request_id。各键互不重复，不提供批内临时 ID；需引用新标签或实体时先创建并取得稳定 ID。writes=[] 须提供 outcome_note，可以说明“核对后没有新增结论”。任何子写入、接续信息、进度或提交失败都会回滚本批新内容，已在此前提交的资产不受影响。

所有任务修改使用版本条件；暂停后不能推进。目标全部 processed，且已提交 calibration_note、limitations（可为 null）和最终 recovery 后才能完成；允许保留未决问题。completed 任务须以 running、reopen_reason 和完整 recovery 显式重开，保留进度并清除当前完成说明。

超时或更换会话后，先用 `asset_write_get` 查外层请求键，再读取当前任务、`coverage_get` 和 recovery，按需核验原文。历史回执不代替当前状态；未查到结果时以原键原输入重试。进度按相邻同状态、同原因合并并分页，任务版本变化后旧游标返回 VERSION_CONFLICT。完整参数、状态转换和错误见 [Spec 07](../specs/07-分析进度与中断接续.md)。


## 正式 WebUI 入口

构建后的前端通过 `GET /ui/` 提供，与 HTTP/MCP 服务同源。源码安装未生成前端时返回 503，并说明执行 `web/` 下的 `npm ci`、`npm run build` 后重启服务。静态页面不包含数据库连接串，也不经 8765 原型代理。

首期复用 `/library/browse`、`/source/read`、`GET /works/{work_id}`。新增 `GET /works/{work_id}/sections/{section_id}` 返回 `SectionOut`（包含实际分部名称与章节名），用于定位引用，避免为了一个章节遍历全书目录；章节必须属于路径中的作品，否则返回 404。该接口不改变原文或分析进度。


### WebUI 资产浏览

- `POST /assets/annotations/browse`：跨可见作品分页返回标注摘要及 `work_name`、首处引用的 `part_name` / `section_title`。输入 `work_id?`、`section_id?`、`work_ids?`、`part_id?`、`source_range?`、`tag_ids?`、`tag_match?`（默认 any 任一命中，all 全部同时匹配）、`query?`（说明文字的字面子串）、`status?`（默认 active，null 查全部）、`limit?`、`cursor?`。章节筛选必须指定作品，任一引用位于该章即可命中；不是只查首处引用。游标绑定全部筛选条件，筛选改变须从第一页开始。
- `POST /assets/annotations/coverage`：输入完整 `SourceRange`（`work_id`、`section_id`、`start_paragraph_id`、`end_paragraph_id`），范围限同一作品、同章最多 200 个连续段落。返回 `work_id`、`section_id` 与 `items[]` 中每段的 `paragraph_id`、`ordinal`、`annotation_count`，包含零计数。按有效标注 ID 去重，重叠引用只计一次，计数不受候选列表分页限制；超过范围返回 `RANGE_TOO_LARGE`，坐标归属错误返回 404。仅供阅读页边标记，不写分析进度；调用失败应提示重试，不能视为无标注。
- `POST /assets/annotations/detail`：输入 `work_id`、`annotation_id`，同一快照返回 `annotation`、完整 `tags`、有序 `locations`。每处位置包含稳定范围、分部/章节名和 `start_ordinal` / `end_ordinal`；不附带小说正文，原文仍由 `/source/read` 分页读取。
- 默认结果排除屏蔽作品；显式访问屏蔽作品返回 `WORK_HIDDEN`，章节/标注不属于指定作品返回 404，无匹配返回空页。默认 MCP 包含 tag_update，旧 reference_query 已移除。
- 标签库复用 `/library/browse(view="tags")`，查询名称、定义、别名及精确命名空间。分类、作品范围和匹配方式遵循本文开头的浏览契约；未使用标签只在全库词表中显示。
