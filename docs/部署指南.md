# 部署指南

本指南面向首次克隆 NovelLens 的使用者及协助部署的 AI。所有数据库和配置由使用者创建或提供，无需维护者的服务器、密码或镜像归档。当前部署包含 Python 应用与 PostgreSQL / PGroonga；embedding、硬件探测与自动调参尚未实现。

## 选择运行方式

默认方式：应用在本机 Python 3.12 环境运行，数据库由本机 Docker Compose 创建。HTTP / MCP 监听 `127.0.0.1:8000`，数据库发布 `127.0.0.1:15432`。Dockerfile 从公开 PostgreSQL 基础镜像构建 PGroonga 扩展，Compose 不引用某台电脑的本地镜像 ID。

如果已经有自己的 PostgreSQL 18 与 PGroonga 实例，使用下文“已有数据库”，跳过本机数据库初始化和 Compose。数据库可以共享，NovelLens HTTP / MCP 仍为本机服务。

准备 Git、Python 3.12 和 uv；默认方式另需 Docker 服务和 Compose，支持 Linux 容器。Linux 原生或 Windows WSL 可在同一环境执行命令；Windows 原生应用配合 Docker Desktop 也可按此路径配置。只有 WSL 内可用 Docker 时，优先整套命令在 WSL 执行，不假定 Windows 的 `docker` 命令存在。平台实测范围见文末。

## 首次安装

从项目根目录执行，命令失败时先处理错误，不继续执行后面的迁移和启动：

```text
uv sync --locked
uv run --locked python scripts/init_local.py
docker compose up -d --build --wait
uv run --locked alembic upgrade head
uv run --locked python -m novel_lens
```

Windows PowerShell 先执行 `$env:PYTHONUTF8 = '1'`。不要先复制 `.env.example` 再运行初始化脚本；脚本只接受 `.env` 和 `data/postgres/password` 都不存在的首次安装目录。它生成独立随机密码，写入这两个文件，不打印密码、不连接数据库、不改全局环境。配置已存在时应复用或人工检查，不删除现有配置来强行重跑。

`docker compose up` 创建空数据库，Alembic 建表并启用扩展。应用不自动迁移。当前迁移末端为 `0006`；新数据库需要安装 PGroonga 的文件以及创建扩展的权限。现有业务库升级前需先备份。

数据库镜像固定 PostgreSQL 18.6 的公开基础镜像摘要及 PGroonga 4.0.8 软件包版本；上游引导包有校验和校验，软件源变化可能导致构建失败，应核对错误而非关闭校验。传递依赖不保证永久不变。依赖来源：[PostgreSQL 官方镜像](https://hub.docker.com/_/postgres)、[PGroonga 安装文档](https://pgroonga.github.io/install/)。

如果 `15432` 被占用，在首次启动前同时调整 `compose.yaml` 的主机端口与 `.env` 中的数据库端口。应用端口可通过 `.env` 的 `NOVEL_LENS_PORT` 修改，MCP 客户端地址也要同步。不要终止不属于当前项目的服务来释放端口。

## 验证与首次导入

1. `docker compose ps` 应显示数据库 healthy。
2. `uv run --locked alembic current` 应显示 `0006 (head)`。
3. 启动应用后，在浏览器访问 `http://127.0.0.1:8000/health` 和 `http://127.0.0.1:8000/works`。前者只验证进程，后者验证数据库读取；新库作品列表为空。
4. 将下面内容保存为 UTF-8 TXT，在 `http://127.0.0.1:8000/docs` 使用 `POST /work-imports/validate` 上传预检，再使用 `POST /work-imports` 上传同一文件并填写一个新 UUID 作为 `request_id`。可通过 `uv run --locked python -c "import uuid; print(uuid.uuid4())"` 生成。记录请求键，超时重试使用原键与原文件。

```text
书名：部署验证样例
标题：第一章
月光照在窗沿，她听见门外的脚步声。
她放下杯子，没有立刻回答。
```

这个步骤会在用户数据库保存一部小样例；使用者可选择直接导入自己的已确认 TXT。导入后调用 `GET /works`，读取返回的作品 ID；用 `POST /source/search` 查询该作品中的“月光”，确认原文关键词检索可用。完整参数见接口文档与[接口说明](接口与使用.md)。

在支持 Streamable HTTP 的 AI 客户端中添加 MCP URL `http://127.0.0.1:8000/mcp`，不需要为每个工具分别设置地址。先枚举工具、调用 `work_list`，再按作品 ID 查询章节或原文。当前服务提供 42 个工具；客户端实际发现的 schema 为调用依据。MCP 成功连接不等于数据库与搜索已经就绪，仍需上述业务验证。

## 已有数据库

不运行 `init_local.py`，也不启动本仓库默认 Compose。将 `.env.example` 复制为项目根目录 `.env`，填入自己管理的数据库连接：

```text
NOVEL_LENS_DATABASE_URL=postgresql+psycopg://USER:URL_ENCODED_PASSWORD@HOST:PORT/DATABASE
```

密码中的保留字符须 URL 编码；TLS 参数按目标数据库实际配置追加，本机默认实例使用 `sslmode=disable`，不能据此要求其他用户关闭远程数据库的 TLS。实例需提供 PGroonga 扩展文件；普通 PostgreSQL 镜像不自动具备全文检索依赖。仅有连接地址而无访问凭据时，AI 不能自行推导密码。

运行 `uv sync --locked`，确认目标库和备份后执行 `uv run --locked alembic upgrade head`，再启动应用。若共用数据库，只需一个受控升级操作，不由每台电脑并发执行迁移。配置载入优先级为进程环境变量、当前目录 `.env`、默认值，未知 `.env` 字段会拒绝启动。

## 配置与数据位置

| 对象 | 默认位置或行为 |
| --- | --- |
| 应用配置 | 项目根目录 `.env`，UTF-8，Git 忽略 |
| 初始化密码 | `data/postgres/password`，Git 忽略；已有数据库密码不会随文件改变 |
| 数据库数据 | Docker 卷 `novel-lens-local_postgres-data`，挂载容器 `/var/lib/postgresql` |
| 小说原字节、段落、资产、进度 | 数据库中；原文件存于 `work_sources.content` |
| 尚未导入的文件、个人写作草稿 | 用户本机；Git 与数据库均不自动同步 |
| Python 环境 | 项目 `.venv`；换电脑重新安装，Windows / WSL 不共用 |

默认 Compose 项目名为 `novel-lens-local`。若用 `-p` 或 `COMPOSE_PROJECT_NAME` 自定义项目名，实际卷名也改变；后续命令须使用同一项目名。数据在 Docker daemon 所在机器，Docker Desktop / WSL 的卷不等同于 Windows 工作区下的普通文件夹。

应用配置键：`NOVEL_LENS_HOST`（回环地址）、`NOVEL_LENS_PORT`（默认 8000）、`NOVEL_LENS_LOG_LEVEL`（默认 INFO）、`NOVEL_LENS_DATABASE_URL`、`NOVEL_LENS_MAX_FILE_BYTES`（默认 64 MiB）、`NOVEL_LENS_MAX_REQUEST_BYTES`（默认 65 MiB）。具体默认值也见 `.env.example`。

## 停止、备份与升级

Ctrl+C 停止应用。数据库可执行 `docker compose stop`，随后 `docker compose start --wait`；`docker compose down` 保留卷。`docker compose down -v` 删除数据，不作为重启或升级步骤。

备份默认本机实例时，可先在容器中生成二进制归档再复制，避免跨平台 shell 重定向破坏归档。以下命令适用于默认账号和库名，备份目标文件名每次应不同：

```text
docker compose exec -T postgres pg_dump -U novel_lens -d novel_lens -Fc -f /tmp/novel-lens.dump
docker compose cp postgres:/tmp/novel-lens.dump ./data/postgres/novel-lens-backup.dump
docker compose exec -T postgres rm /tmp/novel-lens.dump
```

备份包含原文及分析资产，应保存到受控位置，不提交 Git。恢复前使用相容的 PostgreSQL / PGroonga 环境，先检查归档并在独立空库演练；原库覆盖范围须明确。凭据与未导入本机文件另行保存。

已有部署升级时，先核对版本和目标库并备份，再更新代码、安装锁定依赖、核对镜像变化、执行迁移并复验读取与检索。不要通过删除卷解决升级问题，也不要在未验证时降低数据库版本。

旧版仓库默认 Compose 曾绑定维护者本地镜像 ID、固定容器名和 `novel-lens-postgres-data` 卷。本版改为新实例部署模板，使用不同项目名与默认卷，不会自动接续旧卷。旧部署继续使用原部署目录中已验证的配置；不要直接覆盖后运行新 Compose 并把新空库误认为原数据丢失。迁移旧部署需显式核对原卷、备份与目标配置，不属于新用户首次安装步骤。

## AI 协助部署

可以让 AI：“阅读 README 与部署指南，检查当前环境，部署一个新的本机 NovelLens 实例；已有配置时先核实并复用。”AI 应使用本仓库的同一流程，报告命令失败和未验证事项，无需读取历史会话或维护者的本地环境说明。

需要让后续会话了解本机环境时，可按[本地环境模板](本地环境.example.md)将已核实的工具入口、部署方式、数据位置与验证结果记录到 `docs/本地环境.local.md`；已有记录先核实后更新。此文件不提交 Git，不包含密码，也不参与程序配置加载。普通部署不要求先填写所有字段或运行完整开发测试。

当前初始化脚本只生成数据库密码和应用配置，不检测 CPU / GPU 或选择 embedding 参数。未来自动探测、试运行与配置复用的要求见 [Spec 10](../specs/10-原文语义检索与Embedding部署.md)，不能把该草案当成当前可执行工具。

## 验证范围

2026-09-21，在不含原有 `.env`、虚拟环境或业务数据的隔离源码副本中验证：WSL Ubuntu 24.04、Python 3.12.3、uv 0.11.28、Docker 29.7.2、Compose 5.5.0。按锁文件重新安装依赖，从公开基础镜像构建 PostgreSQL 18.6 / PGroonga 4.0.8，生成新配置并迁移空库至 0006。构建使用了本机已缓存的公开 PostgreSQL 基础镜像，扩展软件包联网下载；没有使用维护者服务器镜像归档。

实际验证通过：错误密码被拒绝、HTTP 存活与空作品列表、TXT 预检和导入、原字节下载一致、关键词搜索、官方 MCP 客户端枚举 42 个工具、作品列表及原文回读。应用正常停止，数据库 stop / start 后同一作品与检索仍可用；pg_dump 导出、归档复制和 pg_restore 目录读取通过，本次未执行备份恢复演练。

初始化的 4 项自动化测试覆盖首次生成、重复执行保留配置、已有部分配置拒绝覆盖及失败清理；Windows Python 3.12.13 上通过，静态与类型检查通过。业务实现未改变，未重跑全部业务测试。Windows 原生应用配合 Docker Desktop、macOS、ARM 平台和真实 AI 宿主界面尚未按本版完整步骤实测；不能由 WSL 结果推定通过。
