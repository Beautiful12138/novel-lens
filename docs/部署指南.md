# 部署指南

本指南面向首次克隆 NovelLens 的使用者及协助部署的 AI。运行组成是 Python 应用与 PostgreSQL / PGroonga；WebUI 构建后由同一应用提供。服务不运行 embedding 或其他模型，不需要 GPU、模型下载、模型运行器或 pgvector。外部 AI 客户端自行连接所用模型。

当前数据库版本为 `0017`。新空库直接建立当前结构；已有数据库通过显式迁移升级。默认 MCP 提供 15 项业务工具；维护进程可设置 `NOVEL_LENS_MCP_PROFILE=maintenance` 使用资产管理、关键词检索等接口，不包含语义接口。两个配置共用业务规则，不是权限隔离。

## 选择运行方式

- **新建本机实例：** 应用运行在 Python 3.12 环境，数据库由 Docker Compose 创建。HTTP / MCP 默认监听 `127.0.0.1:8000`，数据库发布 `127.0.0.1:15432`。Dockerfile 从公开 PostgreSQL 基础镜像安装 PGroonga。
- **连接已有实例：** 使用自己管理的 PostgreSQL / PGroonga 和连接配置；跳过本机密码生成及 Compose，不覆盖服务器已有容器、卷或凭据。数据库可共享，NovelLens 仍仅监听本机回环地址。

准备 Git、Python 3.12、uv、Node.js 22.12+；新建本机数据库还需支持 Linux 容器的 Docker 和 Compose。Windows 可使用 Docker Desktop，或在 WSL 内执行整套流程。不要混用 Windows / WSL 虚拟环境；只有 WSL 提供 Docker 时，不假定 Windows 的 docker 命令可用。

## 服务器部署与单密钥鉴权

服务器端复用现有 PostgreSQL / PGroonga，不运行新库初始化。应用通过独立 Python 3.12 虚拟环境运行；源码版本、锁定依赖和前端构建须来自同一提交。可以在构建机执行前端构建与 uv build --wheel，将包含 WebUI 的 wheel 和由 uv export --locked --no-dev --no-emit-project 导出的带哈希依赖清单交付服务器；服务器在专属虚拟环境内安装依赖和 wheel，无需全局安装 Node.js 或项目依赖。

应用仍监听 127.0.0.1，示例内部端口为 18000。由 Nginx 在 10003 提供 HTTPS，并反向代理网页、HTTP 和 MCP。公开 origin 和私有密钥由部署配置提供：

```text
NOVEL_LENS_HOST=127.0.0.1
NOVEL_LENS_PORT=18000
NOVEL_LENS_PUBLIC_ORIGIN=https://YOUR_HOST:10003
NOVEL_LENS_ACCESS_KEY=REPLACE_WITH_PRIVATE_ACCESS_KEY
```

密钥没有写死的默认值，应放于 Git 外的受限配置或服务环境。公开 origin 必须为不含路径、查询或用户信息的 HTTPS 地址，同时必须配置密钥，否则拒绝启动。保留本机匿名模式时两项都省略；显式空密钥不会关闭认证。HTTP/MCP 客户端使用 Authorization: Bearer，网页在 /ui/ 输入密钥；不是 OAuth 自动授权流程。

反向代理应复用有效证书及续期后的 Nginx reload，保留公开 Host 和 Origin；X-Forwarded-For 设为直接连接的 remote_addr，不转发客户端伪造的同名头。应用只信任本机代理。示例 location：

```nginx
location / {
    proxy_pass http://127.0.0.1:18000;
    proxy_http_version 1.1;
    proxy_set_header Host $http_host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_set_header Connection "";
    proxy_buffering off;
    proxy_read_timeout 300s;
    client_max_body_size 65m;
}
```

应用运行账号只读取部署代码和指定导入目录，凭据配置不对其他本机用户开放。不将应用作为 root 运行，也不与 SSH 管理入口共用执行权限。导入文件须先由获授权的操作放到服务器可读目录；本机 D: 路径不会自动上传。网页 API 返回数据禁止缓存；代理不记录包含原文、密钥或请求参数的访问日志。

公开入口仅放行选定应用端口；数据库继续按既有约定维护。部署前核对安全组、端口、证书、数据库版本、备份和现有应用；不覆盖其他站点或更改共享数据库参数。首次部署的回滚是停用新增应用服务及其代理入口；升级保留旧发布目录、虚拟环境和配置备份，切回旧版本后验证。

验收须从客户端访问真实 HTTPS 入口，验证证书和端口可达、匿名业务请求被拒绝、正确密钥可读取目录与原文、MCP 工具调用正常、网页登录及退出有效。重启应用再检查，核对部署前后业务数据摘要。health 只证明进程存活。

## 首次安装

以下命令从项目根目录执行，任一步失败都应先处理错误。Windows PowerShell 先设置 `$env:PYTHONUTF8 = '1'`。

```text
uv sync --locked
uv run --locked python scripts/init_local.py
docker compose up -d --build --wait
uv run --locked python scripts/init_database.py
npm --prefix web ci
npm --prefix web run build
uv run --locked python -m novel_lens
```

`init_local.py` 只生成随机数据库密码和 `.env`，已有任一文件时拒绝覆盖；不要先复制 `.env.example` 再运行它。`init_database.py` 只接受没有用户表、视图、序列或 Alembic 版本记录的新空库，在一个事务内创建 PGroonga、当前结构和迁移版本；失败整体回滚。非空库不会被清空或直接标记为最新。

新库不执行已退役的 0007–0016 历史向量迁移，因此无需安装 vector 扩展。已有库不能用初始化命令代替升级。首次构建需要联网下载依赖，Compose 不依赖维护者的镜像归档或本地镜像 ID。

## 验证与首次导入

1. `docker compose ps` 应显示数据库 healthy；连接远程实例时按其运行方式检查。
2. `uv run --locked alembic current` 应显示 `0017 (head)`，`uv run --locked alembic check` 应无结构差异。
3. 打开 `http://127.0.0.1:8000/health`、`http://127.0.0.1:8000/works` 和 `http://127.0.0.1:8000/ui/`。health 只证明进程响应，作品列表才核验数据库读取；新库列表为空。
4. 在 AI 客户端配置 MCP 地址 `http://127.0.0.1:8000/mcp`，应发现 15 项业务工具。调用 `library_browse({"view":"works"})`，随后通过已安装的分析 Skill 导入和阅读。

可将下面小样例保存为 UTF-8 TXT，在 HTTP 文档 `http://127.0.0.1:8000/docs` 调用 `POST /preparation/import`，提供新 UUID `request_id`、作品 `name` 和 TXT 的绝对 `file_path`。该步骤会在目标库创建样例，使用者也可直接导入自己的已确认 TXT。

```text
分部：正文
标题：第一章
月光照在窗沿，她听见门外的脚步声。
她放下杯子，没有立刻回答。
```

原文与分析任务原子保存；导入成功不等于 AI 已读完。用 `library_browse` 找章节、`source_read` 回读原文；维护接口 `POST /source/search` 可用“月光”验证关键词检索。请求超时先查询回执，重试使用原请求键与原输入，详见[接口与使用](接口与使用.md)。

## 已有数据库

先核实版本、目标、备份和数据保留范围。不要对已有部署运行 `init_local.py`，也不要直接套用本仓库 Compose。已有 `.env` 复用；没有配置时复制 `.env.example` 并填写自己的连接：

```text
NOVEL_LENS_DATABASE_URL=postgresql+psycopg://USER:URL_ENCODED_PASSWORD@HOST:PORT/DATABASE
```

密码保留字符须 URL 编码，TLS 参数遵循实际数据库配置。本机示例的 `sslmode=disable` 不适用于所有远程数据库。只有连接地址而无凭据时，AI 不能自行推导密码。

不同起点的行为：

| 当前版本 | 升级范围 |
| --- | --- |
| 全新空库 | 使用 `init_database.py`，只要求 PGroonga |
| 0016 | 0017 删除旧向量、语义索引及构建回执、统一召回的旧表/触发器/函数和搜索世代字段；保留原文、当前标注、标签、实体关系、任务目标与进度 |
| 0011–0015 | 还会经过 0016：先清理旧标注、旧导航及相关回执、重置旧分析进度；须另行明确接受该范围，原文和普通共享标签保留 |
| 0010 及之前的带数据实例 | 不转换旧结构，应另建空库、重新导入；升级失败不是清空授权 |

执行步骤：

1. 停止所有连接该库的 NovelLens 写入进程，完整备份并在独立库验证恢复。
2. 安装当前锁定依赖，从 `.env` 和服务环境变量中移除 `NOVEL_LENS_EMBEDDING_CONFIG`。旧字段不再接受，配置校验不会静默忽略它。
3. **保留旧数据库镜像及扩展文件，先执行 `uv run --locked alembic upgrade head`。** 历史迁移和旧备份恢复仍可能需要 pgvector；不能在升级前先换成无向量扩展的镜像。
4. 0017 以非 CASCADE 方式删除 vector 扩展。如果同库有项目外的向量对象，迁移会失败并完整回滚；检查依赖后单独安排，不扩大删除范围。
5. 核对业务内容与迁移版本，运行 `alembic check`。之后才可按原部署方式更新数据库镜像；重新构建 WebUI、启动服务并核验目录、原文、标注、任务及 MCP。

0016 和 0017 的清理不可由 downgrade 恢复，需要升级前备份及配套旧代码/数据库环境。数据库共享时只由一个受控操作执行升级。代码更新不自动升级或清理数据库。

## 配置与数据位置

| 对象 | 默认位置或行为 |
| --- | --- |
| 应用配置 | 项目根目录 `.env`，UTF-8，Git 忽略；进程变量优先 |
| 首次生成的数据库密码 | `data/postgres/password`；修改文件不等于修改已有库的密码 |
| 数据库数据 | Docker 卷 `novel-lens-local_postgres-data`，挂载 `/var/lib/postgresql` |
| 原文、目录、分析资产、进度 | 数据库中，原始字节保存在 `part_sources.content` |
| 未导入素材、个人草稿 | 使用者本机，不由 Git 或数据库自动同步 |
| Python 环境 | 项目 `.venv`，换电脑重新安装 |
| 旧模型文件与旧配置 | 服务不再读取；清理磁盘前核对准确目录和是否用于其他任务，不随升级自动删除 |

自定义 Compose 项目名会改变卷名，后续命令使用同一项目名。数据位于 Docker daemon 所在机器，WSL / Docker Desktop 卷不是 Windows 工作区中的普通目录。换电脑须连接原库或迁移备份，克隆仓库不复制作品库。

有效配置键见 `.env.example`：`NOVEL_LENS_HOST`、`NOVEL_LENS_PORT`、`NOVEL_LENS_LOG_LEVEL`、`NOVEL_LENS_DATABASE_URL`、`NOVEL_LENS_ACCESS_KEY`、`NOVEL_LENS_PUBLIC_ORIGIN`、`NOVEL_LENS_MCP_PROFILE`、`NOVEL_LENS_MAX_FILE_BYTES`、`NOVEL_LENS_MAX_REQUEST_BYTES`。未知 `.env` 字段拒绝启动。

## 停止、备份与升级

Ctrl+C 停止前台应用。数据库执行 `docker compose stop`，再次使用执行 `docker compose start --wait`；无需重复初始化。`docker compose down -v` 会删除数据，不是重启或升级步骤。

默认本机实例可先在容器生成归档再复制，避免 shell 二进制重定向问题。每次使用独立备份文件名，以下账号、库名和容器路径仅适用于默认实例：

```text
docker compose exec -T postgres pg_dump -U novel_lens -d novel_lens -Fc -f /tmp/novel-lens.dump
docker compose cp postgres:/tmp/novel-lens.dump ./data/postgres/novel-lens-backup.dump
docker compose exec -T postgres rm /tmp/novel-lens.dump
```

备份包含小说和分析资产，不提交 Git。先检查归档，再在独立空库完整恢复并核对内容；归档存在或能列目录不等于恢复成功。0017 备份使用 PostgreSQL / PGroonga 环境；含旧向量的历史备份还需对应 pgvector。保留旧镜像和版本信息以支持回滚，凭据与未导入文件另行保存。

## AI 协助部署

AI 先阅读本指南及可选的 `docs/本地环境.local.md`，核实执行位置、现有配置、Python/Node/Docker 入口和数据库归属。复用有效配置；只在首次安装生成新密码，不覆盖现有 `.env`、容器或卷，不为本项目检测 GPU、下载模型或启动旧 embedding 服务。

确认空库还是已有库后，按相应路径执行初始化或升级。完成后告知服务地址、数据库版本、实际验证结果和未完成项；需要记录时使用[环境模板](本地环境.example.md)，不填写凭据。迁移、重启、删除数据及对外操作遵循当前授权。

## 正式 WebUI 构建与访问

在项目根目录执行 `npm --prefix web ci` 和 `npm --prefix web run build`，产物进入 Python 包的静态目录；启动后访问 `http://127.0.0.1:8000/ui/`。日常不需要单独运行 Vite，发布 wheel 前也须完成构建。

前端开发可在 `web/` 执行 `npm run dev`。界面当前以阅读浏览为主；真实写入验证使用隔离作品库，不在共享作品上造数。
